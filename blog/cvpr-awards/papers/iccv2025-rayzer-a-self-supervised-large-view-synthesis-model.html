RayZer: A Self-supervised Large View Synthesis Model

Hanwen Jiang · Hao Tan · Peng Wang · Haian Jin · Yue Zhao · Sai Bi · Kai Zhang · Fujun Luan · Kalyan Sunkavalli · Qixing Huang · Georgios Pavlakos
CVF 官方 PDF ⬇Scholar

摘要 Abstract

见上方 arXiv / CVF 链接。

📝 精读笔记

灵魂一句
第一个零 3D 监督（无相机位姿、无几何）的大规模多视图 view synthesis 模型：吃无位姿无标定的多视图图，先估相机、再重建 latent 场景、最后渲染新视图；训练时用自己预测的位姿去渲染目标视图、只靠 2D 光度损失监督。纯 transformer，唯一 3D 先验是 Plücker ray 结构（连接相机-像素-场景）。结果不仅追平、还反超了训练+推理都吃位姿标注的 "oracle"（LVSM/GS-LRM）——因为它们被 COLMAP 的噪声位姿拖了后腿。
问题 & 动机
自监督 + scaling law 撑起了 LLM/VLM/视觉生成的 foundation model，但 3D Vision 仍重度依赖 GT 几何 + 相机位姿标注（通常来自 COLMAP 这类慢且不完美的优化）→限制了可扩展性与上限。本文直接问："how far can we push a 3D Vision model without any 3D supervision?"（不用任何 3D 监督能走多远）。痛点具体化：① COLMAP 位姿有噪声且耗时；② 现有 LRM/LVSM/GS-LRM 训练要 GT 位姿、推理还要准位姿；③ 已有自监督多视图工作（如 RUST）用 latent pose、disentangle 难、不显式 3D-aware。
核心方法（关键公式 + 设计）
把任务看成 3D-aware 图像自编码：disentangle 图像→相机+场景（重建），再 re-entangle→图像（渲染）。控信息流防作弊：图分两组 IA/IB（不重叠），IA 预测场景、IB 提供光度自监督（用 IB 的预测位姿去渲 IA 的场景）。式1 L=(1/KB)Σ_{î∈îB}(MSE(I,î)+λ·Percep(I,î))，λ=0.2。模型纯 transformer、pose-first 级联（"even noisy cameras can be a strong condition for better scene reconstruction"）：① Camera Estimator 估 SE(3) 相对位姿（6D 旋转表示，式6）+ 单焦距内参（式7）；② 位姿→pixel-aligned Plücker ray maps R∈R^{K×H×W×6} 作条件；③ Scene Reconstructor 融合 fA+rA（式8 用原始图 token f 而非 pose-transformer 输出 f*，防 IB 信息泄漏）→ latent 场景 z*（式9）；④ Rendering Decoder（仿 LVSM）按目标 Plücker ray 渲染（式10-11）。
关键结果
DL3DV：RayZer 24.36 PSNR > LVSM 23.69 > GS-LRM 23.49；RealEstate：RayZer 27.48 > LVSM 27.00 > GS-LRM 24.25（都反超 oracle）。Objaverse（Blender 完美位姿）：LVSM 32.34 > RayZer 31.52 > PF-LRM 25.48（此时真 oracle 略胜，但差距小）。位姿 3D-aware 验证（Tab.5 插值渲染）：RayZer 27.01 vs PF-LRM 20.63 vs copy 19.56。Probing（Tab.6）：自监督学到的位姿特征比监督 baseline 更准（RealEstate R@10° 99.6 vs 87.0）。
亮点
① 打破"3D 必须监督"信条——self-predicted pose 渲染做自监督，0 标注；② 反超 oracle 的解释很硬：COLMAP 噪声位姿给监督方设了上限，自监督反而学到"最利于重建的位姿空间"；③ pose-first 是关键：消融里 scene-first 直接崩到 13.31（vs 24.36）；④ Plücker ray 作唯一 3D 先验优雅解了 structure-motion 的鸡生蛋问题，相机与场景互相正则；⑤ 视频连续帧 > 乱序图集（image index p.e. 带来局部位姿平滑），暗示用海量视频 scale 更香。
疑问 / 待查
① 评测用预测位姿而非 GT 位姿渲染（follow RUST），与 oracle 口径不同——PSNR 直接可比性需谨慎，论文已说明"learned poses exist in a different space"；② 3D-awareness 插值时插值系数仍来自 GT 位姿（Tab.5），即"位姿空间几何性"的验证借用了 GT，并非全自给；③ 只做静态场景，动态/大基线泛化原文未涉（原文未写）；④ 训练 50k iter / batch 256，但单卡/总算力与训练时长正文未给（需查附录）。

📖 逐段精读 · 笔记

从 Abstract 起逐段精读（批量精读初稿，供后续 review/深化）。基于 CVF 官方 PDF 全文。最后更新 2026-06-21。
① Abstract（摘要）— 逐句精读
原文逐句引用 + 中文指路：
1) "We present RayZer, a self-supervised multi-view 3D Vision model trained without any 3D supervision, i.e., camera poses and scene geometry, while exhibiting emerging 3D awareness." → 一句话定位：零 3D 监督（既不喂相机位姿、也不喂场景几何）训练，却"涌现"出 3D 感知。emerging（涌现）是关键词——3D 感知不是被显式监督出来的，而是从 2D 自监督任务里自然长出来的。
2) "RayZer takes unposed and uncalibrated images as input, recovers camera parameters, reconstructs a scene representation, and synthesizes novel views." → 四步 pipeline：输入无位姿(unposed)无标定(uncalibrated)多视图 → 估相机参数 → 重建场景表示 → 渲染新视图。
3) "During training, RayZer relies solely on its self-predicted camera poses to render target views, eliminating the need for any ground-truth camera annotations and allowing RayZer to be trained with 2D image supervision." → 自监督的核心戏法：用自己预测的位姿去渲染目标视图，从而只需 2D 图像监督、彻底甩掉 GT 相机标注。
4) 涌现 3D 感知归因于两点："First, we design a self-supervised framework, which achieves 3D-aware auto-encoding of input images by disentangling camera and scene representations."（自监督框架 = 3D-aware 自编码：把图像 disentangle 成相机 + 场景）+ "Second, we design a transformer-based model in which the only 3D prior is the ray structure, connecting camera, pixel, and scene simultaneously."（纯 transformer，唯一 3D 先验是 ray structure，同时连接相机/像素/场景）。
5) 结论："RayZer demonstrates comparable or even superior novel view synthesis performance than 'oracle' methods that rely on pose annotations in both training and testing." → 追平甚至反超那些训练+测试都吃位姿标注的 "oracle"。
一句话抓 Abstract：零 3D 监督的 view synthesis 大模型——靠"自预测位姿渲染目标视图"做 2D 光度自监督，纯 transformer + Plücker ray 作唯一先验，反超被 COLMAP 噪声位姿拖累的监督式 oracle。项目页 hwjiang1510.github.io/RayZer/。
📚 背景知识 A — Latent set 场景表示 & 学习式渲染（§3 Preliminaries 原文）
latent set 表示是什么：原文 "Compressing data into tokens in latent space is a common practice in text, image, video, etc. Recently, this representation has also been extended to 3D research."。区别于经典的显式（mesh/点云）、隐式（NeRF/SDF）、混合（triplane/3DGS）这些本身就 3D-aware 的表示，latent set 是 "not explicitly 3D-aware. It serves as a compression of scene information, where the 3D-awareness properties are fully learned."——3D 性质全靠学。记作 \( z \in \mathbb{R}^{n\times d} \)：n 个 token、d 维特征。
怎么渲染 latent set：需要一个网络 \( R_\theta \)（源自 SRT[57]/LVSM[30]），公式 \( v = R_\theta(z, r) \)，其中 r 是一条射线、v 是该像素被渲染的属性（如 RGB）。对比传统图形学渲染 \( v = R(\text{SCENE}, \text{RAY}) \)（R 是手工预定义的渲染方程，如 NeRF 的 alpha-blending ray marching）——RayZer 的 "'rendering equation' is a learned model parameterized with weights θ"，渲染方程本身是学出来的，而非手工写死。这是"几何免"（geometry-free）路线的根。
📚 背景知识 B — LRM / LVSM / GS-LRM & Plücker ray（外部）
大模型重建/视图合成谱系：LRM=Large Reconstruction Model，用大 transformer 把 2D 多视图前馈映成 3D 表示再渲新视图（免 per-scene 优化）。GS-LRM[86] 输出 3D Gaussian。LVSM[30] 最激进——"replace 3D representations and physical rendering equations with latent representations and learned rendering functions"，丢掉显式 3D 表示与物理渲染方程，用 latent token 集 + 学习渲染函数。它们的硬伤：原文 "they still require ground-truth camera poses for supervised training and/or accurate camera annotations during inference"。RayZer 继承 LVSM 的 latent-set + 学习渲染，但额外学会自己估位姿、训练不要任何位姿标注。
Plücker ray 坐标：每个像素对应一条 3D 射线，用 6 维 Plücker 坐标（方向 d + moment m=o×d）表示，与像素逐一对齐（pixel-aligned）。RayZer 把估出的 SE(3) 位姿 + 内参转成稠密 ray maps \( R \in \mathbb{R}^{K\times H\times W\times 6} \) 喂给场景重建。原文价值："This ray-based representation captures both the 2D ray-pixel alignment and the 3D ray geometry, providing fine-grained, ray-level details that encapsulate the physical properties of the camera model."——既含 2D ray-pixel 对齐、又含 3D ray 几何，比塞一个位姿矩阵更细粒度。
📚 背景知识 C — COLMAP/SfM 鸡生蛋 & RUST 对比 & 6D 旋转（外部）
SfM / COLMAP 与"鸡生蛋"：Structure-from-Motion（COLMAP[60]）从多图联合解"相机运动(motion) + 场景结构(structure)"——但二者互相依赖（要重建得先知相机，要定相机又得有结构对应）=chicken-and-egg problem of structure and motion。COLMAP 靠特征匹配 + BA 迭代优化，原文批它 "requirements of dense-view inputs, slow speed, and sensitivity to hyper-parameters"，在玻璃/白墙等弱纹理处常失败 → 产出噪声位姿。RayZer 用 Plücker ray 让相机与场景 "regularize each other during training" 来缓解。
RUST[58]（最相关自监督前作）对比：RUST 从无位姿图学 latent 场景表示。原文列出 RayZer 三点不同：(1) 顺序相反——"RayZer initially estimates camera poses and uses poses to condition the following latent reconstruction. In contrast, RUST ... first reconstructs the scene and then estimates the camera poses"（RayZer pose-first，RUST reconstruction-first）；(2) 位姿表示——RayZer 用显式 SE(3)（可几何插值、disentangle 好），RUST 用 latent pose（"makes scene-pose disentanglement challenging and they are not explicitly 3D-aware"）；(3) RayZer 估所有视图位姿，RUST 只估 target 视图。消融 Tab.7 的 (3)+(4) 合起来 ≈ RUST。
6D 旋转表示[92]：把 SO(3) 旋转参数化成连续 6D 向量（而非 3×3 矩阵或四元数），保证神经网络回归时的连续性，避免欧拉角/四元数的不连续奇点。
② §1 Introduction — problem（被监督卡住的 3D Vision）
problem：原文 "Self-supervised learning has driven the rise of foundation models ... This paradigm has proven highly effective for LLMs, VLMs, and visual generation. In contrast, 3D Vision models still rely heavily on ground-truth 3D geometry and camera pose labels, which are usually estimated from time-consuming optimization methods, e.g., COLMAP, and are not always perfect. This reliance limits both learning scalability and effectiveness."——别的模态都靠自监督 + scaling law 起飞了，唯独 3D Vision 还死抱 GT 几何/位姿标注（COLMAP，慢且不完美），规模与上限双双受限。
核心提问：原文 "To break free from this constraint, we move beyond the supervised paradigm and ask: how far can we push a 3D Vision model without any 3D supervision?"——不用任何 3D 监督，一个 3D Vision 模型能走多远？这是全文的 driving question。
② §1 Introduction — solution（自预测位姿渲染 = 3D-aware 自编码）
solution 核心：原文 "The key insight of our self-supervised training is to use the camera poses predicted by RayZer itself to render views that provide photometric supervision, rather than following the standard protocol of using ground truth poses for rendering. Thus, RayZer can be trained with zero 3D supervision."——用自己估的位姿渲染、拿 2D 光度损失当监督，于是零 3D 监督可训。
解释为自编码：原文 "this self-supervised task can be interpreted as 3D-aware image auto-encoding. Initially, RayZer disentangles input images into camera parameters and scene representations (reconstruction). It then re-entangles these predicted representations back into images (rendering)."——先 disentangle 成相机 + 场景（编码/重建），再 re-entangle 回图（解码/渲染）。防作弊靠信息流分组：原文 "we divide all images into two parts: one set predicts the scene representation (input views), while the other offers photometric self-supervision (target views) ... thereby preventing trivial solutions that are not 3D-aware."——用第二组(IB)的位姿去渲第一组(IA)的场景，防止学到"非 3D-aware 的平凡解"。
② §1 Introduction — why（为何纯 transformer + 为何 Plücker ray）
why 纯 transformer：原文 "RayZer is built only with transformers – no 3D representation, hand-crafted rendering equation, or 3D-informed architectures. This design is motivated by self-supervised large models in other modalities, enabling RayZer to flexibly and effectively learn domain-specific knowledge."——不塞任何 3D 归纳偏置，对标其它模态的自监督大模型，换取灵活性与可扩展性。
why Plücker ray 作唯一先验：原文 "The only 3D prior incorporated in RayZer is the ray structure ... RayZer first predicts camera poses, which are then converted into pixel-aligned Plücker ray maps to guide the scene reconstruction that follows. This ray-based representation serves as a strong prior for addressing the chicken-and-egg problem of structure and motion, effectively allowing the camera and scene representations to regularize each other during training."——ray structure 把相机/像素/场景绑在一起，把"鸡生蛋"问题转成相机与场景互相正则的可训练问题。这就是 Intro 已经闭环的 problem→solution→why。
③ §2 Related Work — 三大流派定位
(1) 大规模 3D 模型两条路：一条注入 3D 归纳偏置（multi-view stereo / epipolar geometry）；另一条纯 transformer 故意不要 3D 偏置（LRM、LEAP、DUSt3R、SRT、LVSM）。后者中 LVSM/SRT 进一步用 latent 表示 + 学习渲染。但原文点破共性短板："they still require ground-truth camera poses for supervised training and/or accurate camera annotations during inference"。MegaSynth/Stereo4D 走"合成/立体视频扩数据"路线，但 "curating data for different tasks can be laborious"。
(2) 自监督 3D 表示学习：单视图法只能特定类别或部分观测；半监督法仍靠全监督初始化权重。最相关是多视图自监督（Zhou et al./Lai et al. 用相机运动作 2D/3D warping 正则，但 "this strong inductive bias limits the learning effectiveness"），以及 RUST（见背景 C）。
(3) 优化式 unsupervised SfM/SLAM/NVS：per-scene 优化（COLMAP、NoPe-NeRF、BARF、CF-3DGS），与 RayZer "feed-forward parametrized model, learning priors by training on large data" 形成对照——它们 "do not have learnable model parameters to encode priors"，常需现成 3D 监督模型做正则/初始化。
④ §4.1 自监督学习框架 — IA/IB 信息流 + 式1 损失
输入输出：聚焦静态场景。输入一组无位姿无标定多视图 \( I = \{I_i \in \mathbb{R}^{H\times W\times 3}\,|\,i=1,...,K\} \)（来自无标签视频帧或图集）；输出 = 输入的参数化（相机内参、逐视图位姿、场景表示），支持新视图合成。
信息流控制：把 \( I \) 切成不重叠两子集 \( I_A, I_B \)（\( I_A \cup I_B = I \), \( I_A \cap I_B = \varnothing \)）。IA 预测场景表示，IB 提供监督：RayZer 渲染对应 IB 的图像 \( \hat{I}_B \)，施加光度损失（式1）：\[ \mathcal{L} = \frac{1}{K_B}\sum_{\hat{I}\in \hat{I}_B}\big(\mathrm{MSE}(I,\hat{I}) + \lambda\cdot \mathrm{Percep}(I,\hat{I})\big) \] 其中 \( K_B=|I_B| \)，λ 是感知损失[32,42]权重（实现取 λ=0.2）。原文 "The two sets are randomly sampled during training."——两组训练时随机采。
④ §4.2 模型总览 — 为何 pose-first 级联
级联预测（cascaded prediction of camera and scene）是命门设计：原文 "This is motivated by the fact that even noisy cameras can be a strong condition for better scene reconstruction, which is analogous to traditional structure-from-motion methods and is in contrast with recent reconstruction-first methods."——即使带噪的相机也是后续场景重建的强条件，类比传统 SfM、对立于"先重建后估位姿"的 reconstruction-first 路线。原文 "This design can provide mutual regularization of predicting pose and scene during training"——pose 与 scene 训练时互相正则。
整体流：先 tokenize 图像 → camera estimator 估所有视图的内参 + SE(3) 位姿 → 转 Plücker ray maps → scene reconstructor 从 IA + 其 ray maps 出 latent 场景 → rendering decoder 用 IB 的预测相机渲 \( \hat{I}_B \) 算式1。
④ Image Tokenization（patch + 双重位置编码）
仿 ViT 把每张图切成不重叠 patch（patch size s），每个 patch \( \in \mathbb{R}^{s\times s\times 3} \) 经线性层编码成 token \( \in \mathbb{R}^{d} \)，得 patch 对齐 token 图 \( f_i \in \mathbb{R}^{h\times w\times d} \)（\( h=H/s, w=W/s \)）。加两种位置编码：sinusoidal 空间 p.e. + sinusoidal 图像 index p.e.（同一图所有 token 共享 index p.e.）。原文关键观察："When training on continuous video frames, these image index embeddings also encode sequential priors, which benefits pose estimation."——连续视频帧时 index p.e. 编码时序先验、利于位姿估计。最后 reshape 成集合 \( f \in \mathbb{R}^{Khw\times d} \)（transformer 对 token 排列不变）。
④ Camera Estimator \( E_{cam} \)（式2-7：位姿 + 内参）
相机 token 初始化：一个可学相机 token \( \in \mathbb{R}^{1\times d} \) 重复 K 次 + 加 index p.e. → \( p \in \mathbb{R}^{K\times d} \)。full self-attention：式2 \( \{f^*, p^*\} = E_{cam}(\{f, p\}) \)（式3-5 展开为 \( y_0=\{f,p\} \), \( y_l=\text{TransformerLayer}_l(y_{l-1}) \), \( \{f^*,p^*\}=\text{split}(y_{l_T}) \)）。注意：原文 "f* is not used for the following computation – it is only used as context to update p"，f* 仅作上下文。
位姿（式6）：选一视图为 canonical（identity 旋转、零平移），其余预测相对位姿；SO(3) 用连续 6D 表示，\( p_i = \mathrm{MLP}_{pose}([p^*_i, p^*_c]) \in \mathbb{R}^9 \) → 转成 SE(3) 位姿 \( P_i \)。内参（式7）：单焦距假设（fx=fy、各视图共享、principal point 在中心），\( \mathrm{focal} = \mathrm{MLP}_{focal}(p^*_c) \) → 内参矩阵 \( K \in \mathbb{R}^{3\times 3} \)。
④ Scene Reconstructor \( E_{scene} \)（式8-9：关键防泄漏设计）
把 IA 的相机参数 \( P_A \) 转 pixel-aligned Plücker rays \( R \in \mathbb{R}^{K\times H\times W\times 6} \) → tokenize 成 \( r \in \mathbb{R}^{Khw\times d} \)。取 IA 对应的 \( f_A, r_A \)（各 \( \in \mathbb{R}^{K_A hw\times d} \)）沿特征维融合 式8：\( x_A = \mathrm{MLP}_{fuse}([f_A, r_A]) \in \mathbb{R}^{K_A hw\times d} \)。
★ 防泄漏的关键设计（全文最易忽略却最重要的一处）：原文 "Importantly, we use the raw image tokens f rather than the pose transformer output f* for this fusion. This design choice prevents leakage of information from the image set IB, since the camera estimator transformer producing f* has access to a global context that includes tokens from IB."——融合用原始 token f 而非 pose transformer 的输出 f*，因为 f* 经过 full self-attn 见过全局（含 IB）会泄漏 IB 信息、让自监督"作弊"。再 式9 \( \{z^*, x^*_A\} = E_{scene}(\{z, x_A\}) \)，\( z \in \mathbb{R}^{L\times d} \) 为可学场景 token、L 为 token 数，\( z^* \) 为最终场景表示、\( x^*_A \) 丢弃。
④ Rendering Decoder \( D_{render} \)（式10-11，仿 LVSM）
目标图 → pixel-aligned Plücker rays → tokenize 成目标 token \( r \in \mathbb{R}^{hw\times d} \)；full self-attention 解码 式10 \( \{r^*, z'\} = D_{render}(\{r, z^*\}) \)（z′ 丢弃）；patch 级解码 RGB 式11 \( \hat{I} = \mathrm{MLP}_{rgb}(r^*) \in \mathbb{R}^{hw\times(3s^2)} \)，reshape 回 \( \mathbb{R}^{H\times W\times 3} \)。训练时用 IB 的预测 Plücker ray maps \( R_B \) 渲 \( \hat{I}_B \) 算式1。整个 pipeline 端到端、纯 transformer、无任何手工渲染方程。
⑤ §5 实验设置（数据集 / 评测协议 / baseline / 实现）
实现：RayZer 共 24 transformer 层（camera estimator / scene encoder / rendering decoder 各 8 层）；lr=\(4\times 10^{-4}\) cosine 调度、50,000 iterations、batch size 256、λ=0.2、分辨率 256、patch size 16。数据集：场景级 DL3DV[45]、RealEstate[91]，物体级 Objaverse[15]（渲成视频），各自独立训练测试。输入/目标视图数（\( |I_A| / |I_B| \)）：DL3DV 16/8、RealEstate 5/5、Objaverse 12/8；采样 index 范围分别 64-96、128-192、50-65（按数据难度/相机基线选）。
评测协议（与 oracle 不同口径，必读）：原文 "the evaluation protocol of RayZer is different from the 'oracle' and supervised methods, which use ground-truth poses to render images. Instead, we use predicted poses to render novel views ... Since the model is trained without explicit pose annotations, the learned poses exist in a different space ... This evaluation protocol follows RUST."——RayZer 用预测位姿渲染（不是 GT 位姿），因为学到的位姿活在不同空间。"target views are used only for pose estimation and not for scene representation prediction, ensuring that no information leakage occurs."
baseline：① "oracle"（GS-LRM、LVSM encoder-decoder 版，训练+推理都用 GT 位姿，LVSM 也用 latent set 故为主对比）；② 监督式 PF-LRM（学位姿+重建，推理 pose-free）。公平起见 GS-LRM/LVSM 用 16 层（参数量同 RayZer，除 RayZer 多一个 camera estimator），PF-LRM 用 24 层。RUST 无公开实现，故在 Tab.7 消融其关键设计差异。

⑤ §5.4 消融实验 Tab.7（DL3DV 连续，逐项拆设计）
四组消融（PSNR even/rand，对照 (0) RayZer 24.36/23.72）：
(1) latent set → 3DGS+光栅化：训练 failed 不收敛。原文 "verifies the optimization difficulty of explicit 3D representation and demonstrates the flexibility of the latent representation with its learned rendering decoder."
(2) 去 Plücker ray、改塞 SE(3) pose token：降到 22.73/0.687/0.249（21.88 rand），证明 Plücker 对 structure-and-motion 的正则有效。
(3) 去显式位姿、直接用 latent camera token \( p^* \)：23.13/0.700/0.251（22.36 rand），略好于(2)但仍逊于(0)；原文 "the camera tokens \( p^* \) can leak target image information, while SE(3) poses ... serve as an information bottleneck"，且 SE(3) 几何良定可插值。
(4) scene-first 而非 pose-first：崩到 13.31/0.338/0.732（13.12 rand），铁证 pose-first 是命门。原文 "championing traditional pose-first methods in the context of self-supervised learning"。注：(3)+(4) 合起来概念上 ≈ RUST。
📌 全文一页总结（problem → method → experiment → takeaway）
problem：3D Vision 被 GT 相机位姿/几何标注（COLMAP，慢且噪）卡住可扩展性与上限——"how far can we push a 3D Vision model without any 3D supervision?"
method：把 view synthesis 看成 3D-aware 图像自编码，用自预测位姿渲染目标视图做 2D 光度自监督（式1，λ=0.2）；纯 transformer（24 层，3 模块各 8 层）、pose-first 级联——估 SE(3) 位姿(6D 旋转)/单焦距(式6-7) → 转 Plücker ray maps \( R\in\mathbb{R}^{K\times H\times W\times 6} \) 作唯一 3D 先验 → latent 场景重建(式8-9，用原始 token f 防泄漏) → 学习式渲染解码(式10-11)；靠 IA/IB 信息流分组逼出 disentanglement。
experiment：DL3DV 24.36 / RealEstate 27.48 PSNR 反超吃 COLMAP 位姿的 oracle（LVSM/GS-LRM）；Objaverse 完美位姿下真 oracle LVSM 略胜（32.34 vs 31.52）但 gap 小；预测位姿可插值且 3D-aware（27.01 vs PF-LRM 20.63）；probing 优于监督 baseline（RealEstate R@10° 99.6 vs 87.0）。
takeaway：① 3D 监督并非必需——自监督能学出"最利于重建的位姿空间"，甚至超过被噪声 GT 拖累的监督方；② pose-first + Plücker ray 是把"鸡生蛋"转成可互相正则的关键（scene-first 崩到 13.31、去 Plücker 降到 22.73、3DGS 直接不收敛）；③ 视频连续帧（带时序 index p.e.）显著优于乱序图集（24.36 vs 20.56），暗示用海量在线视频 scale 的潜力。
🧐 疑问 / 局限（含 [推测]）
① 评测用预测位姿而非 GT 位姿渲染（follow RUST），与 oracle 口径不同——PSNR 直接可比性需谨慎，原文已诚实说明 "learned poses exist in a different space"；② 3D-awareness 插值实验（Tab.5）的插值系数仍来自 GT 位姿，即"位姿空间几何性"的验证借用了 GT，并非全自给（原文明示）；③ 仅做静态场景（"We focus on the standard setting of modeling static scenes"），动态/大基线泛化原文未涉及；④ [推测] 单卡/总算力与训练时长正文未给（只给 50k iter / batch 256），需查 Appendix；⑤ [推测] latent set token 数 L、patch token 维度 d 的具体取值正文未列，亦在 Appendix；⑥ [推测] 每数据集独立训练，未验证跨数据集/跨域单模型泛化，可能限制"foundation model"叙事的当下落地。
