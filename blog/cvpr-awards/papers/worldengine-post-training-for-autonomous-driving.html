World Engine: Towards the Era of Post-Training for Autonomous Driving

摘要 Abstract（原文）

Autonomous vehicles must operate safely in the real world, where errors can have severe consequences. Although modern end-to-end driving policies excel in routine scenarios, their reliability is limited by the scarcity of safety-critical "long-tail" events in real driving datasets. These rare interactions define the practical safety boundary of the learned policy, yet they are difficult to collect at scale in the real world. Here we show that this fundamental limitation can be addressed by post-training pre-trained driving models on synthesized high-stakes interactions. We introduce World Engine, a generative framework that reconstructs high-fidelity interactive environments from real-world logs and systematically extrapolates them into realistic safety-critical variations. This paradigm enables reinforcement-based post-training to align policies with safety constraints, circumventing the physical risks inherent in real-world exploration. On a public benchmark built on nuPlan, World Engine substantially reduces failures in rare safety-critical scenarios and yields significantly larger gains than scaling pre-training data alone. Furthermore, when deployed on a production-scale autonomous driving system, the resulting policy reduces simulated collisions and demonstrates measurable improvements in on-road testing, showing that post-training on synthesized, safety-critical interactions offers a scalable and effective pathway to safer autonomous driving. The full codebase suite, including training, is released to the public.

📝 精读笔记（要点）

灵魂一句
自动驾驶的安全边界由"长尾"罕见事件决定，而这些事件最危险也最采不到 →「最安全攸关的行为必须从最稀缺的数据中学习」的结构性悖论。World Engine 用生成式世界模型从真实日志重建并外推出这些危险场景，把强化学习后训练搬进可控的合成环境，规避真实探索的物理风险。
问题 & 动机
现代端到端驾驶在常规场景已接近人类水平，但"平均表现"掩盖了关键脆弱性：行人突然横穿、激进加塞、复杂对抗交互等会导致事故的场景在真实数据里统计稀疏；且出于伦理/法律/社会约束，社会无法大规模采集安全攸关数据 → 最有价值的学习信号系统性缺失。单纯扩大数据采集收益递减。
核心方法
World Engine = 生成式框架：① 从真实路采日志重建高保真交互环境；② 系统性外推成逼真的安全攸关变体；③ 在其中做基于强化学习的后训练，让预训练驾驶策略对齐安全约束。本质是把 LLM 的 pre-train→post-train 范式迁移到自动驾驶。
关键结果
在基于 nuPlan 的公开基准上大幅降低罕见安全攸关场景的失败，收益显著大于单纯扩大预训练数据；部署到量产规模自动驾驶系统后，降低仿真碰撞，并在路测中展现可量化改进。完整代码（含训练）开源。

② §1 Introduction · 故事与逻辑链
立靶（P1–P4）：AI 从数字认知走向物理 AI，自动驾驶的核心挑战不再是"会不会开"，而是"安全攸关条件下的可靠性"。可靠性的边界由罕见长尾事件（行人横穿/激进加塞/对抗交互）决定，而它们在真实数据里统计稀疏；更要命的是受伦理/法律/社会约束不敢也不能大规模采集 → 结构性悖论：最安全攸关的行为必须从最稀缺的数据中学习。单纯堆数据收益递减。
借 LLM（P5）：LLM 的应对是从被动预训练转向后训练——用合成推理链 + 强化学习把"稀疏高价值区加密变稠"（DeepSeek-R1 / AlphaProof）。同理：自然驾驶数据覆盖不到的罕见安全场景，必须靠合成主动引导学习。
提出 WE（P6–P8）：从真实日志发现失败场景 → 重建成高保真交互世界 → RL 后训练对齐安全，全程不让真实世界冒险。双线验证：nuPlan 学术基准 + 8 万小时量产系统 / 200km 路测。
③ §2 Overview · 四阶段闭环流水线
1 预训练+长尾发现：模仿学习训基座，用它当"诊断探针"——把日志喂进去做非反应式 rollout，撞了/冲出道路的场景就是长尾（用模型自己的失败精准定位，后训练收益最大）。
2 仿真引擎：3DGS 把场景重建成可交互数字孪生。
3 行为世界模型：DiT 给周围车造多样/对抗轨迹变体（一个场景膨胀成上百个）。
4 RL 后训练：在闭环 rollout 上用强化学习精修策略。

Q1 · 这篇论文要解决的主要问题是什么？
核心：自动驾驶里"最安全攸关的行为，偏偏只能从最稀缺的数据中学习"这个结构性悖论（原文 line 64–65）——即如何让策略在罕见长尾安全场景下可靠。
① 安全边界由长尾决定不由常见场景决定（端到端日常已接近人类，但行人横穿/激进加塞/对抗交互才定边界）；② 这些数据采不到、且受伦理/法律/社会约束不敢采，最有价值的学习信号系统性缺失；③ 单纯堆数据收益递减，模型被迫在训练分布外外推→脆弱失败。
破题方向：借 LLM 的"预训练→后训练"，用 World Engine 从真实日志重建+外推合成长尾危险场景，再用强化学习后训练对齐安全，把稀疏高价值区"加密变稠"，且不让真实世界冒险。
Q2 · 怎么实现，为什么能解决？
怎么实现（§2 四阶段闭环）：
① 预训练+长尾发现：模仿学习训基座，用它当"诊断探针"——把日志喂进去做非反应式 rollout，撞了/冲出道路的场景标为长尾（用模型自己的失败定位，后训练收益最大）。
② 仿真引擎：3DGS 把事故场景重建成照片级可交互数字孪生（场景图分静/动，可自由视角实时渲染）。
③ 行为世界模型：DiT 给周围车造多样/对抗轨迹变体，一个场景膨胀成上百个。
④ RL 后训练：在闭环 rollout 上用行为正则化 RL 精修策略。
为什么能解决长尾悖论：① 把"采数据"换成"造数据"——从已有安全日志重建+外推，危险只发生在仿真里，正面绕开"不敢/不能大规模采集"的死结；② 真实接地——每个场景源自真实 log，物理可信，不学仿真幻觉；③ 闭环 + 海量变体——agent 学的是"自己动作的后果"（误差累积、他车反应），这是静态数据教不了的；④ KL + 真实数据混合——补短板不砸长处。比堆预训练数据强，因为它用模型自己的失败精准定位长尾、定向合成，算力花在刀刃上（外推≈加 ~10× 预训练数据）。
Q3 · ②仿真引擎用什么模型？③会跟②交互吗、只出轨迹还是图片？④RL 是不是只是轨迹级 loss？
②用什么模型：纯重建模型——3DGS（3D Gaussian Splatting）+ 场景图，不是生成图像的模型。输入图像+LiDAR+3D 框，拟合一堆 3D 高斯，光栅化 alpha 合成出图（含深度/法向/NCC/flatten 等正则）。
③会跟②交互吗、只出轨迹还是图片：③行为世界模型只产出轨迹/向量（DiT 在 token 层生成所有车的未来轨迹），不产图片；图片由②渲染。二者经仿真平台耦合：③给出 agent 轨迹（位置/朝向）→ 重定位②里的动态高斯 → ②渲出新图像 → 自车 planner 读图像（观测 o 就是图像）。所以"③定轨迹、②渲成图"，自车与环境交互在图像层。
④RL 是不是只是轨迹级 loss（诚实回应）：对一大半——动作是轨迹候选上的 categorical，优化"回报加权的 push/pull + KL anchor"，且全文没给具体 RL 算法（无 PPO/critic/advantage）。但有三点不止于此：(a) 没有 GT 可 pull，信号是闭环 rollout 的后果；(b) 闭环多步信用分配 + 乘性安全门（撞了把整条 rollout 奖励压没），非单步 loss；(c) KL+真实混合是正则。结论：价值不在 RL 本身，而在"造出采不到的闭环反事实经验"+"可验证、乘性门控的 reward 设计"，RL 是故意做薄的。
Q4 · 3DGS 从零：原理 / 为什么 per-scene 过拟合(跟 NeRF 一样吗) / 三种输入怎么用 / 动静分离 / 刚体搬运 / 伪代码
原理：用一堆带颜色的半透明 3D 高斯椭球表示场景，渲染叫 splatting——把每个椭球投到像面、按深度 alpha 合成，整个过程可微，于是能"渲染→和真照片比→反传调每个椭球"。
每个 3D 高斯 i: μ中心 / q朝向(四元数) / s三轴尺度 / α不透明度 / SH颜色 形状: Σ_i = R(q_i)·diag(s_i)^2·R(q_i)^T 渲染(相机E,K): ①投影 μ'=K·E·μ ②按深度排序 ③alpha合成: color(p) = Σ_i c_i·α_i·Π_{j
per-scene 过拟合，跟 NeRF 一样吗：是的，两者都是"对单场景过拟合"。但选 3DGS 不选 NeRF 因为：① NeRF 隐式 MLP+光线步进慢，3DGS 显式椭球+光栅化实时（RL 要上千 rollout）；② 3DGS 显式→能单独搬一个物体，NeRF 隐式难编辑。而"过拟合单场景"正是数字孪生的目的（不要泛化）。想"不过拟合"得换前馈式（pixelSplat 等），代价是画质降。
三种输入怎么用（不是都当 GT）：3DGS 没有 encoder，是直接拟合椭球参数。图像=主要当光度 GT（L1+SSIM）；LiDAR=初始化高斯位置 + 深度 GT + 曝光对齐；3D 框=结构脚手架（分静/动、定物体坐标系与每帧位姿，不进 loss）。
动静分离 + 刚体搬运：场景图把高斯分成静态节点(背景，固定)和每个动态物体一组(存物体坐标系)。搬运 = 对该物体每个高斯做刚体变换：
μ_world = R_t·μ_obj + T_t # 位置: 旋转+平移 q_world = R_t ⊗ q_obj # 朝向: 旋转叠加 s, α, SH 不变 # 整组刚性移动
伪代码（重建训练 + rollout 渲染）：
# 重建训练(离线, per-scene) static = init_gauss(LiDAR背景点); dyn[o]=init_gauss(框内点→物体系) for it in iters: t,cam = sample() G = static + [rigid_T(dyn[o], Box[o,t]) for o in objs if valid] I_hat = rasterize(G, E[cam,t], K[cam]) L = L1+SSIM + 逆深度(LiDAR) + NCC + 法向 + flatten + oob ; update # rollout 渲染(在线, ③/编辑驱动) def render(ego_pose, agent_poses): G = static + [rigid_T(dyn[o], pose) for o,pose in agent_poses] return rasterize(G, ego_pose∘extr[cam], K[cam]) # 策略看到的图
Q5 · 3DGS 追问：不过拟合方案 / 要离线重建每个动态物体吗 / LiDAR 怎么 init(聚类?)3D 框怎么用 / "搬过去"是什么、归属怎么定、光照遮挡能改吗
不过拟合方案：前馈/可泛化重建（pixelSplat、MVSplat、GS-LRM 等）——训一个网络在很多场景上学，推理一次前向预测高斯，泛化但画质通常较低；这篇要高保真数字孪生且离线重建可接受，故选 per-scene 优化。
要离线重建每个动态物体吗：要。用每帧 3D 框抠出该物体的点、用框位姿统一到"物体标准系"（物体在动反而多角度→更完整），拟合一组高斯。搬运=刚体变换这组高斯。也可换成塞预制 CG 资产（这篇没用）。
LiDAR 怎么 init、聚类吗、3D 框怎么用：不是聚类，是"点→高斯种子"（每个 LiDAR 点初始化一个高斯，颜色从投影取像素），再 densify(克隆/分裂)+prune(删低透明度)。3D 框做分割器：给点打"静态/属某物体"标签 + 提供每帧位姿把动态点搬回物体系。开放场景最终高斯数通常百万~千万级（"十几万"约为单帧雷达点/早期种子量级）。
"搬过去"是什么、归属怎么定、光照遮挡能改吗：搬过去=对该物体那组高斯整体刚体变换(见 Q4 公式)。归属在重建时用 3D 框一次性打标签并存下（场景图）。遮挡✅能正确处理（每帧按深度排序 alpha 合成，挪到前面自动挡住后面）；光照/阴影❌改不了（颜色 SH 在原位置原光照下烤死，挪进树荫照样亮、影子留在背景）——这是重建式仿真的硬伤，故通常挑光照变化不剧烈的片段或加重打光模块。
Q6 · LQR / bicycle 模型 / IDM 怎么实现，行为世界模型跟本车是同一个模型吗
bicycle（纠正：是运动学差分模型，轨迹↔控制）：把四轮车近似成自行车（前轮转向+后轮驱动），编码"车不能横着走"。关键用法是轨迹→控制：对轨迹求导反解出控制量。
模型: ẋ=v·cosθ, ẏ=v·sinθ, θ̇=(v/L)·tanδ, v̇=a 轨迹→控制(差分): v=√(ẋ²+ẏ²); θ=atan2(ẏ,ẋ); a=v̇ 曲率κ=(ẋÿ−ẏẍ)/(ẋ²+ẏ²)^1.5; δ=atan(L·κ) (并给可行性约束|δ|≤δmax)
IDM（智能驾驶员模型）：一维纵向跟车规则，只对前车反应、贴车道中心、确定性。
a = a_max·[ 1 − (v/v0)^δ − (s*/s)² ] s* = s0 + max(0, v·T + v·Δv/(2√(a_max·b))) (v0期望速度, s前车间距, Δv速度差, T车头时距)
行为世界模型 ≠ 本车模型（两个完全不同的模型）：本车策略 π_φ 输入图像→BEV、输出一条自车轨迹、是被 RL 训练的"选手"；行为世界模型输入矢量化场景(agent+地图 token)、输出所有他车轨迹、是 DiT、当"环境(陪练)" T_θ、不被 RL 训练。POMDP 里显式分开：π_φ 是策略，T_θ 是环境转移。
Q7 · 他车怎么处理 / 并行 rollout 是什么
他车三模式（可混用）：① log replay（重放原轨迹，非反应式，可能"鬼畜碰撞"）；② IDM（规则反应式）；③ 行为世界模型 DiT（学习式、多样+反应+可控）。决定轨迹后→LQR 修可行→把该车 3DGS 高斯刚体搬到该位姿→渲染。Table 1 证明带行为模型的反应式闭环最好。
并行 rollout：一次 rollout = 闭环跑批(策略看图→选轨迹→LQR执行→他车反应→渲下一帧→…记 obs/action/reward)。并行 rollout = 同时跑成百上千个实例（多 Sim worker × 多场景 × 行为模型随机变体）。前提是 3DGS 实时渲染 → 高吞吐造经验喂 RL（这也是不用 NeRF 的原因）。
Q8 · LQR 从零：线性系统 / 二次代价 / u=−Kx 与 Riccati 分别怎么解释、怎么用
大白话：你偏离规划线 0.5 米、车头歪 5°，方向盘该打多少才能"快回线又不甩人"——LQR 就是算这个"刚刚好"的控制器。
① 线性系统 x_{t+1}=A·x_t+B·u_t："下一刻偏差 = 偏差自己怎么变(A) + 我的操作扳多少(B)"。x=偏差状态(横向偏/航向偏/速度偏)，u=控制(方向盘/油门)，A=偏差自然演变、B=动作影响，二者由 bicycle 在参考轨迹附近线性化得到。
② 二次代价 J=Σ(xᵀQx+uᵀRu)：给"纠偏好不好"打分(越低越好)。单变量时 xᵀQx=q·e²(偏差平方×权重)、uᵀRu=r·δ²(控制平方×权重)。调 Q/R 这两个旋钮：Q 大 R 小=激进贴线，Q 小 R 大=温柔平顺。
③ u=−K·x、K 由 Riccati 给出：最优动作就是"偏多少、反方向按比例纠多少"。K=把"偏差"换算成"动作"的增益，由 (A,B,Q,R) 经 Riccati 自动算出(库函数，不用手算)。
准备(一次): 线性化得A,B → 设Q,R → 解Riccati → K 开车(每步): 量偏差x → u=−K·x → 执行 → 再量 (反馈循环) 总控制 = 前馈(bicycle差分出的名义δ,a) + 反馈(−K·误差)
Q9 · diffusion 从零（通用，图像生成起源）+ DiT 在 train/infer 怎么跑 + 15 连问
起源：DDPM(2020) 本是生成图像——真图反复加噪变雪花，训网络(当时 U-Net)学去噪；生成时从纯噪声反复去噪"显影"出新图。后来：Latent Diffusion(隐空间扩散=Stable Diffusion)、DiT(去噪器换成 Transformer)。三件套不变：①加噪规则 ②预测噪声的网络 ③从噪声迭代去噪采样。
为什么"凭空造"+怎么加 condition：生成起点是纯随机噪声(无信息)，去噪成样本=无中生有。加条件=让去噪网络也吃条件 c：f(x_t,t,c)，方式有"直接喂 c / classifier guidance / classifier-free guidance"。本文 c=地图+历史/目标(用保持那些 token 干净来当条件)。
怎么加噪声/加在哪/怎么算纯噪声/噪声等级：
x_t = α_t·x_0 + σ_t·ε (ε~高斯; α随t 1→0 信号变少, σ随t 0→1 噪声变多) "噪声等级"=t(或加了多少噪声); t=0干净, t=T纯噪声; 必须告诉网络t "纯噪声"由调度保证: 到T时α≈0,σ≈1 → x_T≈标准高斯(不是去判断) 加在哪: 数据空间(原始轨迹) 或 隐空间(VAE latent,如SD); 本文加在归一化后的轨迹token
预测噪声 vs 预测原图、为什么只预测噪声：两者数学等价(知 ε 可反解 x_0=(x_t−σ_t ε)/α_t)。选预测 ε 是因为 ε 目标尺度恒定(~单位方差)、跨 t 好优化；预测 x_0(加重建 loss)也行但高噪声时难、易模糊。本质上预测 ε 就是一种重建监督，只差线性变换。
infer 怎么用、X_t 怎么来：训练时 X_t=真 X_0 人为加噪(知道 ε 当监督)；推理时 X_t 来自反向链——X_T 采纯噪声，for t=T..1 用网络预测噪声→去掉一点→X_{t-1}，最终 X_0 才是可用轨迹(中间 X_t 是去噪到一半的噪轨迹)。
逐 token 还是 SA 联合 / 怎么联合生成 / 有无 teacher forcing / 像不像 MAE：非自回归——每个扩散步内一次 self-attention 联合处理全部 N×T 个 token(+地图)，"步"是去噪迭代(几十~上千)，不是逐 token 生成。训练用随机的每-token 噪声等级掩码(含"历史低噪声/未来高噪声"模式)，是 masked 训练、不是 AR teacher forcing。条件生成确实类 MAE(可见 token 推被遮 token)，差别是扩散迭代+随机+软掩码(噪声等级而非有/无)。
guidance 怎么作用：去噪每步后对 token 做 push/pull 修正——碰撞沿中心连线推开、二阶差分平滑加速度、偏离超阈值拉回最近车道中心线(附录公式12–14)，把硬物理约束注入生成，无需重训(只在采样时作用)。
goal point 怎么 encode：目标点就是 agent token 的属性(位置)；条件生成时把"目标 token"设低噪声(当已知固定)，DiT 去噪其余 token 时就会朝该目标自洽地生成；Intent Attack 即把邻车目标 token 强设到 ego 目标附近。
push-pull 是 loss 吗、token 怎么 decode 成轨迹、decoder 怎么训：push/pull 是采样时(inference)对 token 的修正项，不是训练 loss(训练 loss 是去噪 MSE)。token 本身就是轨迹属性向量(x,y,朝向,速度,尺寸)，去噪完直接读出即轨迹——不需要单独的 decoder(向量化表示自带语义，归一化的逆变换即还原)。
怎么评价"自洽"：① 物理可行性(LQR 修轨 + 碰撞/可行驶检查，通过才入库)；② 与历史/地图一致(条件生成保证)；③ guidance 强制不穿模/不压线。论文用这些硬检查筛掉不合理生成。
Q10 · 整个 diffusion 实现总览（它原来做图片生成）
训练: 真数据 x_0 →随机 t 加噪得 x_t →网络 ε_θ(x_t,t,c) 预测噪声 →MSE(预测,真实) 反传。采样: x_T 采高斯 →循环去噪 →x_0。图像用 U-Net/Latent；本文把"数据"换成多车轨迹 token、去噪器换成 DiT、并用解耦噪声做条件 + guidance 注入物理。
Q11 · 现在还有什么 SOTA 生成方法？flow matching 怎么做？diffusion vs flow matching 是不是像 NeRF vs 3DGS？
谱系：GAN / VAE / 自回归 / normalizing flow / diffusion / flow matching(rectified flow) / consistency models。图像视频现以 diffusion 和 flow matching 为主(SD3、Flux 用 flow matching)，语言仍自回归。
flow matching：学一个速度场 v(x,t)，从噪声沿(尽量直的)路径连续搬运到数据；采样=对速度场解 ODE(积分)。路径越直步数越少→更快；训练就是回归速度，简单稳定。与 diffusion 深层同源(diffusion 的概率流 ODE 是近亲)。
"≈ NeRF vs 3DGS" 只对一半：对的是"新方法同目标、采样更快"；不对的是——NeRF→3DGS 换的是表示(隐式 MLP→显式高斯)，diffusion→flow matching 换的是传输的数学形式(随机 SDE→确定性 ODE/更直路径)；且 diffusion/flow-matching 本质同源、远比 NeRF/3DGS 紧密，是"统一精炼"而非"取代"。
Q12 · 为什么不直接用 CoT 造场景？（agent 的诚实纠正）
先认错(范畴错误)：轨迹就是序列(点链/浮点也是 language)，AR/CoT 式生成器完全能造场景(MotionLM 等)，所以"CoT 造不出场景"是错的；而且 CoT 是生成范式、与"闭环评测"正交，早先拿"CoT vs 闭环"对比是混了两件事。
纠正后的真相：流水线有两块——(a) 场景/轨迹生成器(diffusion，可换成 AR/LM/CoT 式；diffusion 胜在联合非自回归+灵活条件+guidance，是工程选择不是"能不能")；(b) 闭环仿真器+RL(rollout 出后果、当 reward 与经验来源)。"用不用 CoT"只关乎 (a)；真正不可替代、且区别于"查答案式 CoT 任务"的是 (b)——撞没撞只能闭环跑出来。

Q13 · §3.4 RL 后训练从零：POMDP 怎么实现
MDP：状态 s / 动作 a / 转移 P(s'|s,a) / 奖励 r / 折扣 γ；循环"在 s 选 a 拿 r 进 s'"，目标最大化累计折扣奖励。POMDP = 部分可观测：agent 看不到真状态 s，只看到观测 o（图像），得据此行动（一帧图揭示不全世界）。
World Engine 的 POMDP 实例(§3.4): 观测 o = 相机图像(3DGS 渲染) 状态 s = ego/他车/地图 动作 a = 从轨迹词表打分选一条 转移 T_θ(s'|s,a) = 行为世界模型 + 仿真引擎 ← "环境" 奖励 r(s,a) = shaped reward(公式19: 安全门×软目标) 策略 π_φ(a|o) = 被训练的自车策略 实现 = 闭环rollout: 看图→选轨迹→环境推进+渲新图→算奖励→再来 整套 WE(3DGS+DiT+平台)就是"环境", 被优化的只有 π_φ
Q14 · 没 GT 怎么训？怎么算 KL？（预训练 IL 有 GT，后训练 RL 没 GT）
没 GT 怎么训 —— 用"奖励"顶替"GT"：IL(预训练)有人类真值轨迹当 GT、最小化距离(要标签)；RL(后训练)没 GT，改用奖励打分：试动作→rollout→看后果(撞没撞/在不在道/有没有进度)，高回报轨迹↑概率、低回报↓。靠"试错+奖励"学，不要标签。这正是为什么必须有闭环——合成危险场景里没人类 GT 可模仿，唯一信号是 rollout 后果。
怎么算 KL —— KL 是"两个模型输出之间"的距离，不需要 GT：
KL(π_φ ‖ π_ref | o) = Σ_a π_φ(a|o)·log( π_φ(a|o) / π_ref(a|o) ) a 遍历轨迹词表候选; π_φ(当前)、π_ref(冻结的预训练) 都是"候选上的概率分布" → 同一观测 o, 让两个策略各跑一遍拿分布, 套公式即可; 完全不需要 GT 洞察: KL 比的是"两个模型", 不是"模型 vs GT"; 且 π_ref 封存了 IL/GT 学到的本事
Q15 · 多步信用分配是什么
一串决策(如 4 秒 20 步)在终点撞车，到底哪一步的锅？把终点结果分摊回沿途每一步 = 信用分配。RL 用折扣累计回报 R(τ)=Σ γ^t·r_t：每个动作的价值=它之后所有奖励的折扣和 → 早期动作若导致 3 秒后撞车、其累积回报就低 → 被惩罚。对比单步 IL(每帧各自跟 GT 比、没有"3 秒前那下害的"概念)：闭环 RL 因 rollout 复合 + 奖励算整段，能把"坏决策→几步后才出事"的因果链起来——这正是它区别于"逐帧 push/pull"之处。
Q16 · KL 的作用
−λ·KL(π_φ‖π_ref) 把后训练策略拴在预训练策略附近，三个作用：① 防灾难性遗忘：只在罕见危险场景猛优化会忘了日常怎么开，KL 锚在擅长日常的预训练策略附近(Table1 常见 PDMS 仍最高即证据)；② 防 reward hacking/退化解：光追安全奖励可能学出"永远急停"，KL 限制别离合理先验太远；③ 稳定训练(信任域)：防策略一步跳太远搞崩(类 TRPO/PPO 的 KL 约束精神)。这就是"behaviour-regularized RL"的 regularized。串起来：没 GT→用奖励学；奖励靠多步信用分配回传；只追奖励会忘本→KL 拴住封存了 GT 知识的 π_ref；再加真实数据混合+hard mining → "罕见变强、日常不退化"。
