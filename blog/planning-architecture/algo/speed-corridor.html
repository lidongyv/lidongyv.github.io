纵向走廊 · STBoundsDecider

为速度 QP 准备「每个时刻 s 能落在哪、对每个障碍怎么办」：把动静态障碍预测投影到 ST 图，扫线扫出每个时刻可通行的 s 区间，并对每个障碍定下 让行 / 超车 / 跟随 / 停车，再叠加红灯、限速、freespace 虚拟墙。是 SpeedCorridorConstructor 子链。

解决的问题

速度 QP 只会「在给定上下界里求平滑速度」，它不知道哪个障碍要让、停止线在哪。纵向走廊负责把这些翻译成 QP 能吃的边界：

  • 障碍 → ST 边界：把每个障碍在未来各时刻占据的 s 区间画到 s-t 图上（静态=竖墙，动态=随 t 移动的带）。
  • 多障碍取舍：同一时刻多个障碍给出不同上下界，要扫线选出一条连贯可行的 s 通道。
  • 规则虚拟墙：红灯停止线、换道暂停、泊车停车、OCC 占据都化成虚拟限速墙叠加进来。
⚙️

实现

Backside→Reverse→Occ→STBounds→SpeedBounds

障碍投影（STObstaclesProcessor）：静态障碍 overlap s 区间在 t∈[0,T] 不变 → 竖直 ST 墙；动态障碍遍历预测轨迹，GetOverlappingS 求每时刻 (s_lo, s_hi)，速度投影 v·cos(θ_obs−θ_path) → SVTPoint(s,t,vₛ)。

// STBoundsDecider 扫线：对每个 tᵢ = i·0.1 (50 点) 1. s_lower=-∞, s_upper=+∞ 2. STDrivingLimits → 车辆动力学可达 s 范围 3. GetSBoundsFromDecisions→ 各障碍 SVT 候选 (s_lo,s_hi) 4. RankDecisions(STGuideLine) → 按参考速度引导选最优 5. SetObstacleDecision → YIELD / OVERTAKE / FOLLOW / STOP 6. 写入 STDrivableBoundary (t, s_lower, s_upper)

虚拟墙：kTldLimit（红灯停止线）/ kParkingStop / kLcPause / kOccLimit，统一以 virtual_limit_wall_width 宽度叠加。限速：SpeedLimitDecider 综合 refline 限速 + 曲率 v≤√(a_lat/|κ|) + 近距障碍的距离-速度表。
