HTS 参考速度 (Hybrid A* + ST)

速度 QP 之前的「领路人」：在 s-t 栅格上用 Hybrid A* 对 jerk 采样扩展，搜出一条把限速、跟车、红灯、换道暂停都编码进代价的参考速度曲线 ReferenceSpeed(s,t,v,a,j)，并顺带给出对各障碍的让行 / 超车意图。是 CoarseTrajectoryGenerator 的纵向产物。

解决的问题

纯凸 QP 擅长「在给定决策下求最优平滑速度」，但不擅长做离散决策——比如对一个横穿障碍到底是「抢先过」还是「让它先走」，这是组合选择问题。HTS 用图搜索补这一环：

  • 给 QP 一个好的参考速度：QP 的 s_ref 和 ST 引导线都来自它。
  • 做让行/超车意图决策：在 ST 栅格里，障碍占据的 (t,s) 区域天然表达「先过还是后过」。
  • 编码硬性事件：红灯停止线、换道虚线停车点都转成限速惩罚融入搜索。
⚙️

实现

STGraph::Search (Hybrid A*)

调用链：HeuristicTrajectorySearch::Search → STGraph::Search。节点 (s, v, a, j, t)，对 jerk 采样集做三次积分扩展，A* 在 ST 栅格里找代价最小路径。

节点扩展（jerk 三次积分）
aₖ₊₁ = aₖ + Δt·j vₖ₊₁ = vₖ + aₖ·Δt + ½Δt²·j sₖ₊₁ = sₖ + vₖ·Δt + ½aₖΔt² + ⅙Δt³·j // v < 0 钳为停车
节点代价 g
g = g_speed_limit 超速惩罚(含红灯/换道停车) + g_acc + g_jerk 舒适 + g_env ST 栅格内障碍碰撞/挤压 + g_improvement −Δs，鼓励前进

障碍投影：AddObs2STGrid 把各时刻障碍 SL 盒写入 (t,s) 栅格。换道：GapManager 选出目标 gap 后，SetCurrentGapInfo 注入目标 s 启发（IDM 期望距）引导搜索；开 multi-gap 时每个 gap 各跑一次 HTS 产出多模态。回退：无 HTS 时退化为匀速巡航 ReferenceSpeed(init_v, 0.1, 5)。
