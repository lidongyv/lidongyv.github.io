一份对 ad-/pnc/planning 真实代码的解构：10 Hz 的 operator 流水线，把轨迹规划拆成先横后纵再合成三步。横向最终路径走 CiLQR（Cartesian 6 维状态联合优化），纵向速度走 OSQP 分段-jerk QP（ST 走廊约束），粗轨迹由 五次多项式 + Hybrid A* 暖启动，泊车另走 Hybrid A* 几何搜索。下面每个结论都标注了「代码可证」还是「遗留/推测」。

一句话速览：横纵向怎么做到

Planning 不是端到端一把梭，而是经典的 path-speed 解耦（decoupled）分层：先在空间上定「往哪走」（横向路径，不含时间），再在这条路径上定「走多快」（纵向速度，含时间），最后把两者对齐合成带时间戳的轨迹。每一层各用最合适的优化器。

① 横向 Path（空间）

先画出「车要走的那条线」l(s)——绕开障碍、贴合车道，不管快慢。主力 CiLQR。

② 纵向 Speed（时间）

在这条线上排「何时走到哪」s(t)——让行/跟车/限速，决定快慢与停走。OSQP 分段-jerk。

③ 合成（时空）

把形状与速度按弧长 s 对齐，吐出带时间戳的 (x,y,θ,κ,v,a,t) 轨迹交给控制。

↔ 横向 Lateral / Path —— 决定路径形状 l(s)

两阶段。① 粗参考路径：Frenet 坐标下用五次多项式暖启动，再由 OSQP 分段-jerk QP 平滑 l(s)（默认）。② 精细路径：CiLQR 在 Cartesian 直接优化 6 维状态 [x,y,θ,κ,v,a]，避障/边界以软代价（penalty）注入。借道/换道通过切换参考线与 goal 点、扩展横向走廊实现。

↕ 纵向 Longitudinal / Speed —— 决定速度曲线 s(t)

两阶段。① 粗参考速度：Hybrid A* + ST 栅格搜索（对 jerk 采样扩展），把跟车/限速/红绿灯都编码进代价。② 精细速度：OSQP 分段-jerk QP 在 5 s / 51 点上优化 s(t)，跟车用 RSS / IDM 软上界；低速到点切「舒适停车曲线」绕过 QP。

⚠️

易混淆点（已用代码校正）：「精细横向 PathOptimizer」用的是 CiLQR，不是 分段-jerk QP；分段-jerk QP（OSQP）用在纵向速度和粗横向参考路径。另外 optimizer/solver/ 里那套基于因子 + Levenberg-Marquardt 的横纵分解求解器，当前并未接入 Optimizer::Create()，属历史遗留代码。

02

横向规划 · Path / Lateral

目标：在 Frenet 弧长 s 上求横向偏移曲线 l(s)，即「车往哪个轨迹走」（不含速度/时间）。分粗、精两阶段，精细阶段是整个横向的主力。

🛣️

一句话：先不管快慢，在车道里画出一条「绕开障碍、平滑贴线」的行车曲线。分两步走——先用五次多项式 + QP 拉一条粗线打底，再用 CiLQR 精修成车真正能开的形状。

阶段 A · 粗参考路径（warm-start + 凸平滑）

阶段 B · 精细路径优化 = CiLQR

PathCorridorConstructor 先沿参考线中心匀速推出启发轨迹 + 映射 SL 走廊（前轴额外 +2.927m），再交给 CilqrTrajectoryOptimizer（泊车场景跳过、直接透传搜索路径）。这是 constrained-iLQR 的工程实现 —— iLQR + 线搜索 + λ 正则化，约束以惩罚代价进入。

状态 / 控制 / 动力学（RK4 离散）
// 6 维状态, 2 维控制 x = [ x, y, θ, κ, v, a ]ᵀ u = [ dκ, j ]ᵀ // 连续动力学 dx/dt = v·cos θ   dy/dt = v·sin θ dθ/dt = v·κ      dκ/dt = dκ dv/dt = a        da/dt = j // 求解器 cilqr::Solver<6,2> iLQR + line-search + LM
代价项（每步 + 终端）
代价形式速度耦合
position refw·‖p−p_ref‖²—
heading refw·(θ−θ_ref)²×v²
kappa refw·(κ−κ_ref)²×v⁴
kappa-ratew·(dκ)²×v⁴
speed/acc/jerkw·(·−·_ref)²—
*Limit 软约束w·max(0,viol)²—
Safety / 前轴w·max(0,d_safe−d)²nudge 界

跟踪参考的巧思：x_ref,y_ref 取自参考线上 (s, goal.end_l) 的 XY（决定横向贴哪条线），而 θ,κ,v,a 参考来自中心线启发轨迹。借道/换道正是通过改 goal.end_l 和切换参考线来「掰」这个跟踪目标。

借道 / 换道：如何影响横向

LANE BORROW · 借道
LaneBorrowDecider
触发：非换道态 + 车速≤15m/s + 非路口 + 前方 blocking/dead_car（3 帧滞回）。效果：把走廊上界/下界扩展到相邻车道边界（无邻道再加 off-lane 宽），但仍用原车道参考线。
LANE CHANGE · 换道
LaneGuider
Precheck → ObstacleTracer → HardEndDecider → Evaluator（Deviation + Efficiency + Pullover 代价）。CHANGE 态切到目标参考线、end_l→0；HOLD 态保持原线 end_l=±0.5m。
03

纵向规划 · Speed / Longitudinal

目标：在横向已定的路径上，求弧长随时间的曲线 s(t)（从而得到 v=ṡ, a=s̈），即「在这条路上走多快、何时停」。同样分粗（搜索）、精（QP）两阶段，且各自有一套 ST 表达。

⏱️

一句话：路径定好后，再决定「在这条线上何时走到哪、何时该让该停」。分两步走——先用 Hybrid A* 在 s-t 图上搜一条参考速度，再用 OSQP 分段-jerk QP 精修成平顺速度曲线。

阶段 A · 参考速度 = Hybrid A* + ST 栅格

⛏ HTS 搜索（默认）

节点 (s, v, a, j, t)，对 jerk 采样集做离散积分扩展；代价 g = 限速 + 加速度 + jerk + 障碍 + 进度(−Δs)。障碍按各时刻 SL 盒写入 (t,s) 栅格，红绿灯/换道虚线停车点编码成限速惩罚。输出 ReferenceSpeed(s,t,v,a,j)。

节点扩展（jerk 三次积分）
ak+1 = ak + Δt·j vk+1 = vk + ak·Δt + ½·Δt²·j sk+1 = sk + vk·Δt + ½akΔt² + ⅙Δt³·j // v < 0 钳为停车

GapManager（换道时）：目标车道 ±80m 障碍排序 → 枚举 gap → 对 (v_diff, acc) 采样推演 + 安全校验 + 代价选最优 gap → 注入 HTS 作目标 s 启发（IDM 期望距）。开启多 gap 时每个 gap 各跑一次 HTS，产出多模态粗轨迹。

纵向走廊 · SVT 边界 + ST 可行域

SpeedCorridorConstructor 子链：BacksideDecider → ReverseDecider → OccDecider → STBoundsDecider → SpeedBoundsDecider。核心是把障碍投影到 ST 图、扫描出每个时刻可通行的 s 区间，并对每个障碍定下 让行/超车/跟车/停车 决策。

阶段 B · 速度优化 = OSQP 分段-jerk QP

在路径弧长 s 上、5 s / 51 点（Δt=0.1s）求 s(t)。状态 [s,v,a]、jerk 为段间控制，标准 QP min ½zᵀPz+qᵀz s.t. l≤Az≤u 交 OSQP。

输出后强制单调：sᵢ=max(sᵢ,sᵢ₋₁), vᵢ=max(vᵢ,0)。低速到点触发滞回 → GenerateComfortStopProfile 直接给停车曲线、绕过 QP。

04

合成 · path ⊕ speed → 轨迹

FinalTrajectoryGenerator 把横向路径 path(s)=(x,y,θ,κ) 与纵向速度 speed(t)=(s,v,a,j) 按弧长对齐，拼出带时间戳的可发布轨迹 PublishableTrajectory。

// 先继承 stitching_trajectory 作为前缀（拼接历史，保证平滑接续） for t in [0, T]: // 0.1s 密采样, >1s 后稀疏 (s, v, a, j) = speed.GetSpeedPointWithTime(t) // 纵向给 s (x, y, θ, κ) = path.Evaluate(s) // 横向按 s 查 Cartesian emit TrajectoryPoint(x, y, θ, κ, v, a, j, t + t_stitch)
🧭

Frenet → Cartesian 在哪做？ 不在合成阶段。粗路径在 ConstructDiscretizedPathByFrenetFramePath() 就转好；CiLQR 直接输出 Cartesian。合成时只按弧长 s 查表，不再做坐标变换。
