OD 检测方案介绍与迭代计划

基于 onemodel 共享 PV2BEV + BEV feature，用 Query Group 分组解耦输出五大类目标，支持临时新增任意稀少类别 query；后续沿 Sparse（陈昌）与时序 + 预测（张达）两条主线演进。整套方案围绕可验证 · 可迭代 · 可预测设计。

🔬 可验证 · 每类独立评测 🔁 可迭代 · 需求方自助加 query 📈 可预测 · 距离/稳定按需扩展

总览 · 共享架构与设计哲学

12V 图像经统一 PV2BEV 得到共享 BEV feature，OD / Lane / TLD / OCC 各挂任务头；OD 在自车系输出动 / 静态目标 3D 框。三条设计主线如下。

🧩

共享 BEV 主干 + 多任务头

共享 PV2BEV 与 BEV feature，OD 仅负责检测头；前融合分支额外融合 Lidar 点云特征。

🎛️

Query Group 分组解耦

不同 query 组数据与配平互不影响，新增类别 / 需求只加耗时、不动主线指标，支持多人并行迭代。

🚀

Sparse · 时序 + 预测

两条改进主线：Sparse 适配任意检测距离并切分纯视觉 / 前融合；时序 + 预测解决稳定性与短距预测。

五大类输出 + Animal query（待合入）+ 临时新增稀少类别能力；Query Group 分组迭代；共享 PV2BEV + BEV feat。

02

泊车位检测专项蔡孟玥

泊车位作为第 6 个 query group（group 5）接入，复用整套解耦机制；表征从 3D bbox 演进到 2D polygon（4 角点），并带占用 / 类型 / 属性多重状态识别——「新增类别只加 query、不动主线」与「可验证 / 可迭代」的最佳样例。

P

Parking Zonegroup 52D polygonconfig 驱动

走全部 head（camera / lidar / fusion），Lidar 两路对 parking 零 loss（以视觉为准）；Head / 后处理零代码改动，纯 config 新增。

① 接入 · Query Group group 5（config 驱动）

  • group 5（label=5）加到现有 5 组后，模型结构不变，parking query 走全部 head
  • lidar_zero_loss_groups=[5]：Lidar OD + Fusion Lidar 两路对 parking 零 loss（以视觉为准）
  • Head / 后处理零代码改动：num_groups 由 len(group_num_queries) 自动驱动
  • DOD / SOD 都监督：dod=[0,1,2,3,5]、sod=[4,5]
# config 驱动新增 group 5（基线 bbox 形态）
CLASSES = { ..., "ParkingSpace": 5 }
GROUP_NUM_QUERIES = [540,108,180,72,20,40]
group_score_thr   = [.2,.25,.2,.2,.1,.15]
lidar_zero_loss_groups = [5]  # Lidar 两路 loss=0

② 表征演进 · 3D bbox → 2D polygon（角点 CA）

  • base：N 条中心 query，单 reference deformable CA；offset 半径只有几 BEV pixel，远端角点出感受野、长车位覆盖不足
  • 角点 CA（MapTR 式）：N instance × 4 corner query，每角点带独立 reference 做 deformable CA
  • line_wise_sa / line_to_ins 把 4 角点绑到同一 instance；保留 bbox 分支
  • parking query 40→120（30×4），总 query 960→1040，多一路 corners 输出
中心 query（覆盖不足） vs 4 角点 CA（polygon）

③ 多重状态识别 + 评测（可验证）研发 / 验证中

  • 除 corner / heading 外，识别 Occupancy（占用）/ Type / Attribute
  • Attribute 长尾：charging / disabled / ground_lock(raised·lowered) / diagonal
  • 1000 帧 parking val · corner 精度 / heading 误差 / 分类准确率 · perm loss 角点匹配
⚠️

数据：4 类 ATTRS 长尾 + 斜列缺口大需分批补采；val 仅 1000 帧、3 个长尾类 0 instance，须先扩 val（P0）。

03

改进主线 A · Sparse 方案陈昌

动态适配检测距离；切分纯视觉与前融合两条路线分开迭代——纯视觉作基本盘、前融合作交付项；增强 query group 响应能力，随时随地按需加 query。

核心思想 · 去掉 PV2BEV

Dense BEV 先用约 20000 个 BEV query、3 层 transformer（约 90G FLOPs）建图，再让 OD query 查图。Sparse4D 跳过建图：每个 query 知道自己 3D 位置后，直接算出投影到 12 相机的 2D 像素并采样——920 个 query 各自独立采样。

Dense「建图→查图」 vs Sparse「直接查原图」

GroupedSparse4DHead · 实现细节

输出格式与 GroupedBEVFormerHead 完全兼容，与现有 query group / 配平 / 评测体系无缝对接。

# Instance Bank（query 起点）
instance_feature: (bs, 920, 256)  # 全零初始化
anchor:           (bs, 920, 10)   # KMeans 初始化
# 920 query 按类别分 5 组
group_sizes = [540, 108, 180, 72, 20]
# anchor 10 维 = [X,Y,Z, logW,logL,logH,
#               sinYaw,cosYaw, VX,VY]

# Decoder：6 层迭代精炼 · 每层 op_order
[deformable, norm, ffn, norm, refine, gnn, norm]
#   第 1 层跳过 gnn+norm；各操作参数不共享
  • Deformable Aggregation（替代 PV2BEV）：每 anchor 生成 13 个 3D 关键点（7 固定 + 6 可学习）→ 投影 12 相机 → 多尺度 grid_sample → 8-group 注意力加权融合
  • PVRefinement：embed=256 · points=4 · cams=12 · levels=2(stride16/32) · heads=8
  • Refinement：box 残差回归（共享）+ 分组二分类（每组独立 MLP）

2-stage 纯视觉 / 前融合切分 研发 / 验证中

4 个 vision block + 2 个 fusion block，在 fusion 边界 detach，从 bft200 warm-start。评测固定三列：dense baseline / 纯视觉(2stage_cam) / 前融合(2stage_fused)。

04

改进主线 B · 时序 + 预测张达

解决稳定性问题以及短距离预测与状态识别。保单帧为 base，多帧为后融合方案，吃收益、不接受回退。

Stream time fusion · 两种形态

# 形态 1：缓存 5 帧时序队列
for frame in stream:
    q = cross_attn(frame, queue[-5:])
    assoc, traj = predict(q)   # 关联 + 轨迹预测

# 形态 2：无缓存队列（仅与上一帧 CA）
for frame in stream:
    q = cross_attn(frame, prev)
    if warmed_up:  emit(traj)  # 前 4 帧不出 traj
⏱️

关联 (association) 已初步可用，作为轨迹预测的前置；用当前帧 CA 后的 query 做关联与预测。

当前进展 · 张达「时序模型进展」

子项状态备注
关联 association初步可用作为预测前置
轨迹预测迭代中已训一版；large veh. 时序数据需调整重训
帧间稳定调优中首帧抖动；修复后整体轨迹变差，需平衡
死车 / 静止车标签待处理帧间稳定性（李辰提出）
⚠️

关键约束：单帧为 base、多帧为后融合——多帧分支只做增量，必须吃收益、不接受回退，主线随时可回退到稳定单帧。

05

三可论证落地

设计与迭代如何具体兑现「可验证 · 可迭代 · 可预测」。

🔬 可验证

  • 每个 query group 独立评测，互不干扰
  • 场景 × 距离桶 × 类别 × 指标（AP / P / R / x_err / y_err / rot）
  • 固定三列对照：dense / 纯视觉 / 前融合，[+]/[-] 标注，pp<0.5 视为持平

🔁 可迭代

  • 组内自主配平，新增不动主线、只加耗时
  • 多人并行：每条 query group / 主线独立 owner
  • 需求方自助加 query 跟数据迭代，CIPV 60m 一天上线即范式

📈 可预测

  • 检测距离：Sparse 动态适配，按需扩展不重构
  • 稳定 / 预测：时序短距预测 + 状态识别，单帧 base + 多帧后融合
  • 收益边界：纯视觉近距已可用、前融合全段吃收益，可估算每步 ROI
