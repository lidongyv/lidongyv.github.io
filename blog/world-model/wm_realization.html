① 动机 / 核心思想

为什么要做多任务 v2：clean full latent 下 caption 被模型完全忽略。
诊断 在 clean full latent 条件下 caption 内容被完全忽略：交换 caption 内容（caption swap）输出 L1 ≈ 0.014（≈ 直接删除 caption 的效果）；只有把 cross-attn 整条关掉（OFF）输出才崩到 1.22。根因——recon / depth / seg 是图像的确定性映射，给了干净全 latent，目标已被输入唯一决定，caption 信息冗余，模型自然学会不看它。
解法（无法造 paired data） 造不出「同图不同 caption 对应不同真值」的 paired data，于是走多任务 v2：用 MAE / 噪声 / coarse 池化 / perceiver 主动制造信息缺口 H(Y|X) > 0——让输入不再唯一决定输出。caption 只注入生成类任务（ids 3–7），逼模型真正用 caption 去补上缺失的信息。
一句话 确定性任务（recon/seg/depth）里 caption 是冗余的 → 模型不看；制造信息缺口后目标不再被输入唯一决定 → caption 成为必要条件，模型被迫使用。门控开关：caption_task_ids = [3,4,5,6,7]（开 id9 caption-perceiver 时 +9、开 id10 diffusion-transfer 时 +10）。

③ 实现要点

caption 怎么进模型、perceiver 怎么造瓶颈、cond-stream 双流怎么写回、warm-start 怎么接。

caption-AdaLN-Zero ca 模式caption_adaln

零初始化 AdaLN 头把 umT5 caption 池化成条件向量 → 加到每个 DiT 块的时间调制 e0，按 caption 行门控。

默认关闭时逐位不变（零初始化 = 恒等起步，不扰动 baseline）。

开关 caption_adaln · 注入点 = 每个 DiT 块的 e0 时间调制

Perceiver id7 recon_perceiver · lightperceiver_mode: ca|sa

6 层（原 2 层）。单开关 perceiver_mode 同时控制【提取】（128 可学习 query 读干净 z0）与【注入】（perceiver token → DiT image token），二者强制同模式。

ca = cross-attn：query 交叉注意 z0 / token 进 cross-attn context。
sa = self-attn：query 与 z0 拼接做自注意力 / token 并入 image 自注意力序列，用 per-row self_attn_mask 隔离非 perceiver 行。

新增 · single-pass caption perceiver_caption_sa：sa 模式下把 caption tokens 拼进 perceiver 自注意力序列（query + z0 + caption），input 仍为纯噪声。与 id9 heavy 的 two-pass 构成 single-pass ↔ two-pass 对比。

默认 ca · 提取与注入模式强制一致 · perceiver_caption_sa 默认 off

cond-stream SA captioncond_attn_mode: ca|sa

sa 下 caption / 任务 token 作双流 attend 图像 K/V，并经零初始化 beta_img 门做 image ← cond 双向写回（MJ1 修复）。

step0 与 ca 逐位一致，随训练 caption 才开始影响图像。

开关 cond_attn_mode · beta_img 零初始化 → 起步无扰动

Heavy perceiver id9 caption-perceiver · two-passcapperc_two_prompt

两遍 DiT + caption 进两 pass 自注意力。基于 id9 caption_perceiver + 开关 capperc_two_prompt：Pass1 EXTRACT（prompt「extract the scene content into compact tokens」）从干净 z0 提 128-token readout；Pass2 INJECT（prompt「generate the driving scene from the caption and compact tokens」）从噪声凭 readout + caption 重建 z0。

两 pass 用不同 task-prompt，caption 在两 pass 都进 perceiver 自注意力。因两遍 DiT 显存重 → bs = 2。
（原始 id8 prompt_extract_perceiver 是无 caption 的独立变体，默认关；"heavy" 实验走 id9 + two-prompt。）

id9 + capperc_two_prompt · caption-in-SA(both passes) · 与 id7 light 成 single↔two-pass 对比

Diffusion-transfer id10 · newdiffusion_transfer_task

独立 rectified-flow 任务（与 id5 diffusion 分开、不混）。输入 = A 样本的 z0（clean 或随机-t 加噪，各 50%）；条件 = B 样本 caption；GT = B 的 clean z0；20% B=A。prompt =「diffusion transfer」。

逼模型把 A 的内容按 B caption 迁移 → 直接量测 caption 对生成的驱动力。B 样本经 batch 内 roll-by-1 取（需 batch≥2）。

id10 · 复用 _genception_v_loss flow · caption_task_ids +10

init_ckpt warm-start

4 组实验均从 baseline 26415 的 step12000 非严格加载（matched = 858, unexpected = 0）。新增参数（6 层 perceiver 的后 4 层 / caption_ada / cond-stream / heavy）保持各自初始化；caption_ada 输出零初始化 = 恒等起步，保证 warm-start 起点与 baseline 行为一致、不破坏已学表征。

strict=False load · matched=858 · unexpected=0 · 新增参数各自初始化

输出头与解码

GenCeption-faithful velocity head + Wan-VAE 解码——velocity（flow-matching）预测忠于 GenCeption 设定，latent 经 Wan-VAE 解回像素。

最新结论（驱动本轮重设计） (a) 除纯 diffusion（id5）外，图像条件任务（env_gen / gen_mask / gen_mani / perceiver）基本忽略 caption——上图 diffusion L1=1.032 一枝独秀，其余都低。(b) perceiver 重建质量差（recon_perceiver 仅 0.153，且成像模糊）。(c) 主要症结 = perceiver + caption。→ 据此重设计 id4（1×1 coarse + 50% B-swap）、id7（caption 进 perceiver SA）、id9 heavy（two-pass caption-perceiver + 两段 prompt），并新增 id10 diffusion-transfer 直接量测 caption 驱动力。
