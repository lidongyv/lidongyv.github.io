Perception · 物体感知

物体感知的两个本质问题 · 从 OD formulation 出发

从物体检测（OD）出发，用两个本质问题组织物体感知的架构哲学：① 先检测还是先预测 · ② 先单帧还是先时序。并直面一个实验痛点——grid-based formulation 对大目标（vehicle）划算、对小目标（行人/cyclist）大量浪费算力；解法不在"堆分辨率/堆算力"，而要从 formulation 改起。

⚠ 思考框架 / 判断；含内部实验观察；所引方法为公开工作，具体收益需实测

① 两个本质问题 = 一张「感知架构哲学」两轴图

横轴：先检测 ↔ 先预测；纵轴：先单帧 ↔ 先时序。两问不是独立的——右上（预测×时序）就是世界模型/端到端那一支，左下（检测×单帧）是传统起点，对角线是演进方向。
问题 1 · 先检测 还是 先预测

detect-first vs predict-first

  • 先检测：单帧/当前观测先出 box/instance，再做跟踪、运动预测。模块化、可监督、可评测（每帧有 GT）；但丢时序先验，单帧歧义（遮挡/远小目标）难解。
  • 先预测：先在表征里预测世界演化（未来状态/占用），检测是预测的一个 readout。利用运动先验、对遮挡鲁棒、与世界模型统一；但监督/评测难、误差累积。
  • 我的判断：趋于融合——query-based 端到端里 object query 跨帧传播，检测即预测（同一 latent 同时出当前框与未来）。
问题 2 · 先单帧 还是 先时序

frame-first vs temporal-first

  • 先单帧：把单帧做到极致再叠时序。工程稳、标注友好（单帧标注多）、是强基线；但小目标/遮挡/运动模糊在单帧本就信息不足，单帧上限低。
  • 先时序：时序作一等公民，单帧是特例。对小目标（多帧累积弱证据）、遮挡（时序补全）、速度（天然可得）有本质增益；但计算/内存重、时序对齐与标注难。
  • 我的判断：小目标/遮挡本质是"单帧信息不足"，时序有不可替代增益；但落地宜"单帧建强基线 → 尽早时序化"。
两问是耦合的
先预测 ≈ 先时序（预测世界必然要时序，落在右上＝世界模型/e2e）；先检测 ≈ 先单帧（左下＝传统）。所以这不是两个独立选择，而是同一条对角线——从"单帧检测"走向"时序预测"，检测逐渐变成"预测世界"的一个出口（呼应 统一视角：检测＝在某层 latent 上的一个 readout）。

② 实验观察：grid-based formulation 的小目标困局

◆ 内部实验观察
grid-based formulation 对 vehicle 检测效果不错，但对行人 / cyclist 等小物体会浪费大量算力。 直觉修法（提高全图 grid 分辨率）会让算力平方级增长，而增加的高分辨 cell 绝大多数是空的——钱花在了背景上。
先看清 grid formulation 为什么"大目标划算、小目标亏"。
  • 分辨率–算力平方矛盾：小目标要细粒度 → 提 grid 分辨率 → 算力/显存 O(H×W) 平方增长。
  • 稀疏性浪费：真实场景绝大多数 cell 是道路/背景（空），密集 grid 对空 cell 一视同仁地算，钱花在背景上。
  • 尺度失配：vehicle 占多 cell（grid 是"合适容器"），行人/cyclist 是 sub-cell（一个 cell 塞不下一个、或多人挤一个 cell），grid 粒度与目标尺度天然不匹配。
  • 密集监督不友好：小目标正样本极少，密集 head 的正负极度不平衡，训练也吃亏（这是 formulation 带来的，不只是算力）。

③ 从 formulation 出发的解法：从「为空间付费」到「为物体付费」

核心不是堆分辨率/堆算力，而是改表述让算力自适应地流向"有物体、需细粒度"处。按"改动的彻底程度"排序。
最本质

密集 grid → 稀疏 query

放弃"每 cell 预测"，改"每 object query 预测"。算力 ∝ query 数（≈物体数），与空间分辨率解耦；小目标可多派/自适应分配 query，不为空背景付费。

代表：DETR / Deformable DETR / Sparse R-CNN；3D：Sparse4D · PETR / StreamPETR · SparseBEV。
缓解

多尺度 / 分层分配

小目标交高分辨浅层特征、大目标交低分辨深层（FPN + 按尺度分配标签）。缓解尺度失配，但高分辨层仍密集，没根治平方问题。

代表：FPN · FCOS 多尺度 · NWD/RFLA（小目标标签分配）。
算力跟前景

coarse-to-fine / 前景稀疏化

先粗 grid 找 foreground，只在前景区域细化（级联 / 稀疏卷积 / token 剪枝）。算力随前景走，空背景不细算。

代表：SparseBEV · SparseOcc · Focal Sparse Conv（LiDAR 侧类比）· AdaMixer。
自适应采样

deformable / 可变形采样

采样点自适应聚到物体上，不均匀撒点；小目标处采样密、背景处稀。把"密集卷积"换成"稀疏可变形 attention"。

代表：Deformable DETR · Deformable attention 系。
换坐标系

非均匀 formulation

换表述让远处小目标不被稀释：距离自适应 BEV 分辨率（近粗远细）、极坐标 grid（远处角分辨率自然细）、range-view（LiDAR 侧）。

代表：PolarFormer / 极坐标 BEV · 距离自适应体素。
接时序

object-centric + 时序 query 传播

小目标单帧弱证据 → 跨帧传播 query、累积证据，让弱小目标从背景里"跳"出来。把"先时序/先预测"直接变成算力分配器。

代表：StreamPETR（memory queue）· Sparse4D 时序 · MOTR（query 传播）。
✔ 一句话解法
小目标困局的根因是 grid「为空间均匀付费」；解法是把 formulation 改成 「为物体付费」——稀疏 query（算力∝物体）＋ 前景稀疏化（算力跟前景）＋ 时序 query 传播（弱证据累积）。堆分辨率是治标，改 formulation 才治本。

④ 回接两个本质问题

小目标困局恰好把两个本质问题"逼"了出来：
· 它印证 先时序——行人/cyclist 单帧只有几个像素/一个 cell，信息不足；多帧时序累积是把弱证据攒够的本质手段（不是锦上添花）。
· 它也印证 先预测——用预测的占用/运动先验引导算力分配（"哪里可能出现人 → 那里细化"），即 prediction-guided detection。
· 而"稀疏 query"这个解法，正是 统一视角 里"消费哪层 latent + 多层出口"在检测上的落地：检测 head 从"密集像素/cell readout"变成"稀疏 object-query readout"。

⑤ 我的推荐路线

  • 工程上"先单帧"建强基线（快、标注友好、可评测），但——
  • 架构上从第一天就押"稀疏 query"而非 dense grid，避免小目标的"分辨率债"；vehicle 用 dense grid 的短期收益，会在小目标上连本带利还回来。
  • 尽早"时序化"：object-centric query 跨帧传播，既解小目标弱证据、又天然得到速度/运动。
  • 终局"检测即预测"：让检测成为"在某层 latent 上预测世界"的一个 readout（右上象限），与世界模型统一。
