Cross3DGS：跨平台 3DGS 训练的 schedule 选择

④ 系统执行类 arXiv 2611.22240 · WACV 2027 Workshop ｜ 让同一优化器在桌面与手机上算对

中文核心说明

把 3DGS 训练搬到手机上，难点不在「把 CUDA kernel 翻译一遍」：subgroup 宽度、float32 原子加、storage-buffer 范围、批量 command submission 的可靠性因 GPU/驱动而异，决定名义等价的步骤能否完成并返回正确的 update。关键观察是：错误的梯度也可能渲染出漂亮的 PSNR，所以正确的验证方式是直接比对 update 数值（同 GPU 精确 gather 最大差 3.4e-8，CPU 双精度 oracle 1.6e-5），而不是只看画质。

Cross3DGS 训练循环不变（projection → tile binning+radix sort → alpha 合成 → loss → 梯度 → Adam，MCMC 稠密化每 100 步、在循环外），区别在于：把 6 个执行选项（梯度方法、command submission、训练图驻留方式、排序实现、投影+Adam 融合、pair dispatch）组合成 256 种 schedule，选择分两步——① 13 条规则排除「已知会算错」的组合：5 条设备限制（如 native atomic 要求 float32 atomicAdd、tiled 需要 ≥48KiB 共享内存与 ≥8 lane subgroup）、4 条负载规则（如 resident 要求图像完整放进单个 storage buffer）、4 条驱动规则（全绑定 Qualcomm 实测故障：scatter failure / watchdog timeout / sort key 损坏 / device fault）；② 对剩余可行集用固定偏好序取最靠前的组合，不在设备上计时。无可行解则拒绝训练，而不是硬跑。

English summary. Porting 3DGS training to phones is not a matter of translating CUDA kernels: subgroup width, float32 atomics, storage-buffer ranges and batched command submission reliability differ across GPUs and drivers, deciding whether nominally equivalent steps execute and return a correct update. Wrong gradients can still yield plausible PSNR, so correctness is verified by comparing updates directly (3.4e-8 max diff vs exact pair gather, 1.6e-5 vs a CPU double-precision oracle). Cross3DGS keeps the training loop (projection → tile binning + radix sort → alpha compositing → loss → gradients → Adam; MCMC densification every 100 steps, outside the loop) and instead composes 256 execution schedules from 6 option axes. Selection is two-stage: 13 rules exclude known-incorrect combinations — 5 device limits (native atomics need float32 atomicAdd; tiled needs ≥48 KiB shared memory and ≥8-lane subgroups), 4 workload rules (resident needs the image to fit one storage buffer), 4 driver rules (all Qualcomm-bound, recording observed failures), then a fixed preference order picks the first feasible schedule without on-device timing. No feasible schedule → refuse to train.

核心代码实现（示意，按论文 §3–§4 整理）

import itertools

# 6 个执行选项轴（Table 1）
AXES = {
    "grad_method": ["per_splat", "per_pixel_cas", ...],       # 8 种梯度实现
    "submission":  ["batched_8", "fenced"],                    # 命令提交方式
    "train_graph": ["resident", "streamed"],                   # 训练图驻留/流式
    "radix_sort":  ["subgroup", "portable"],                   # 排序实现
    "proj_adam":   ["fused", "split"],                         # 投影+Adam 融合
    "pair_dispatch": ["indirect", "direct"],                   # pair 调度
}
SCHEDULES = [dict(zip(AXES, combo))
             for combo in itertools.product(*AXES.values())]   # 256 种

def device_rules(c, lim):
    """5 条设备限制规则：返回 False 表示已知会算错。"""
    if c["grad_method"] == "native_atomic" and not lim.get("float32_atomic_add"):
        return False                                            # 需 float32 原子加
    if c["grad_method"] == "tiled" and (lim["shared_kb"] < 48 or lim["subgroup"] < 8):
        return False                                            # 需 48KiB 共享内存 + ≥8 lane
    if c["train_graph"] == "resident" and not lim.get("image_fits_buffer"):
        return False                                            # 图像要能放进单 buffer
    if c["pair_dispatch"] == "indirect" and not lim.get("indirect_supported"):
        return False
    return True

def workload_rules(c, wl):
    """4 条负载规则：负载太大就回退（如 1M 高斯 + 全 SH 需要 streamed）。"""
    if c["train_graph"] == "resident" and wl["gaussians"] * wl["bytes_per_gauss"] > wl["buffer_max"]:
        return False
    if wl["sh_two_buffers_overflow"] and c["train_graph"] == "resident":
        return False
    if wl["frames"] * wl["frame_bytes"] > wl["buffer_max"] and c["train_graph"] == "resident":
        return False
    return True

def driver_rules(c, lim):
    """4 条驱动规则：Qualcomm 上实测的故障组合（scatter/watchdog/sort key/device fault）。"""
    if lim["vendor"] != "qualcomm":
        return True
    return c["radix_sort"] == "portable"      # 该平台 subgroup sort 会坏 key；其余 3 条同理由

RULES = (device_rules, workload_rules, driver_rules)

def feasible_schedules(lim, wl):
    out = []
    for c in SCHEDULES:
        if (device_rules(c, lim) and workload_rules(c, wl)
                and driver_rules(c, lim)):
            out.append(c)
    return out

def choose_schedule(lim, wl, preference):
    """两步：规则排除 -> 固定偏好序取首个可行（不做 on-device timing）。"""
    F = feasible_schedules(lim, wl)
    if not F:
        raise RuntimeError("no feasible schedule on this device")  # 拒绝训练
    return next(c for c in preference if c in F)

实现要点

要点取值 / 做法
组合规模6 轴 × 各自选项 = 256 种 schedule；Adreno740 淘汰链 256→128→32→6
规则数量5 设备 + 4 负载 + 4 驱动（驱动规则全绑定 Qualcomm）
选择策略固定偏好序（按 Table 1 列序），不在设备上计时；无可行解即拒训
内存1180 B/高斯槽 × 1M = 1.18 GB；bicycle 全程 2.13 GB
正确性验证同 GPU exact pair gather：梯度 3.4e-8、Adam 1.5e-6；双精度 oracle 1.6e-5；负控制（漏一个 tile partial）29,921 例违约被抓
设备范围8 配置 6 厂商：NVIDIA/Intel/Mali/Adreno/AMD(RADV)/Apple（MoltenVK）；跨设备 PSNR span 0.019 dB
