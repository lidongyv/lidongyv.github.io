# 大模型 → VLA / WAM 蒸馏研究

> 独立工程。目标：把「把大模型蒸馏进 VLA / 世界-动作模型（WAM）」这件事，拆到可实现的损失、可复现的配置、可对比的数字。
> 建立时间：2026-11-21 · 主要覆盖：2026-08-15 → 2026-11-21 的新进展，向前追溯到 2015 年经典 KD 与 2022 年扩散蒸馏。

---

## 这个工程回答什么

1. **实现**：每篇核心论文蒸什么、在哪一层对齐、损失长什么样、冻结什么、训练配置是什么、伪代码能不能直接抄。
2. **原始大模型的效果与速度**：教师是多少参数、多少 Hz / 多少 ms、什么成功率。
3. **蒸馏后的效果与速度**：学生掉多少点、快多少倍、显存省多少——以及**反超**的案例。
4. **trick 总谱**：常用（soft label、hint layer、on-policy、DMD、progressive）与不常用（闭式权重编辑、随机单跳、冲突感知多教师、离线特征缓存、跨架构 CKA）的完整清单，带公式与代码。
5. **最近三个月**：2026-08-15 之后的 30+ 篇工作，按机制归类，标出哪些只是摘要级证据。

## 三条最重要的结论（先看这个）

1. **蒸馏可以反超教师**：Orion-Lite 闭环 DS 80.6 > 教师 77.7；SnapFlow 1-NFE 98.75% > 10-NFE 教师 97.75%。原因不是"学生更强"，而是**蒸馏顺带修掉了教师推理路径上的误差累积**（多步积分、长 CoT、测试时搜索的方差）。
2. **2026 年下半年的主战场从"蒸输出"转向"蒸过程"**：on-policy 蒸馏（学生自己跑、教师对学生到达的状态打分）与步数蒸馏（蒸去噪轨迹/端点）成为两条主线；纯 logit KD 在 VLA 上几乎消失。
3. **部署时"教师必须消失"是硬约束**：能落地的方案要么离线缓存教师特征（THAW-VLA）、要么把教师蒸进权重后丢掉蒸馏模块（CKT-WAM、Orion-Lite）、要么教师只在训练期存在（VLP）。任何推理期还要加载教师的方案，在车端/机器人上都不成立。
