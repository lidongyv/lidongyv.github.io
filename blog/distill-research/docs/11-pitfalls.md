# 11 · 陷阱与复现清单：蒸馏论文里最容易骗人的 15 件事

> 这一页是"审稿人视角"。每一条都给：**现象 → 为什么错 → 怎么查**。
> 用法：读别人的蒸馏论文时逐条对照；自己做实验时当作 checklist。

---

## 1. 拿 open-loop 指标证明蒸馏成功

**现象**：动作 L2 / 轨迹 ADE 降了 20%，就宣称蒸馏有效。
**为什么错**：驾驶 VLA 的 open-loop 与 closed-loop 排序经常相反。Orion-Lite 在相关工作里点名 DiMA：*"distilling VLM features via KL-divergence but limits its evaluation to open-loop metrics"*——open-loop 好的学生，闭环可能更差（因为学生一旦偏离就回不来，而 open-loop 永远不会偏离）。
**怎么查**：要求闭环指标（Bench2Drive DS、NAVSIM PDMS、LIBERO 成功率）；至少要有 on-policy rollout 的曲线。

## 2. 把"模块加速 150×"当成"端到端加速 150×"

**现象**：摘要写 "accelerates the reasoning module's inference by 150×"。
**为什么错**：150× 只针对被替换的 reasoning 模块；端到端还有视觉编码、tokenizer、动作头。Orion-Lite 自己给了全链路数字：**806ms → 267ms（约 3×）**。
**怎么查**：找端到端 batch=1 的延迟；看是否包含预处理与后处理。

## 3. 教师没有被放在同一评测协议下重跑

**现象**："学生 80.6 > 教师 77.7"。
**为什么错**：教师的 77.7 可能来自原论文（不同 checkpoint、不同评测脚本、不同帧率），学生的 80.6 是作者自己复现的。跨协议比较没有意义。
**怎么查**：看有没有"我们复现的教师"这一行；没有就标 L1。

## 4. 把"蒸馏"和"压缩/加速"混为一谈

**现象**：Fast-WAM、Rift、LAWA 被列进"蒸馏综述"。
**为什么错**：它们没有教师被拟合，只是训练-推理路径不同（训练用未来帧、推理删分支；或一次前向预填 KV）。把它们算作蒸馏，会让"蒸馏到底有没有用"的结论失真。
**怎么查**：问一句"有没有一个教师模型的输出/特征被学生显式拟合？"没有就不是 KD。

## 5. 蒸馏数据里混进了评测分布

**现象**：用大模型在 nuPlan 全量上造 CoT，然后在 nuPlan 上评测。
**为什么错**：教师见过评测场景（或评测场景的近似），学生等于间接见过测试集。
**怎么查**：看数据划分是否按场景/城市/时间切分；看教师训练集与学生评测集是否重叠。

## 6. 只报成功率，不报方差与种子数

**现象**："LIBERO 98.75%"。
**为什么错**：LIBERO 已接近饱和（97–99%），1 个点的差异在 3 个种子下可能不显著；不同论文的评测协议（每任务 50 次 vs 500 次）差别巨大。
**怎么查**：要求 mean±std、种子数、每任务 rollout 数；饱和基准要看 LIBERO-Plus / RoboCasa / 真机。

## 7. 蒸馏成本不计入总账

**现象**：只报学生推理便宜，不报蒸馏花了多少 GPU 小时。
**为什么错**：CKT-WAM 用 8×A800 训 CKT 模块；S-VAM 自蒸馏 50k 步单卡 H100；GR00T N1 预训练 5 万 H100 小时。如果蒸馏成本 > 重新训一个小模型，那蒸馏就不划算。
**怎么查**：找 "training cost / GPU hours" 一节；没有就自己按 batch×steps×卡数估。

## 8. 学生的速度是在不同精度/批大小下测的

**现象**：教师 fp16 batch=8，学生 int8 batch=1。
**为什么错**：延迟对比必须同精度、同批大小、同硬件、同 warmup。
**怎么查**：看 latency 表的脚注；没有就假设不可比。

## 9. "学生反超教师"其实是测试时计算不同

**现象**：学生单次前向 > 教师单次前向。
**为什么错**：可能学生用了更多 test-time 采样（Best-of-N），或教师被限制了输出长度。
**怎么查**：对齐 NFE / 采样次数 / token 预算再比。

## 10. 动作 chunk 长度不一致导致 MSE 虚高/虚低

**现象**：教师 H=50，学生 H=10，直接 MSE。
**为什么错**：时间网格错位，学生学的是"被平均后的动作"。
**怎么查**：看论文有没有写重采样/只对齐前 k 步；没有就是隐藏 bug。

## 11. 一步蒸馏后的模式塌缩没人提

**现象**：1-NFE 学生在多峰任务（绕障、抓取多解）上成功率掉很多，但平均值看不出来。
**为什么错**：端点 MSE 会把多个模态平均成"中间动作"（比如撞向障碍物中心）。
**怎么查**：看有没有 per-task 的最差任务；看可视化轨迹是否"平均化"。

## 12. 教师特权信息在部署时消失，但论文没说

**现象**：教师用真值感知/未来帧/仿真状态训练，学生只用相机。
**为什么错**：这是"学习作弊"（Learning by Cheating），不是纯蒸馏；部署时学生拿不到特权信息，性能边界不同。
**怎么查**：看 §3 的输入表；看有没有"privileged information"字样。

## 13. 蒸馏后遗症：遗忘与能力窄化

**现象**：蒸馏后在目标任务上很好，但通用指令跟随/其他任务崩了。
**为什么错**：小学生在拟合教师分布时丢掉了预训练能力（灾难性遗忘）。
**怎么查**：看有没有"蒸馏前后在其他 benchmark 上的对照"；没有就自己补一个零样本测试。

## 14. on-policy 蒸馏的教师查询成本被隐藏

**现象**："on-policy 比离线好 5 个点"。
**为什么错**：on-policy 每步要一次教师前向，教师 7B 时训练成本可能 10×；如果教师查询降采样到 1/10，增益可能消失。
**怎么查**：看教师查询频率、是否有 cache、是否用 LoRA 教师。

## 15. 把"自蒸馏"当成"免费午餐"

**现象**：教师=自己多步输出，宣称"不需要教师"。
**为什么错**：自蒸馏的目标来自模型自身，无法引入新知识；它压缩的是**推理路径**，不是**知识容量**。S-VAM/SnapFlow 属于这一类——它们能提速、甚至小涨，但不能让 0.5B 学生学会 7B 教师的世界知识。
**怎么查**：问"教师的知识从哪来？"如果答案是"模型自己"，那它是加速方法，不是知识迁移。

## 复现清单（做自己的蒸馏实验时逐项打勾）

- [ ] 教师 checkpoint 固定，记录 hash / 日期
- [ ] 教师在同一评测脚本下重跑，得到 baseline
- [ ] 学生同架构、同数据、无蒸馏的对照（ablation 的 anchor）
- [ ] 蒸馏数据与评测数据按场景切分，记录重叠检查
- [ ] 延迟：batch=1、同精度、同卡、warmup 100 次、报 p50/p95
- [ ] 成功率：≥3 seeds、每任务 ≥50 rollouts、报 mean±std
- [ ] 蒸馏成本：GPU 小时、教师前向次数
- [ ] 部署形态：推理时是否还加载教师/蒸馏模块（必须是"否"）
- [ ] 能力保持：蒸馏前后在 2 个无关 benchmark 上的零样本对照
- [ ] 失败案例：至少 5 条可视化，标注失败模式（平均化/抖动/卡死）
