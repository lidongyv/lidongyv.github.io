2. 原文引用（5 句英 + 中译）

按精读规范，先给「整篇的 5 句骨架」，后面每一节再各引 1 句落到机制。所有英文原句逐字，不删改。

Q1 · 问题定义

原文： "Prior approaches face a fundamental tradeoff: VLM backbones are general, but not fast, and robot visuomotor policies are fast but not general."（System 1, System 2 段）

中译：先前的方法面临一个根本性权衡：VLM 骨干通用，但不快；机器人 visuomotor 策略快，但不通用。

Q2 · 慢系统的定义

原文： "System 2 (S2): An onboard internet-pretrained VLM operating at 7-9 Hz for scene understanding and language comprehension, enabling broad generalization across objects and contexts."（System 1, System 2 段）

中译：System 2（S2）：一个机载、经互联网预训练的 VLM，以 7–9 Hz 运行，负责场景理解与语言理解，从而在物体与场景上获得广泛泛化。

Q3 · 接口（全篇最关键的一句）

原文： "S2 distills all semantic task-relevant information into a single continuous latent vector, passed to S1 to condition its low-level actions."（Architecture 段）

中译：S2 把所有与任务相关的语义信息蒸馏成单个连续 latent 向量，交给 S1 作为其低层动作的条件。

Q4 · 动作空间里的「自终止」

原文： "We append to the action space a synthetic "percentage task completion" action, allowing Helix to predict its own termination condition, which makes it easier to sequence multiple learned behaviors."（Architecture 段）

中译：我们在动作空间里追加了一个合成的「任务完成百分比」动作，让 Helix 自己预测终止条件，从而使多个已学行为的串接更容易。

Q5 · 部署与训练的镜像关系

原文： "This deployment strategy deliberately mirrors the temporal offset introduced in training, minimizing the train-inference distribution gap."（Optimized Streaming Inference 段）

中译：这套部署策略刻意镜像了训练时引入的时间偏移，从而最小化训练-推理之间的分布差。

这 5 句正好构成一条链：权衡 → 慢系统职责 → 唯一接口 → 终止条件 → 训练/部署对齐。全文其余细节都是这条链的实现注脚。

3. Problem：为什么「再快一点」不是解法

原文： "The current state of robotics will not scale to the home without a step change."（New Scaling for Humanoid Robotics 段）

中译：没有一次台阶式的跃变，当前机器人技术水平无法扩展到家庭场景。

原文： "Teaching robots even a single new behavior currently requires substantial human effort: either hours of PhD-level expert manual programming or thousands of demonstrations. Both are prohibitively expensive when we consider how vast the problem of the home truly is."（同段）

中译：今天教机器人一个新行为都需要大量人力：要么是数小时的博士级专家手工编程，要么是上千条示教。考虑到家庭问题本身的规模之大，这两条路都贵到不可接受。

原文： "The home presents robotics' greatest challenge. Unlike controlled industrial settings, homes are filled with countless objects–delicate glassware, crumpled clothing, scattered toys–each with unpredictable shapes, sizes, colors, and textures."（同段）

中译：家庭是机器人最大的挑战。与受控的工业环境不同，家里充满无数物体——易碎的玻璃器皿、揉皱的衣物、散落的玩具——它们的形状、尺寸、颜色、材质都不可预测。

把问题写成成本函数

成本 = 每技能成本 × 技能数 ≈ (专家编程 数小时 + 示教 10³ 条) × N_行为

一行物理意义：传统路线里「技能」是离散资产，每加一个行为就要重付一次固定成本；而家场景的长尾意味着 N_行为 趋向无穷，所以线性成本必然爆掉——瓶颈不在单点精度，而在边际成本。

这正是博客 Figure 1（scaling curves）想表达的：heuristic manipulation 的技能数随「博士数」增长，imitation learning 的技能数随「采集数据量」增长，而 Helix 想让技能数随「语言指令」增长。区别是：前两者要为新技能重新采集/编程，后者只要「说出来」。

注意：博客没有给 Figure 1 的坐标数值，只有定性曲线；本页不编造曲线上的数。

4. Core idea：按「时间尺度」切两半，再用一个向量焊起来

原文： "Helix resolves this tradeoff through two complementary systems, trained end-to-end to communicate:"（System 1, System 2 段）

中译：Helix 通过两个互补的、端到端训练以互相通信的系统来解决这个权衡。

原文： "System 1 (S1): A fast reactive visuomotor policy that translates the latent semantic representations produced by S2 into precise continuous robot actions at 200 Hz."（同段）

中译：System 1（S1）：一个快速反应式的 visuomotor 策略，把 S2 产生的 latent 语义表示翻译成 200 Hz 的精确连续机器人动作。

原文： "This decoupled architecture allows each system to operate at its optimal timescale. S2 can "think slow" about high-level goals, while S1 can "think fast" to execute and adjust actions in real-time."（同段）

中译：这种解耦架构让每个系统在自己最优的时间尺度上运行。S2 可以「慢想」高层目标，S1 则「快想」以实时执行和调整动作。

频率不是玄学，是算出来的

环节频率单步预算这一档频率能做什么 / 不能做什么
S2（7B VLM）7–9Hz111–143 ms能跑一次 7B 级前向 + 语义推理；不能做闭环纠偏（143ms 内物体已移动）
S1（80M visuomotor）200Hz5 ms能做接触、抓取滑移、协作避让的实时纠偏；不能承担开放语义推理
比值200 / 9 ≈ 22.2，200 / 7 ≈ 28.6S1 每跑 22–29 步，S2 才更新一次意图（推算，由两个公开频率直接相除）

为什么这个切分是「自然」的：参数量的差（7B vs 80M = 87.5 倍）与频率的差（200/8 ≈ 25 倍）同量级——单步算力预算 ≈ 参数量 × 频率，二者相乘近似守恒。也就是说，Helix 不是随便选了 80M，而是先用 5 ms 的硬预算反推出 S1 只能是小模型，再把语义能力全部推给 7B。这条推理链是本页对博客的解读，博客只给了两个数字，没有给这个推导。

代价（博客自己点出的，也是它相对 π0 的取舍）：为了不引入 action tokenization，S1 直接输出连续控制；而 π0 走的是「动作块 + flow matching 去噪」，单次推理要 10 步网络前向（π0 论文 Table I：10 步 flow 共 27 ms）。两条路线在「如何把 VLM 语义变成高频动作」上分叉：Helix 换小模型换频率，π0 换并行去噪换精度。详见 π0 / π0.5 页。

5. 架构细节：S2 / latent / S1 / 动作空间

5.1 S2：7B 开源开放权重 VLM，只做一件事——吐一个向量

原文： "S2 is built on a 7B-parameter open-source, open-weight VLM pretrained on internet-scale data. It processes monocular robot images and robot state information (consisting of wrist pose and finger positions) after projecting them into vision-language embedding space."（Architecture 段）

中译：S2 构建在一个 7B 参数、开源、开放权重的 VLM 之上，该 VLM 在互联网规模数据上预训练。它处理单目机器人图像与机器人状态信息（由腕部位姿与手指位置构成），先把它们投影进视觉-语言嵌入空间。

读法：注意两个「小」设计——① 输入是单目，不是多相机堆叠；② 状态只取腕位姿 + 手指，不喂全身关节。这两点都是为了把 S2 的输入对齐到 VLM 原生模态（一张图 + 一段文本），从而不需要为机器人新增视觉编码器。代价是 S2 看不到躯干与底座状态——它只负责「看到什么、该做什么」，不负责「身体在哪」。

5.2 latent：一个向量，不是 token 序列

原文： "Combined with natural language commands specifying desired behaviors, S2 distills all semantic task-relevant information into a single continuous latent vector, passed to S1 to condition its low-level actions."（同段）

中译：结合描述目标行为的自然语言指令，S2 把所有与任务相关的语义信息蒸馏成单个连续 latent 向量，交给 S1 作为低层动作的条件。

为什么是「一个」而不是「一串」：接口带宽等于跨系统每次通信的固定开销。若传 L 个 token，S1 的交叉注意力序列长度为 N_v + L，且 S2 侧还要维护 L 个输出槽；传 1 个向量则 S1 只需 proj(z) 拼接一次。博客没给 d，但从「单向量」这个措辞可以确定：语义压缩比 = 7B 内部表示 → d 维，d 必然远小于 S2 隐藏维，这就是本方法的信息瓶颈，也是它唯一可能的失效点（见 Q&A 3）。

5.3 S1：80M 交叉注意力 encoder-decoder，视觉骨干在仿真里预训练

原文： "S1, an 80M parameter cross-attention encoder-decoder transformer, handles low-level control. It relies on a fully convolutional, multi-scale vision backbone for visual processing, initialized from pretraining done entirely in simulation."（同段）

中译：S1 是一个 80M 参数的交叉注意力 encoder-decoder transformer，负责低层控制。它依赖一个全卷积、多尺度的视觉骨干做视觉处理，该骨干的初始化来自完全在仿真中完成的预训练。

原文： "While S1 receives the same image and state inputs as S2, it processes them at a higher frequency to enable more responsive closed-loop control. The latent vector from S2 is projected into S1's token space and concatenated with visual features from S1's vision backbone along the sequence dimension, providing task conditioning."（同段）

中译：S1 接收与 S2 相同的图像与状态输入，但以更高频率处理它们，以获得更灵敏的闭环控制。来自 S2 的 latent 向量被投影进 S1 的 token 空间，并沿序列维与 S1 视觉骨干的视觉特征拼接，从而提供任务条件。

三个可复现的设计要点：① 全卷积骨干 → 输出是多尺度特征图，不是固定 patch 序列，分辨率改变时不必重训位置编码；② 仿真预训练 → S1 的视觉先验与语言无关，纯粹学「像素 → 可操作几何」；③ 沿序列维拼接 → z 不是加性调制（不像 FiLM/AdaLN），而是作为额外 token 参与注意力，因此 S1 可以「选择性读取」意图的某几维。

5.4 动作空间：35-DoF + 1 维完成度

原文： "S1 outputs full upper body humanoid control at 200hz, including desired wrist poses, finger flexion and abduction control, and torso and head orientation targets."（同段）

中译：S1 以 200 Hz 输出完整的类人上半身控制，包括期望的腕部位姿、手指屈曲与外展控制，以及躯干与头部朝向目标。

原文： "Head and torso control pose unique challenges—as they move, they change both what the robot can reach and what it can see, creating feedback loops that have historically caused instability."（Results 段）

中译：头部与躯干控制带来独特挑战——它们一动，既改变机器人能够到的范围，也改变它能看见的东西，形成历史上导致不稳定的反馈回路。

块内容为什么难
腕部（双臂）期望位姿与手指耦合：位姿错 1cm，抓取点就偏
手指屈曲 + 外展高维且冗余，多解；需要接触反馈才能选对解
躯干 / 头朝向目标改变可达域与视野 → 与视觉输入构成闭环，容易自激振荡
+1 完成度[0,1] 标量自终止：把「什么时候停」也学成动作，从而能串接多行为

为什么把「完成度」塞进动作空间而不是单独分类头：分类头是离散决策，需要额外标注「成功/失败」；而完成度是连续回归量，可以复用同一条动作回归损失、同一个 S1 前向、同一个 200Hz 节拍，不需要额外的推理路径（博客原文用词 “append to the action space”）。这也解释了它为什么能「串接多个已学行为」：完成度是时序上的分段信号。

6. 训练：500 小时 + hindsight 标注 + 时间偏移

原文： "We collect a high quality, multi-robot, multi-operator dataset of diverse teleoperated behaviors, ~500 hours in total."（Data 段）

中译：我们采集了一个高质量、多机器人、多操作员的多样化遥操作行为数据集，总计约 500 小时。

原文： "To generate natural language-conditioned training pairs, we use an auto-labeling VLM to generate hindsight instructions. The VLM processes segmented video clips from the onboard robot cameras, prompted with: "What instruction would you have given the robot to get the action seen in this video?""（同段）

中译：为了生成以自然语言为条件的训练对，我们用一个自动标注 VLM 生成事后（hindsight）指令。该 VLM 处理来自机载相机的分段视频片段，提示词为：「如果想让机器人做出视频里看到的动作，你会给什么指令？」

原文： "All items handled during training are excluded from evaluations to prevent contamination."（同段）

中译：训练中接触过的所有物品都被排除在评估之外，以防止数据污染。

6.1 为什么是 hindsight（事后）标注

遥操作采集时，操作员手上做动作、嘴上不一定同步说出精确指令；如果事后人工补标，500 小时的标注成本与采集同量级。hindsight 做法把「指令」变成对已发生视频的逆问题：给定结果反推指令。代价是标注质量受标注 VLM 上限约束（该 VLM 型号未公开），且会引入 VLM 的系统性偏差——比如更倾向输出「把 X 放进 Y」这种模板化句式。博客没有讨论这个偏差，这是本页标出的一个隐含风险。

6.2 单阶段端到端，梯度穿过 latent 回传到 7B

原文： "Helix is trained fully end-to-end, mapping from raw pixels and text commands to continuous actions with a standard regression loss. Gradients are backpropagated from S1 into S2 via the latent communication vector used to condition S1's behavior, allowing joint optimization of both components."（Training 段）

中译：Helix 完全端到端训练，用标准回归损失把原始像素与文本命令映射到连续动作。梯度经由那个用于条件化 S1 行为的 latent 通信向量，从 S1 回传到 S2，从而联合优化两个组件。

原文： "Helix requires no task-specific adaptation; it maintains a single training stage and single set of neural network weights without separate action heads or per-task fine-tuning stages."（同段）

中译：Helix 不需要任何任务特定适配；它只保留单一训练阶段与单一套网络权重，没有单独的动作头，也没有按任务的微调阶段。

关键工程含义：「梯度经一个 d 维向量回传」意味着 S2 的唯一学习信号是「你给的意图是否让 S1 的动作更像示教」。这带来两个后果——① S2 不需要任何 VQA/指令标注的辅助损失（博客明确没提辅助损失）；② 如果 d 太小，S2 收到的梯度被压缩，7B 的大部分容量学不到东西（本页推断，博客未讨论）。这与 π0.5 的做法形成对照：π0.5 显式给子任务做文本交叉熵监督，Helix 完全隐式。

6.3 时间偏移：把部署的延迟搬进训练

原文： "During training, we add a temporal offset between S1 and S2 inputs. This offset is calibrated to match the gap between S1 and S2's deployed inference latency, ensuring that the real-time control requirements during deployment are accurately reflected in training."（Training 段）

中译：训练时，我们在 S1 与 S2 的输入之间加入一个时间偏移。该偏移经过标定，以匹配部署时 S1 与 S2 推理延迟之间的差，从而保证部署时的实时控制要求被准确反映到训练中。

一句话物理意义：部署时 S1 手里的 z 一定是「过去」的意图（S2 要 111–143 ms 才算完），如果训练时让 S1 见到「此刻」的 z，它就会学到「意图与画面同步」这个部署时不成立的假设；加入偏移后，训练与部署看到的是同一种「意图落后于画面」的世界。

偏移的具体帧数/毫秒数博客未给。若按 200Hz 控制周期折算，S2 的一次推理跨 22–29 个控制步（推算：0.111–0.143 s × 200 Hz）。这个数字只用于理解量级，不是博客原文。

7. 部署：双 GPU、异步流式推理、一套权重

原文： "Helix's training design enables efficient model parallel deployment on Figure robots, each equipped with dual low-power-consumption embedded GPUs. The inference pipeline splits across S2 (high-level latent planning) and S1 (low-level control) models, each running on dedicated GPUs."（Optimized Streaming Inference 段）

中译：Helix 的训练设计使其能在 Figure 机器人上高效地做模型并行部署，每台机器人配备两块低功耗嵌入式 GPU。推理管线在 S2（高层 latent 规划）与 S1（低层控制）之间切分，各自跑在专用 GPU 上。

原文： "S2 operates as an asynchronous background process, consuming the latest observation (onboard camera and robot state) and natural language commands. It continuously updates a shared memory latent vector that encodes the high-level behavioral intent."（同段）

中译：S2 作为异步后台进程运行，消费最新的观测（机载相机与机器人状态）与自然语言指令。它持续更新一个共享内存中的 latent 向量，该向量编码高层行为意图。

原文： "S1 executes as a separate real-time process, maintaining the critical 200Hz control loop required for smooth whole upper body action. It takes both the latest observation and the most recent S2 latent vector."（同段）

中译：S1 作为独立的实时进程运行，维持平稳上半身动作所需的、关键的 200Hz 控制回路。它同时取用最新观测与最近一次的 S2 latent 向量。

原文： "The asynchronous execution model allows both processes to run at their optimal frequencies, allowing us to run Helix as fast as our fastest single task imitation learning policies."（同段）

中译：这种异步执行模型让两个进程都在各自最优频率上运行，使我们能把 Helix 跑得像我们最快的单任务模仿学习策略一样快。

9. 公式 + 物理意义 + 映射到代码

博客没有任何公式（L1 证据的硬限制）。下面两条是按博客文字描述重写的形式化表达，标注为「改写」，不是原文公式；第三条是纯算术。

式 1 · 单阶段端到端回归（改写，博客：standard regression loss）

L(θ₂, θ₁) = E_{(I, s, ℓ, a) ~ D} ‖ a − π₁( φ(I_t), W·z_t, s_t ) ‖²，其中 z_t = π₂( I_{t−Δ}, s_{t−Δ}, ℓ )

一行物理意义：用动作误差一次性监督「7B 语义 → d 维意图 → 200Hz 动作」整条链路，z 没有标签也没有辅助损失，它唯一的义务是让下游动作更准。

三项符号各自的物理含义：φ(·) 是 S1 的全卷积多尺度视觉骨干（只吃像素，与语言无关）；W 是 d → S1 token 维的线性投影；Δ 是训练时人为加入的时间偏移，模拟部署时 S2 落后于 S1 的那一段。

映射到代码（第 11 节的三行对应）：

式 1 中的量代码行形状
z_tz = s2(img_s2, state, lang)(b, d)
W·z_t 与 φ(I_t) 拼接a = s1(vis, proj(z), state)vis (b, N_v, c)；proj(z) (b, 1, c)
回归误差loss = mse(a, a_gt)a, a_gt (b, 36)

式 2 · 时间偏移（改写，博客：temporal offset）

训练：S1 输入 (I_t, s_t, z_{t−Δ})｜部署：S1 输入 (I_t, s_t, z_{t−τ_deploy})，标定使 Δ ≈ τ_deploy

一行物理意义：让训练时 S1 见到的「意图滞后量」等于部署时真实存在的滞后量，把 train-inference gap 从「分布错配」压成「零」。

博客原话只说「calibrated to match the gap」，没有说偏移方向（S2 看更早的帧，还是 S1 看更晚的 z）。从因果上只能是前者：部署时 z 必然滞后，所以训练也必须让 z 滞后。此处为逻辑推断，已标注。

式 3 · 频率预算（纯算术，由公开两个频率得出）

T_S2 = 1/8 s ≈ 125 ms（区间 111–143 ms）｜T_S1 = 1/200 s = 5 ms｜N_latent ≈ T_S2 / T_S1 = 22 ~ 29

一行物理意义：S1 每 22–29 个控制拍才拿到一次新意图，其余时间必须靠自己的 80M 网络把「旧意图 + 新画面」补成动作——这正是 S1 必须足够快、又必须带视觉的原因。

10.3 结论（本页判断，非原文）

Helix 的实验证据强度是「演示级」而非「基准级」：它证明了这套架构能跑起来、能泛化到数千个新物体、能双机协作，但没有给出可与 π0/OpenVLA 横向比较的成功率。因此正确的引用姿势是：引用其架构决策与工程约束（7–9Hz/200Hz 双频、单 latent、时间偏移、双板载 GPU、单套权重），而不是引用其「效果有多好」。

11.2 训练一步（示意）

# ===== 训练：单阶段、端到端、一个回归损失 =====
# 依据：博客 Training 段 + Architecture 段（非官方源码）
img_s2, state_s2 = history.at(t - delta)      # 时间偏移：S2 看「更旧」的一帧，模拟部署时滞后的意图
z = s2(img_s2, state_s2, lang)                # (b, d) 语义意图：慢、低频，但决定「做什么」；无独立标签

vis = s1_backbone(img_s1)                    # (b, N_v, c) 全卷积多尺度特征：仿真预训练初始化，只学「像素→几何」
tok = concat(proj(z), vis, axis=1)           # (b, 1 + N_v, c) 沿序列维拼：z 作为额外 token，参与注意力而非加性调制
a = s1_head(s1_encoder_decoder(tok, state_s1))  # (b, 36) 200Hz 目标：35 关节/位姿 + 1 完成度

loss = mse(a, a_gt)                          # 标准回归；梯度经 z 回传到 7B S2（博客明确 joint optimization）
loss.backward()                              # S1 与 S2 同时更新；无 per-task 头、无第二阶段

逐行物理意义已写在注释里。注意 delta 只作用于 S2 的输入，不作用于 S1——因为部署时只有 z 会滞后，画面不会。

11.3 部署两个进程（示意）

# ===== 部署：GPU0 跑 S2（后台），GPU1 跑 S1（硬实时） =====
# 依据：博客 Optimized Streaming Inference 段（非官方源码）

def s2_loop():                                # 后台进程，7–9Hz
    while robot.running:
        img, state = camera.latest(), robot.state()
        z_shared.write(s2(img, state, lang))   # 只写一个向量：跨进程通信量 ~d 个 float，不是 token 序列

def s1_loop():                                # 硬实时进程，200Hz
    while robot.running:
        img, state = camera.latest(), robot.state()
        a = s1(vis(img), proj(z_shared.read()), state)   # 读最新意图：可能落后 111–143ms，这正是训练时 delta 模拟的情形
        robot.set_targets(a[:35])              # 35-DoF 目标交给控制器
        if a[35] > done_threshold:            # 完成度：自预测终止（阈值未公开）
            robot.finish_current_skill()
        sleep(0.005)                            # 5ms = 200Hz；这一拍绝不能等 S2

为什么 S1 不能在循环里等 S2：等一次就是 111–143ms ≈ 22–29 个控制周期，PD 环会抖成不可控。异步 + 共享内存是这套架构唯一可行的工程形态。

13. Q&A（追问 why，带数值或反例）

Q1：为什么 S1 只有 80M？把 S1 也做到 7B 会怎样？

反例算术：S1 的预算被 200Hz 钉死为 5ms/次。若 S1 用 7B（= 80M 的 87.5 倍），单次前向至少要 87.5 倍算力；除非同时把控制频率降到 200/87.5 ≈ 2.3Hz，否则物理上跑不动。而 2.3Hz 的控制连「抓滑落的杯子」都做不到（100ms 内物体已下落约 5cm，按自由落体 g=9.8，0.1s 位移 ≈ 4.9cm）。所以 80M 不是保守选择，是 5ms 预算的上界。

另一面：把语义全压给 S2 的代价是 z 必须承载全部意图——这就是 Q3 讨论的瓶颈。

Q2：时间偏移不做会怎样？能省掉吗？

数值：部署时 z 的滞后 = S2 一次推理时间 ≈ 111–143ms = 22–29 个 5ms 控制拍。若训练时 z 与画面严格对齐，S1 会学到「意图总是新鲜的」，于是把 z 当作高置信度的当前目标。反例场景：双机协作递物——伙伴机器人的手在 143ms 内可能移动数厘米，S1 若相信「旧意图对应新手位」，就会提前合拢手指或撞上对方。训练偏移把这段延迟显式编码进策略，让 S1 学会「对旧意图保持一定的保守度」。这不是精度问题，是因果结构问题：不偏移等于训练一个在部署时不存在的时间关系。

Q3：单个 latent 向量会不会丢信息？为什么不用一串 token？

why：接口带宽是跨系统固定成本。传 L 个 token 时 S1 的注意力序列长 N_v + L、S2 要维护 L 个输出槽、跨进程拷贝 L×c 个 float；传 1 个向量则是 d 个 float。若 d = 1024、L = 64、c = 2048，则 L×c = 131,072 vs d = 1,024，差 128 倍（示意量级，d 未公开）。反例：任务需要「先开抽屉、再取物、再关抽屉」的精确时序时，单向量可能只编码了「当前该做什么」，而丢掉了剩余步骤——这正是 π0.5 要用显式子任务文本（可自回归、可多步）的理由。两条路线的取舍点因此很清楚：Helix 用带宽换实时性，π0.5 用 token 换长程结构。

Q4：把「完成度」放进动作空间，为什么比单独训一个成功检测器好？

why：① 零额外标注：完成度是连续回归量，可以直接由示教片段的进度折算，不需要人工标「成功/失败」二元标签；② 零额外推理：它和 35 维动作共享同一个 S1 前向与同一个 200Hz 节拍，不引入第二条推理路径（若单独训检测器，200Hz 下每拍多一次前向，预算直接翻倍）；③ 可串接：完成度是时序信号，天然支持「做完 A 再做 B」的分段。反例：外挂检测器在分布外物品上会把「正在靠近」误判成「已完成」，而完成度是随动作一起被回归监督的，误差与动作误差同源、同步收敛。
