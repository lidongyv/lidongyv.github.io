1.3 快速上线 · 地图前融合 切换梯度流

  • 纯视觉 head freeze；新增 map encoder 处理 maps3d → map query group。
  • 纯视觉 query detach 梯度，通过 SA 取 map 信息 → fusion query result。
  • 输出结构与纯视觉完全一致，不影响纯视觉 head。
  • MapRouter 透传 LD-HD maps3d 结构体作为输入。
可预测：前融合是能力上限，无图不可能在小范围质量上超地图，以此 base 预测大盘多阶段提升。

1.4 模型后续两个大 feat：sparse · 时序 已在 OD 走通 · 等待上线

① sparse — 替换 BEV
  • 替换 BEV，删除 pv2bev，使用 pv-ca 实现迭代
  • 对 backbone 强依赖 → 需放开 backbone 训练
  • 与 OCC 的 feat 统一性更强
  • 梯度争抢都回到 backbone → 有利于多任务调参
价值：解决检测距离问题 + 减少耗时
② 时序 — query fusion
  • 使用 query fusion，保持单帧 det 性能不变
  • stream 两帧融合，保持帧间稳定性
  • lane + path 不需带预测
  • 时序只起平滑 / 稳定性，不需多帧及预测模块
价值：帧间稳定，处理路口 / m2n 线跳变

准出逻辑 · MIL / SIL

可验证可预测

门禁流水线：场景集 → MIL（benchmark + issue 集）→ SIL（静态 + 交互）→ 发版。MIL/SIL 共用一套 checker。

2.1 场景集 Matrix 点格看口径

白天傍晚黑夜下雨中/后下雪中/后
每格 = 一个细分场景，点击查看数据口径。

2.2 MIL 需求

① benchmark（每场景 >30km）

ref path+ego_lane mean/max distlane counttrack frame · temporal distboundary type路口可达率
指标跟踪：无大面积波动 + hard case 里程增加 → 发版，波动 < 3%。

② issue 集（shadow mode >500 issue）

lc/split/junction/弯道-小路 各 ~500 clip；指标：lc 成功率、split 三方向、路口四方向、居中里程。

门禁：不允许成功率回退；解释单类跷跷板；不允许多类指标跷跷板。

③ Hard case mining

用 MIL 做 hard case mining：strict IoU 下 recall/precision 门槛——前融合带 aug 点数 >85%、不带 aug >92%。纯视觉方案同样需 MIL 支持 hard case mining。

2.3 SIL 需求

全链路 model-infer→mapengine→loc→maprouter→planning→control，判断可达 + 是否撞车。

静态集（新增·需 hack SIL）：剔除所有 OD+OCC，只跑纯道路结构，判 ref path 可达，checker 同 MIL。
交互集：全链路正常 SIL，考虑效率变道 / 变道失败 / nudge 下的 ref path。
准出门禁：与 MIL issue 一致，不允许成功率回退，解释单类跷跷板，不允许多类跷跷板。

判定结果

    核心 topic /perception/static_3d/ref_lanes + /maprouter/operation_area_on_path；状态机：Open → SIL_Testing → Pass/Fail → Closed → WhiteListed。

    3.3 运作模式（特别说明，按优先级）

    • ① shadow mode 是发动机：底图前 issue 大头来自 shadow mode（小头 issue 刷黑）；底图后仍依赖 shadow mode——shadow mode + 数据闭环是无图持续迭代的唯一保证，重于 issue 治理。
    • ② 连续长距离刷白：短距离易致状态机不稳 / PNC 猛打方向盘；连续 ≥700m 的 link 刷白才可升无图，否则等待。
    • ③ 离线 SIL 投影校验：刷黑刷白均离线 SIL 跑，依赖视觉投影；全黑 cam 作 failsafe，第一期黑夜小路不保证刷白质量。
    • ④ 自动产线：刷黑后自动转 4D GT，D+2 内回流参与 One Model 训练。
    • ⑤ 大盘管理：平台支持查看 black/white link 数量、采集计划、刷黑刷白计划。

    核心需求（量 + 时间）

    可验证可迭代

    无图落地的核心需求，按 MIL · SIL · 地图 · 数据 · 路测 · QA · 刷白 排出各项的「量」与「时间」。

    🎯 MIL

    量：issue 集 lc / split / junction / 弯道-小路 各 ~500 clip（shadow 黑名单 >500 issue）；benchmark 每场景 >30km
    时间：0605–0630，分三期 10% → 30% → 60%

    🧪 SIL

    量：静态集（剔 OD+OCC 纯道路结构）+ 交互集（全链路）两套
    时间：随评测体系 0605–0630；静态集为新增

    🗺 地图

    量：LD lite 导航/map info + LD-HD maps3d 透传 + 超视距路信；高优刷白 local black
    时间：前融合 0610 上线前就绪；多图元切换/高优刷白本月不做

    💾 数据

    量：训练每场景 >100w 帧 1Hz；采集完整路线 >1500km / 80 条高热；shadow 回传 >500km/天
    时间：80 条高热 0604；shadow T+2 进 One Model；纯视觉迭代 0626

    🚗 路测

    量：issue 刷黑（小头）；完整运营路线 500km → 1000km 连续采集
    时间：500km 0610 / 1000km 0617

    👥 QA

    量：刷黑刷白标注 ~30–32 issue/人天（需扩量，杠杆线性提速）；待清 0602 黑名单 68.2% 未采集 / MPI 6008 未 triage
    时间：0527 已上 5 人，0605 起扩量

    ⚪ 刷白

    量：连续 link ≥700m；里程 500km → 1000km → 持续；黑白名单大盘平台
    时间：0610 / 0617 / 0617–0630
