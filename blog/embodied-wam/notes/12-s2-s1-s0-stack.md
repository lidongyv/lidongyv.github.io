# 从 S2 到 S0 的实操实现：当前最常用的一条分层链路

> 2026-11 工程共识：**分层异步 + 潜动作接口**。S2 慢想（1–5Hz）→ 接口（语言子任务 / 64 维潜动作 token / 关键点位姿）→ S1 快控（50–200Hz）→ S0 物理层（≥1kHz PD/阻抗 + 机械顺应 + 安全）。
> 依据：GR00T N1.5/N1.7 + SONIC（NVIDIA 官方文档）、Helix（Figure 博客）、GR00T 2（WAM + agent S2）、Taniguchi 2503.06138（S0 定义）。

---

## 0. 一条链路（默认答案）

```
┌────────────── S2 慢想（1–5Hz，GPU）──────────────┐
│ VLM/VLA：看画面 + 读指令 → 子任务 / 目标 / 潜动作 │
└───────────────┬──────────────────────────────────┘
                │ 接口（三选一）
    ① 语言子任务（π0.5 式）
    ② 64 维 SONIC 潜动作 token ×40（2.5Hz）
    ③ 关键点位姿 + 导航指令（3 点 VR 格式）
                ▼
┌────────────── S1 快控（50–200Hz，机载）──────────┐
│ 全身策略：token/参考运动 + 本体感知 → 关节目标     │
└───────────────┬──────────────────────────────────┘
                │ 关节位置/速度目标
                ▼
┌────────────── S0 物理层（≥1kHz，驱动器内）────────┐
│ PD/阻抗控制 + 力矩限幅 + 机械顺应 + 安全停机       │
└───────────────────────────────────────────────────┘
```

**为什么接口选潜动作 token**：跨本体、可缓存、可加 residual、S2 不必懂关节；这也是 SONIC/GR00T 2 的做法。

---

## 1. 各层规格

| 层 | 频率 | 输入 | 输出 | 典型实现 | 训练方式 |
|---|---|---|---|---|---|
| **S2** | 1–5Hz | RGB（可多相机）+ 语言 + 本体状态 | 子任务文本 / 目标图 / `[40,64]` token / 位姿+导航 | Qwen2.5-VL、Eagle-2、GR00T N1.5/N1.7、Gemini Robotics（云） | 示教微调（LeRobot 数据 50–100 条/任务，20k steps，4 GPU） |
| **接口** | 2.5–10Hz | S2 输出 | S1 条件 | 语言 / token 缓存 / 规划器参考运动 | 无（对齐/缓存） |
| **S1** | 50–200Hz | 观测 + token/参考 + proprio | 关节目标（位置） | SONIC（42M，PPO，50Hz）、Helix S1（80M，200Hz）、GR00T S1 DiT（120Hz） | 仿真 RL（IsaacLab，4096 envs，域随机化）+ sim2real；或 IL |
| **S0** | ≥1kHz | 关节目标 | 力矩/电流 | 关节 PD（Kp/Kd 按电机调）、阻抗、限幅、IMU 安全 | 系统辨识 + 调参；**不学习** |

## 2. 以「G1 + SONIC + GR00T N1.7」为例的具体实现

1. **S2**：微调 GR00T N1.7（`--embodiment-tag UNITREE_G1_SONIC`），输入 ego 相机 + 语言，输出两种之一：
   - 3 点格式：头/双腕 SE(3) + 腰高 + 导航指令（线/角速度）；
   - 64 维 SONIC token ×40 步（2.5Hz）。
2. **接口**：
   - 3 点格式 → 运动规划器（自回归，0.8–2.4s 段，100ms 重规划，<5ms/12ms）→ 参考运动；
   - token → 直接进 SONIC 解码器；可用 latent residual 注入下游修正。
3. **S1**：SONIC 50Hz 输出全身关节目标（78 维动作空间 = 64 token + 7+7 手部）。
4. **S0**：G1 关节 PD（部署含 per-motor Kp/Kd scaling 减少绊倒）+ 力矩/限位/IMU 安全。

**替代方案**：Helix 式端到端双系统（S2 7B VLM 7–9Hz → S1 80M 200Hz，latent 向量接口，训练加时间偏移镜像部署延迟）。

## 3. 多速率代码骨架

```python
# 进程 A：S2（GPU，2.5Hz）
while True:
    obs = cameras.latest()
    tok40 = vla.infer(obs, prompt)            # [40, 64]
    token_buf.push(tok40, ts=now())

# 进程 B：接口/规划（10Hz）
if mode == "token":
    ref = token_buf.consume_fresh()           # 按时间戳取最新，不追旧
else:
    ref = planner.step(cmd)                   # 0.8–2.4s 参考段

# 进程 C：S1（50Hz）
q_target = sonic.decode(ref, proprio)         # [n_joints]

# 进程 D：S0（1kHz，驱动器）
tau = Kp * (q_target - q) - Kd * qd
tau = clamp(tau, tau_min, tau_max)
```

**延迟对齐**：S2 的 token 带时间戳，S1 只用「最近一个未过期」token；S1 输出队列带时间戳，S0 按当前时刻插值——不要追已过期的目标。

## 4. 训练流水线（自下而上）

1. **S0 先行**：系统辨识（质量/惯量/摩擦）、PD/阻抗调参、限位与安全、机械顺应（足底橡胶、关节柔顺）。
2. **S1**：仿真 RL（跟踪奖励 + 域随机化）→ sim2real；或端到端 IL。
3. **S2**：VLM/VLA 微调（50–100 条/任务；LeRobot v2.1；4 GPU、20k steps、bs 32）。
4. **接口对齐**：S2 输出与 S1 输入严格同构；训练时注入部署延迟（Helix 的时间偏移）。
5. **联调**：先 S1+S0 单独稳（空载/负载），再接 S2；S2 超时→保持/停止。

---

## 5. 常见坑

- **频率错配**：S2 出 token 太慢导致 S1 用旧 token（表现：动作滞后/抖动）→ 加超时与「保持动作」。
- **接口语义漂移**：S2 训练用 3 点格式、部署改 token → 必然掉点；接口版本要锁。
- **S0 被忽略**：PD 增益/限幅没调好，S1 再强也抖；SONIC 的 per-motor Kp/Kd scaling 就是证据。
- **安全层缺失**：S0 必须有独立于 S1 的力矩/速度/姿态停机。
- **延迟未建模**：训练不含推理延迟 → 部署振荡（Helix 用时间偏移解决）。

---

## 6. 与 WAM 的关系

WAM 通常放在 **S2**（慢想象/规划）或作为 **S1.5**（潜动作预测）：它的输出最好落在**潜动作空间**（如 SONIC 的 64 维 token），这样 S1 不需要改、S2 的想象可直接被执行。GR00T 2 正是这个结构：WAM 本体 + agent 做 S2 + SONIC 做 S1。
