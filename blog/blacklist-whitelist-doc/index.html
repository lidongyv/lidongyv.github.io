1.1 为什么需要黑白名单

  • 自动驾驶系统的能力 ≠ 全域能力，存在"会的路段" vs "不会的路段"
  • 黑白名单是 link 级别 的能力声明 — 一条 link 在某个模块（LD / HD / TLD / OCC / Local）上是否可信
  • 黑白名单驱动两件事：
    1. 运行时：路径规划层面是否允许走这条 link、是否切到 HD、是否依赖 OCC
    2. 数据闭环：高热 black link 优先采集 → 优先 triage → 优先刷白

1.2 五条黑白名单通道

2. 刷黑机制 (Blacklist Generation)

"刷黑"是把一条 link 在某个通道上标记为不可信。不同模块的问题产生不同通道的 black、刷黑的粒度也不同。

2.3 各场景刷黑细则

1.1   LD→HD black（地图几何偏移）
  • 仿真模板见 Map 手册（LD黑名单刷HD白Triage指南）
  • 先看 goline 是否完整；再看是否压线 / 压路沿
  • 若 LD 偏差大且 HD 也偏差 / 无 HD / HD goline 中断 → 视为 HD 不可解，整个 issue 刷黑，所有涉及 link id 进入 LD/HD black 仓库
⚠️典型不可解：①HD 投影同样偏差大；②此处无 HD 显示；③HD goline 中断（导航到辅路而辅路无 HD）；④HD 投影正常但无 goline。
1.2   TLD black — 地图拓扑 / 挂接错误
  • 拓扑挂接错误导致车道未关联到正确的红绿灯
  • 影响范围更大：issue 所在路口的 entry link + inner link 全部刷黑
  • 路口结构相关 link 一并影响，粒度更粗，目的是覆盖整片路口
1.3   TLD black — 识别 / 后处理问题
  • 红灯期间 tld.status 错给了 1（放行）→ 闯红灯接管
  • 或停止点异常（停止点位置与实际停止线偏差大）
  • 同样 路口 entry + inner link 全部刷黑
🚫仿真复测窗口：距停止线 15m 内 / 过停止线 5m 内，tld.status 必须稳定为 0，抖动到 1 也算不通过。
1.4   OCC black — 识别 / 后处理问题
  • 车端原始结果在自车前方 25~30 米 范围内未及时检出红色占据栅格
  • OCC 漏检 或 检出晚 都会导致接管 → 该 issue 涉及 link 全部刷黑，整个 issue 刷黑
  • 核心视图：occ_fusion_status（红 = 占据，蓝 = OD 动目标）
1.5   Local black — Lane Model 识别 / 后处理问题（无图模式）
  • 自车经过该 link 的过程中，ref path 投影出现偏差 / 回折 / 断连
  • 路口不可过：参考线无法穿过路口、或与路沿/栅栏相交
  • 该 link 刷黑，整个 issue 刷黑
📌判定字段：/maprouter/operation_area_on_path.operation_areas[0].link_id 配合 /perception/static_3d/ref_lanes。

3. 刷白机制 (Whitelist Promotion)

"刷白"是当新版本（HD 更新或模型更新）已修复某 black link 时，按对应手册做 SIL 仿真复测，通过则把 link 从 black 状态升级为 white。

3.1 五种刷白场景与对应手册

2.1地图几何修复 + HD 更新HD goline 完整 + centerline 居中Map 手册Issue link id 刷白；整个 issue 刷白
2.2地图 topo / 挂接修复 + HD 更新ego_line.tld.status 红灯期间稳定为 0TLD 手册TLD black 刷白；路口 entry + inner 刷白
2.3TLD 模型 / 后处理更新ego_line.tld.status 红灯期间稳定为 0TLD 手册TLD black 刷白；路口 entry + inner 刷白
2.4OCC 模型 / 后处理更新occ_fusion_status 25~30m 内检出红色占据OCC 手册OCC black 刷白；整个 issue 刷白

LD 黑名单刷 HD 白 Triage 指南

模板及可视化设置

  • 看 /sim/neo_map_router/router_output 的停止点信息

LANE 子分支

  • 先看 HD goline 是否完整
  • 再看 goline 是否压线 / 压路沿
✅通过：飞书任务状态改 CLOSED；"刷白结论 / HD刷白状态" 改 可刷白；填 jobid + 仿真任务链接。
🚫不通过：状态不变；填 jobid + 链接；"HD刷白状态" 改 不可刷白。

典型不可解（仿真也救不了）

  • 此处无 HD 显示 → 无 HD 可切

  • HD 投影正常但无 goline

TLD 刷白 Triage 指南

📎 原始手册   ·   docx: QHQAdOYyqobzHaxcDeNcilXAn7p

⚠️只处理 TLD "闯红灯" 接管类型的 issue。

核心字段

在 webviz 看 ego_line.tld.status：

红灯期间 = 0
已拦停 → 🟢 刷白通过（新版本正确拦下来了）
红灯期间 = 1
还会闯红灯 → 🔴 刷白失败

判定窗口

距停止线 15 米内，或过停止线 不超 5 米；窗口内 tld.status 必须 稳定 为 0，中间不能抖动到 1。

背景

原 issue = 闯红灯接管 = 原版本 tld.status 在红灯期间错给了 1（放行）。所以新版本只要这个字段稳定为 0，问题就修复了。

判定流程

  1. 评论里填：仿真 jobid + 仿真任务链接 + 测试结论
  2. 飞书任务状态改 CLOSED
  3. "刷白结论 / TLD刷白状态" 改 可刷白

正反向案例

  • 正向：0ba21c2a-50d2-49bd-8612-00b676d57013 — 原 status=1 → 新模型 status=0，判通过
  • 反向：fb28e280-83f4-4725-950f-dc8a7a5e2d7d — 模型输出正确但停止点异常导致 status 仍 = 1，判不通过

📎 原始手册   ·   docx: VLbNdqJBSoECLExwpw8cd19nnjf

⚠️只处理 OCC 漏检 和 检出晚 两类 issue。

拓路数据 Local 黑白名单 Triage 指南

📎 原始手册   ·   docx: Pg3JdjPzCodhPIxDUxsckFZNnuc

定位自车在哪条 link

  • topic: /maprouter/operation_area_on_path
  • operation_areas[0] = 自车所处的 link
  • .link_id = 当前 link id（即刷白刷黑对象）
  • .begin_distance = 自车系下 link 起点到自车的距离
  • .end_distance = 自车系下 link 终点到自车的距离

核心可视化 topic

/perception/static_3d/ref_lanes（感知静态参考线，"3d"是可视化平台加的）

三种场景判据

直道场景

  • ref path 与道路中心线贴合，误差 ≤ 1/4 车道宽
  • 没有回折线，未断连
  • 必须看自车在 整段 link 上的视频

路口前停止线场景

  • ref path 居中
  • 停止点已生成且偏差不大
  • 停止点在停止线后 ≤1m、前 ≤3m

路口场景

  • ref path 必须能通过路口
  • 不与路沿 / 栅栏相交
  • 无折线、未断连

完整经过 link

begin_distance / end_distance 在 5m 误差 内算"完整经过"。

正反例

  • 正例：link 16367577190 自车完整经过 + ref path 居中 → 刷白
  • 反例（直道）：数据起始 begin_distance = -75m，无法完整经过 link 16367605620 → 刷黑
  • 反例（路口）：绿色 ref path 与护栏相交 → link 15612901941 刷黑
📝记录方式：平台 ready 前手动记录 Job ID − issue − 黑名单 link − 白名单 link 关系。

4. 数据握手与管理

4.1 统一管理 Black / White Link

  • 统一仓库：5 个通道的 black/white link 全部沉淀到统一表 — (link_id, channel, status, issue_id, jobid, timestamp)
  • 聚类口径：按 black link 的 点位数量（occurrences）聚类，而不是按 issue 数量
    • 一个高频 link 可能对应多个 issue → 必须看点位数才能反映真实热度
  • 高热点位高优刷白：按点位 Top-N 排序，driving release / 模型迭代时优先修复

4.3 大盘口径

指标口径关注什么
Black link 总数link 维度，按通道分真实能力盲区面积
刷白进度(白名单 link 数 / 总 link 数) × 100%数据迭代速度
刷黑进度(新增 black link / 周)是否回退 / 新场景暴露
高热点位 Top-N按 link 点位数排序高优修复目标
不看 issue 数—issue 是事件，link 才是能力单元

4.4 发版数据集（水位数据集）

  • 录制完整路线：每次发版前录制完整路线数据，作为 水位数据集
  • 作用：
    1. 回归基准：确认 release 版本在水位数据集上 没有回退
    2. 能力背书：水位数据集 = 当前版本承诺可走的全部 link
    3. 触发条件：刷白后 link 进入水位数据集，下一版本继续验证
🏁发版水位 = 当前能力的"承诺地图"，每次发版前用它做回归，只增不减。
