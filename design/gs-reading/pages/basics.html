3DGS 工作原理：输入、学习、新视角合成与渲染

3D Gaussian Splatting（Kerbl et al., SIGGRAPH 2023）。按 Marr 三层组织：L1 讲它算什么，L2 讲表征与算法（输入/学习在这层），L3 讲渲染管线（图片怎么出来）。

目录： L1 计算理论 L2 表征与算法 “没有神经网络”是什么意思 单场景优化与泛化 L3 渲染管线 颜色怎么出来：球谐系数

L1：计算理论——它要解决什么问题

  • 任务：输入一组已标定相机位姿的照片，重建一个 3D 场景表征，使得对任何没见过的新相机位姿，都能渲染出照片级逼真的图像。
  • 天然约束：所有输入图像是同一个 3D 场景的不同投影，因此场景必须同时解释所有视角（几何一致性）；不可见区域没有信息，所以模型的失败只体现在“训练视角之外的区域模糊/出错”。
  • 正确性判据：渲染图与真值图逐像素 L1 误差 + 感知相似度（D-SSIM）。本质是在学习一个显式的、可微的场景表示（类辐射场/光场的采样版本）。

L2：表征与算法——输入是什么、学的是什么

输入（两样，没有网络前向推理）：

  1. 几十到几百张照片 + 每张的相机内外参（位姿通常先用 COLMAP 做 SfM 求出来）；
  2. SfM 产生的稀疏点云（几万~几十万点），用来初始化高斯的位置。

表征：场景 ≈ 一大组 3D 高斯椭球 {Gi}，每个高斯携带的参数：

参数含义
均值 μ3D 位置（椭球中心）
协方差 Σ = RSSᵀRᵀ缩放 S（3 个尺度）+ 旋转四元数（4 个数）→ 决定椭球的形状与朝向
不透明度 α该椭球的透明度
球谐系数（SH）颜色随观察方向变化，模拟视角相关的反射外观

学的是什么（关键反直觉点）：3DGS 的学习 = 对这上百万个高斯各自参数的梯度下降求解（per-scene optimization），信号来自“渲染图 vs 真值图”的损失：

L = (1 − λ)·L₁ + λ·LD-SSIM

同时做自适应密度控制：在重建不好的区域把高斯分裂（split）或克隆（clone），把低贡献的高斯剪掉（prune）。所以“学习”= 优化高斯集合的布局 + 颜色 + 形状 + 透明度，让所有训练视角的渲染结果都对得上照片。

“没有神经网络”是什么意思（≠ 没有学习）

差在被优化的对象是什么：3DGS 里的“学习”是对一组显式场景参数的梯度下降求解，不是训练一个输入→输出的函数网络。

NeRF3DGS
被优化的东西一个 MLP 的权重（函数逼近器）场景本身：每个高斯的位置、形状、朝向、透明度、SH 颜色系数（显式数据，几百万个浮点数）
渲染时网络的角色查询 MLP：(x, d) → (密度, 颜色)没有查询这一步，高斯参数直接参与光栅化
“模型”是什么网络高斯点集这个数据结构

广义上，用梯度下降解一个逆问题就是学习——bundle adjustment、光度立体重建、相机标定都是“优化参数”，但没人说它们是神经网络。3DGS 属于这一类：

场景未知参数 θ（数百万高斯参数）→ 可微渲染器 R(θ) 生成图像 → 与照片比较得损失 → 梯度反传 → Adam 更新 θ

这里唯一算得上“网络”的东西只有那个可微渲染器，而它是固定管线，没有可学习权重。准确说法：3DGS 没有函数逼近网络，但有一个用梯度下降驱动的 per-scene 逆问题求解过程。

单场景优化与泛化

Vanilla 3DGS 和 NeRF 一样是 per-scene 优化：每个新场景必须从头优化（分钟级），参数无法跨场景迁移。换场景全部重来。

泛化路线（前馈预测 + 可选微调）：在输入图后面接一个网络，让它直接回归每个像素对应的高斯参数，一次训练、多场景可用。代价：前馈预测没有“渲染闭环”逐场景修正，质量通常略低于 per-scene 优化；所以常见混合用法——前馈预测当初始化，再对每个场景微调几十步。详见范式演进页。

L3：实现——如何渲染出图片

渲染 = 一个完全可微的光栅化（splatting）管线，四步：

  1. 视锥剔除：只保留落在当前相机视锥内的 3D 高斯，其余丢弃。
  2. 投影：把每个高斯的均值按针孔相机模型投到像平面；3D 协方差通过局部仿射近似（雅可比矩阵 J）变为屏幕空间的 2D 高斯：Σ′ = JWΣWᵀJᵀ。这一步把 3D 椭球“拍扁”成 2D 光斑（splat）。
  3. 按深度排序：把图像切成 16×16 的 tile，每个 tile 内按深度给高斯排序（近到远）。
  4. Alpha 混合：每个像素沿视线把覆盖它的高斯颜色从前到后混合，最终输出就是一张 RGB 图片：
C = Σᵢ cᵢ · αᵢ · Πj<i(1 − αⱼ)　（αᵢ = 该像素处 2D 高斯值 × 该高斯不透明度）

因为整条管线可微，损失对每个高斯参数的梯度可以一路反传回去，驱动 L2 里的优化。全部用 CUDA 实现，重建后渲染可达 100+ FPS；显式表征还让场景编辑、压缩（如 Compact3DGS）、动态场景（4DGS）变得容易。

颜色怎么出来：球谐系数（SH）

每个高斯存的不是固定 RGB，而是一组球谐系数；渲染时按“当前观察方向”求出一个颜色，再参与混合。

L2 表征——颜色存在哪：球谐是球面上的一组正交基函数（“定义在方向上的多项式”），给一个方向 d 就求出一个值：

c(d) = Σₗ Σₘ kₗₘ · Yₗₘ(d)

3DGS 常用 3 阶 SH：每个 RGB 通道 16 个系数 × 3 通道 = 每个高斯 48 个数。这些系数和位置、形状一样，是被梯度下降学出来的参数。

为什么不用固定颜色：真实物体表面有视角相关外观——高光、镜面反射会在不同视角变化。固定 RGB 渲染不出这种效果；SH 相当于给每个高斯配了一个“随视角变化的小函数”。（训练早期常用 0 阶 SH = 常数色先收敛，随后逐步升阶，这也解释了为什么优化初期画面发“糊”。）

L3 渲染——颜色怎么变成像素值：① 高斯被投影到屏幕，算出它盖住哪些像素；② 对每个像素，用该像素的视线方向代入该高斯的 SH 系数，求出它朝这个方向反射的颜色 cᵢ；③ 所有覆盖这个像素的高斯按深度排序，做 alpha 混合得到 RGB。一句话：颜色的“存储”在 SH 系数里，“计算”发生在渲染时用视线方向求值的那一刻，“呈现”靠按深度的 alpha 混合。
