# VLA 蒸馏实现：论文与方法

> 调研日期：2026-11-21 · 用途：《VLA 在 L4 的可执行落地方案》车端化蒸馏路线参考
> 核实：全部条目经 arXiv 官方 API/全文核对，引用逐字摘自原文；无 arXiv 论文的工作（π0-FAST）标 ❗。

## TL;DR

- **蒸馏有五个子类，别混用**：① 动作/输出分布蒸馏（把大 VLA 的动作输出蒸馏进小模型）；② 特征/隐层蒸馏（蒸馏 LLM 的中间表示，驾驶侧主力）；③ 数据蒸馏（大模型生成监督标注，学生独立训练）；④ 训练期教师（大模型只在训练期存在，推理零开销）；⑤ 任务级经验蒸馏（大模型+小模型搭班子跑任务，只保留成功轨迹训小模型）。
- **驾驶侧最硬的一条证据**：Orion-Lite 把 ORION 的 7B LLM 蒸馏成一个 0.1B 的 6 层 transformer decoder，Bench2Drive 闭环 Driving Score **80.6 反超教师的 77.7**，推理模块快 150×、显存 31GB→8GB——「驾驶反应式规划未必需要大 LLM 在推理期存在」。
- 对 robovan 的推荐组合：**Orion-Lite 式隐层蒸馏（省推理）× AutoVLA 式数据蒸馏（便宜造 CoT 标注）× VLP 式训练期教师（零推理开销）**，三选一或混合；推理侧再用 SnapFlow 式把流匹配压到 1-step。
- **最近三个月（2026-08~11）窗口内 9 篇新作**（见第九节，全部带伪代码）：驾驶侧有 WAM-Diff2 的 AR→扩散三阶段蒸馏（15.1× 解码加速）；一步生成三股势力（SnapFlow/DriftingVLA/FastOPD）；TTC 固化（Verify-Act-Distill）与遥操接管蒸馏（H2E）可直接接入 RFT 闭环。

## 一、分类框架

| 子类 | 蒸什么 | 教师何时存在 | 代表 |
|---|---|---|---|
| 动作/输出分布蒸馏 | 大 VLA 输出的动作 chunk / 分布 | 离线 | SnapFlow、π0-FAST❗、Verify-Act-Distill |
| 特征/隐层蒸馏 | LLM 中间隐层（latent planning token） | 离线 | Orion-Lite、DiMA、VERDI |
| 数据蒸馏 | 教师生成的文本标注（CoT/QA/指令） | 离线（只产数据） | AutoVLA、DriveGPT4、Senna、OmniDrive、LMDrive |
| 训练期教师 | 教师编码+对比/回归损失 | 仅训练期，推理移除 | VLP |
| 任务级经验蒸馏 | 教师参与的完整成功轨迹 | 离线（跑任务时） | H2E |

## 二、动作/输出分布蒸馏

### SnapFlow（2604.05656，2026）

- 动机："every action chunk is produced by integrating a learned velocity field over about ten sequential action-expert evaluations, so action generation dominates model latency and caps the achievable control frequency"（Abstract）。
- 方法（原文）："SnapFlow mixes local flow-matching supervision with shortcut samples whose target is the model's own two-step Euler endpoint under stop-gradient, and adds a single zero-initialized destination-time projection so that one action expert serves both objectives while the pretrained predictor is preserved at initialization; **no separate teacher network or critic is required**"（Abstract）——即渐进自蒸馏：教师=模型自身的两步 Euler 终点，无额外教师网络。
- 效果（Abstract）：π0.5（10-NFE 教师）→ 1-NFE 学生 LIBERO **98.75% vs 教师 97.75%**；π0 单步版超教师 +10.5pp；延迟 −3.3×。
- 备注：目标是把「10 步积分求解」压成「1 步」，直接对应车载控制频率瓶颈。

### π0-FAST（PI 博客，❗无 arXiv 论文）

- 路线：把 π0 的流匹配动作专家蒸馏成 FAST tokenizer 的自回归专家（openpi 开源权重），推理约 5×。依据为官方博客 + openpi 代码，无同行评议论文，引用时标注。

### Verify, Act, Distill（2610.14885，2026）

- 方法："A fixed verifier scores candidates generated by a flow-matching VLA, the weighted aggregate is executed, and the observations and aggregated chunks from successful adaptation episodes are distilled directly into **LoRA parameters with the standard flow-matching loss**... without additional reinforcement learning or rollouts dedicated to teacher generation"（Abstract）。
- 效果：SmolVLA 5k 上 40 个 LIBERO 任务，每任务 10 个 episode 蒸馏后单候选成功率 **54.1% → 70.6%**（保留 TTC 聚合增益的 74%）；对蒸馏后策略再套 TTC 聚合进一步 82.3%。
- 含义：把「测试时计算（verifier 选候选）」固化进模型，是 Best-of-N 的「蒸馏掉 oracle」版本——与前面讨论的 oracle PDMS 相对照：这是把 oracle 的增益沉淀到权重里的合法路径。

## 三、特征/隐层蒸馏（驾驶侧重点）

### Orion-Lite（2604.08266，CVPRW 2026，TU Eindhoven，代码开源）

- 设置：教师=ORION（EVA-02-L 视觉 + Vicuna-v1.5 **7B** LLM + VAE 生成式规划器）；学生=把 LLM 换成 **0.1B** 的 6 层 transformer decoder（input projection + learnable planning query + cross-attention + output projection，§3.3），**纯视觉、丢弃文本 prompt**。
- 蒸馏目标（§3.2）：教师 LLM 的 latent planning token T_p ∈ R^{1×C_p}——"we discard the text prompts entirely to achieve a vision-only architecture, utilizing the teacher's T_p as the pseudo-ground truth distillation target"。
- 损失（§3.4，原文公式）：
  - 特征模仿：`L_mimic = (1/(B·C_p)) Σ ||T_student − T_p||₁`（Eq.1，L1 回归，不用 KL——作者明确对比："avoiding... suboptimal distributional metrics"，即 DiMA 用 KL）；
  - GT 轨迹监督：`L_GT = L_col + λ_bd·L_bd + λ_reg·L_reg + λ_vae·L_vae`（Eq.2，λ_bd=λ_reg=λ_vae=3）；
  - 总损失：`L_total = L_GT + L_mimic`（Eq.3）。
- 冻结策略："the pre-trained vision encoder and QT-Former are kept strictly frozen... we focus the gradient updates entirely on the lightweight student decoder and the ensuing planner"（§3.4）。
- 结果（Table 1）：Bench2Drive 闭环 DS **80.6**（教师 ORION 77.7、MindDrive 78.0、UniDrive-WM 79.2）；能力分 60.5（教师 54.7）；"accelerates the reasoning module's inference by 150×... reduces total GPU memory usage from 31 GB to 8 GB"；整体延迟 806ms→267ms。
- 转引的同类工作（其 §2.3）：DiMA（"distilling VLM features via KL-divergence but limits its evaluation to open-loop metrics"）；VERDI（"performs distillation from Qwen-2.5-VL for closed-loop evaluation on HugSim... compares its student against older baselines rather than against its own teacher"）；DriveAdapter / Hydra-MDP（"distill knowledge from a heavy vision-centric teacher to a more efficient vision-only student"）。
- 关键论断（Abstract）："an efficient vision-only student model Orion-Lite can even **surpass the performance of its massive VLA teacher**"——闭环、交互场景下的反超，与 EMMA 的「自监督零感知头」同源：LLM 在直接模式下实际是 "overparameterized feature extractor"（§2.2）。

**实现伪代码（输入 / 输出 / 模块）**

| 模块 | 输入 | 输出 | 职责 |
|---|---|---|---|
| 视觉编码器 + QT-Former（冻结，ORION 权重） | 多视角图像 (N_c, H, W, 3) + 历史帧 | 视觉/历史特征 | 提特征，不训练 [论文 §3.4] |
| 教师 LLM（Vicuna-7B，冻结） | 视觉特征 + 文本 prompt | latent planning token T_p (1, C_p) | 产出伪标签 [论文 §3.2] |
| 学生解码器（0.1B，可训） | 压缩 token T_c (N_c, C_c) | 学生 planning token T_s (1, C_p) | 投影→learnable query 交叉注意力（6 层）→投影 [论文 §3.3] |
| VAE 规划器（ORION 权重，可训） | T_s | 轨迹 (T, 2) | 生成式规划头 |
| 联合损失 | T_s、T_p、轨迹、GT 轨迹 | 标量损失 | 特征模仿 + 碰撞/边界/回归/VAE 四项 GT 监督 [论文 §3.4] |

```python
# ---------- 准备：教师为每个训练场景生成伪标签（一次性离线）----------
def build_targets(dataset, vision, teacher):
    cache = []
    for scene in dataset:                          # 8 相机图像 ×4 帧 + 指令 + GT 轨迹
        feats = vision(scene.imgs)                 # 冻结编码器 + QT-Former
        T_p   = teacher.planning_token(feats, scene.prompt)   # (1, C_p) 教师隐层
        cache.append((scene, T_p))
    return cache

# ---------- 训练：学生 decoder + 规划器可训，视觉/教师冻结 ----------
def train_step(scene, T_p, vision, student, planner):
    T_c = vision(scene.imgs)                       # (N_c, C_c)
    T_s = student(T_c, scene.ego_cmd)              # (1, C_p) 无文本 prompt，纯视觉
    traj = planner(T_s)                            # (T, 2)
    L_mimic = l1(T_s, T_p)                         # 特征模仿（L1，不用 KL）
    L_gt    = collision(traj) + 3*boundary(traj) \
              + 3*l1(traj, scene.gt_traj) + 3*vae_kl(planner)   # λ=3 [论文 Eq.2]
    (L_mimic + L_gt).backward()                    # 只更新 student 与 planner [论文 §3.4]

# ---------- 部署 ----------
def act(scene, vision, student, planner):
    T_s = student(vision(scene.imgs), scene.ego_cmd)  # 教师与文本 prompt 全部移除
    return planner(T_s)                                # 806ms → 267ms [论文]
```

**输入/输出**：准备阶段输入=训练场景集；输出=（场景, 教师伪标签）缓存。训练输入=场景 + 伪标签；输出=学生 decoder 与规划器参数（视觉编码器/QT-Former/教师全程冻结）。部署输入=实时多视角图像 + 导航命令；输出=轨迹，LLM 不再存在。

## 五、训练期教师（零推理开销）

### VLP（2401.05577，CVPR 2024）

- 机制："VLP is only active during training, ensuring no additional parameters or computations are introduced during inference"（Fig.2 caption）；冻结 LLM 把 GT 感知/规划写成 prompt 编码，对比损失对齐 BEV 特征与规划特征，LM 冻结只训适配层（§3.2）。
- 价值：教师（语言模型的世界知识）以「对齐目标」形式进入学生，推理期完全不存在——最省部署成本的一条路。

## 六、任务级经验蒸馏

### H2E（2611.16246，2026）

- 机制："pairs an LLM planner and a frozen VLA as a heterogeneous training agent, keeps only sessions that reach the goal, and then trains a VLA alone on them so **no LLM is used at test time**"；"It masks the loss on steps moving away from the goal and assigns end labels to states near it"（Abstract）。
- 效果：REVERIE-CE 成功率 +15.6%、NavRAG-CE +11.1%；"The distilled VLA exceeds its agent on unseen episodes with zero LLM tokens and runs 3.7 times faster"（Abstract）。
- 与 robovan 的对应：LLM planner ≈ 你们的「远程接管员/运营指令系统」，VLA ≈ 车端策略——把「带人工介入才成功」的任务片段蒸馏成「无介入也能跑完」的策略。

## 七、非蒸馏的小型化对照（防止混淆）

- **SmolVLA**（2506.01844）：0.45B，直接训小 VLM + 流匹配动作专家（imitation learning），**不是教师蒸馏**（VLM 只用于标注清理）；layer skipping（N=L/2）、64 token/帧、异步推理栈。
- **TinyVLA**：SmolVLA 论文转述为 "trained a lightweight sub-1B model from scratch on multimodal data and then fine-tuned it on robotics datasets"（§2）——从零+微调，非蒸馏。
- **EMMA**（2410.23262）：直接用最小号 Gemini（Nano-1）微调——「选小号教师直接微调」的另一条路，非蒸馏。

## 八、总表与对 robovan 的启示

| 路线 | 代表 | 教师 | 学生 | 关键证据 | 对 robovan 的适用性 |
|---|---|---|---|---|---|
| 隐层蒸馏 | Orion-Lite | ORION 7B LLM | 0.1B decoder | DS 80.6>77.7；150× 推理提速 | **首选**：直接对应「VLA 决策 LLM → 车端小网络」 |

- 组合建议（[合成]）：SFT（遥操）→ 数据蒸馏（大模型造指令/CoT 标注）→ 隐层蒸馏（Orion-Lite 式，若保留大 LLM 教师）或直接小骨干 → RFT（PDMS）→ SnapFlow 式压推理步数 → 用 Verify-Act-Distill 把上线后 verifier 的增益固化回 LoRA。
- 反直觉结论要写进方案：**蒸馏可以反超教师**（Orion-Lite 闭环 DS 80.6 > 77.7；SnapFlow 98.75 > 97.75）——「大模型是训练期的老师，不一定是推理期的必要件」。

### 9.2 伪代码：七个关键机制（输入 / 输出 / 模块逐段标注）

#### (1) WAM-Diff2：AR → 掩码离散扩散三阶段蒸馏（驾驶）

**模块拆解**

| 模块 | 输入 | 输出 | 职责 |
|---|---|---|---|
| Tokenizer | 多视角相机图像；语言指令 | 图像 token、目标序列 o0 (B,L) | 全部任务共用同一文本 tokenizer，无任务专用头 [论文] |
| 掩码调度器 | o0、时间步 t | 加噪序列 o_t (B,L)、保留掩码 keep (B,L) | 按 β_t 把部分 token 替换成 [MASK]，可闭式采样 [论文] |
| Block-Causal Mask Builder | 解码块大小 B_blk | 注意力掩码 (L,L) | 块内双向、块间因果；Stage I 从 1 逐步放宽到 32 [论文] |
| 学生解码器 | 图像 token、o_t、掩码 | 干净 token 的 logits (B,L,V) | 并行去掩码重建 |
| 块级扩散教师（Stage II） | o_t（学生并行解码产生的中间态） | 目标 logits | on-policy 蒸馏，暴露学生自己的中间噪声态 [论文] |
| 跨尺度扩散教师（Stage III） | o_t | 目标 logits | 8B 教师 → 2B 学生，同范式 token 预测高度对齐 [论文] |

**伪代码**

```python
# ---------- 单步训练：掩码扩散重建 ----------
def train_step(batch, model, sched, blk):
    img_tok = tokenize_vision(batch.cams)          # (B, L_img)
    o0      = tokenize_target(batch.text_or_traj)  # (B, L) 文本/轨迹 token
    t       = randint(1, T, size=(B,))             # 每样本随机时间步
    o_t, keep = sched.corrupt(o0, t)               # 部分 token → [MASK]；keep 记录哪些被保留
    attn    = block_causal_mask(L, B_blk=blk)      # 块内双向、块间因果 [论文 §3.2]
    logits  = model(img_tok, o_t, attn)            # (B, L, V)
    loss    = cross_entropy(logits, o0, mask=~keep)  # 只对被打掩码的位置算损失 [合成]
    loss.backward()
    return loss

# ---------- 三阶段编排（离线脚本）----------
# Stage I  : for blk in [1, 4, 8, 16, 32]:
#                train_step(...)                  # B=1 时退化为纯自回归
# Stage II : teacher = freeze(stage1_last_model)   # 小 block 扩散教师
#            for blk in [8, 16, 32]:
#                on_policy_distill(teacher, blk)  # 学生先并行解码出中间态，再让教师给目标
# Stage III: cross_scale_distill(teacher_8B, student_2B)

def on_policy_distill(teacher, student, batch, blk):
    o_mid = student.parallel_decode(batch.img_tok, steps=2,
                                    block=blk)     # 学生自产中间噪声态 [论文 §3.2]
    tgt   = teacher.logits(batch.img_tok, o_mid)   # 教师对这些态给目标 logits
    loss  = kl_div(student.logits(batch.img_tok, o_mid), tgt)
    loss.backward()                                # 只更新学生

# ---------- 推理：并行重掩码 ----------
def generate(img_tok, model, steps=8):
    o = full_masked(L)                             # 全 [MASK] 起步
    for _ in range(steps):                         # 每步并行精炼整个序列 [论文 §3.1]
        p = softmax(model(img_tok, o), -1)         # (L, V)
        conf, tok = p.max(-1)
        o = commit_top_confidence(o, tok, conf)    # 固定高置信 token，其余重新掩码 [合成]
    return detokenize(o)
```

**输入/输出**：训练输入=批量场景（相机图像 + 目标文本/轨迹 token）+ 随机时间步；训练输出=各位置的交叉熵梯度（只反传到学生解码器）。推理输入=相机 token + 全掩码序列；推理输出=解 token 后的轨迹/文本，解码步数由 8 步重掩码替代原来的逐 token 生成。

#### (2) DriftingVLA：原生一步生成

**模块拆解**

| 模块 | 输入 | 输出 | 职责 |
|---|---|---|---|
| VLM 前缀编码器（保留预训练权重） | 多视角图像、语言指令、本体状态 | 多模态前缀 prefix | 每个 batch 只算一次，G 个 sibling 复用 [论文] |
| 动作生成器 f_θ（重初始化） | 高斯噪声 z (H,D)、prefix | 动作 chunk A (H,D) | 直接「噪声→chunk」，不再输出速度场 [论文] |
| 漂移场估计器 | 生成样本、真实样本 | 每个漂移组的修正方向 | 把分布修正量做成 stop-gradient 回归目标 [论文 Eq.7] |
| PDTD 分组器 | chunk (H,D) | D 个分组（每维完整时间轨迹） | 每个动作维度单独成组，几何独立 [论文] |
| 训练损失 | 生成 A、修正目标 | 标量损失 | 尺度回归，把修正吸收进生成器 [论文 Eq.8] |

**伪代码**

```python
# ---------- 训练（post-training，Q 个 sibling 共享 prefix）----------
def train_step(batch, vlm, gen, drift, G=4):
    prefix = vlm(batch.cams, batch.instruction, batch.state)  # 共享前缀，只前向一次 [论文]
    loss   = 0.0
    for g in range(G):                              # G 个 sibling 假设
        z   = randn(batch.B, H, D)                  # 高斯噪声
        A_g = gen(z, prefix)                        # (B, H, D) 直接生成 chunk
        for d in range(D):                          # PDTD：按动作维分组 [论文]
            x      = A_g[:, :, d]                   # (B, H) 该维完整时间轨迹
            target = drift.field(x, batch.real_A[:, :, d])   # 漂移场修正
            loss  += squared_error(x, stop_grad(x + target))
    loss.mean().backward()                          # 只更新 gen（VLM 可联合微调）

# ---------- 推理（原生一步）----------
def act(obs, vlm, gen):
    prefix = vlm(obs.cams, obs.instruction, obs.state)
    return gen(randn(1, H, D), prefix)              # 单次前向，无积分、无蒸馏捷径
```

**输入/输出**：训练输入=场景（图像/指令/状态）+ 真实动作 chunk (B,H,D)；训练输出=生成器参数更新。推理输入=当前观测；推理输出=完整动作 chunk，一次前向（原方法需 10 次 action-expert 前向）。G=2→8 时训练成本仅 +3.78% [论文]。

#### (3) FastOPD：在线蒸馏到少步学生

**模块拆解**

| 模块 | 输入 | 输出 | 职责 |
|---|---|---|---|
| 教师策略（多步流匹配，冻结） | 观测 o、动作 a | 教师速度场/目标 | 提供「单状态」监督信号 [论文 Abstract] |
| 学生策略（少步流，小骨干） | o、a、当前步 | 学生速度场/2 步动作 | 学习教师动态 |
| 自一致性项 | 学生对同一 o 的多次/不同起点预测 | 一致性损失 | 约束学生自洽 [论文 Abstract] |
| 推理器 | o | 动作 chunk | 2 步采样出动作（延迟 −78.1%）[论文] |

**伪代码**

```python
# 单次训练步（细节公式见论文，此处为接口级重构 [合成]）
def train_step(o, a, teacher, student, lam):
    # ① 单状态教师监督：把教师多步过程蒸馏成「单状态」目标
    tgt = teacher.target_for_state(o, a)             # 教师在该状态给出的目标 [论文]
    L1  = mse(student.velocity(o, a), tgt)
    # ② 自一致性：学生对同一观测的不同起点/步长预测需一致
    a2  = student.sample(o, steps=1)                 # 一步预测
    a2b = student.advance(student.sample(o, steps=1))# 自洽对照 [合成接口]
    L2  = mse(a2, a2b)
    (L1 + lam * L2).backward()                       # 只更新学生

# 推理
def act(o, student):
    return student.sample(o, steps=2)                # 2 步保留 π0.5 的 84% [论文]
```

**输入/输出**：训练输入=观测-动作对 + 教师目标；训练输出=学生参数。推理输入=观测；输出=动作 chunk（2 步）。教师只在训练期出现。

#### (4) Verify-Act-Distill：把测试时计算固化进 LoRA

**模块拆解**

| 模块 | 输入 | 输出 | 职责 |
|---|---|---|---|
| 流匹配 VLA（冻结） | 观测 o | G 个候选动作 chunk | 多候选采样 [论文] |
| Verifier（固定） | o + 每个候选 | 分数/权重 | 给候选打分 [论文] |
| 加权聚合器 | G 个候选 + 权重 | 执行用 chunk | 加权平均后执行 [论文] |
| 成功缓存 | (o, 聚合后 chunk, 任务是否成功) | 蒸馏样本 | 只留成功 episode [论文] |
| LoRA 适配器 + 流匹配损失 | 成功样本 | LoRA 参数更新 | 把 TTC 增益蒸馏进权重 [论文] |

**伪代码**

```python
# ---------- 执行期：TTC（测试时计算）----------
def act_with_ttc(o, vla, verifier, G=8):
    cands = [vla.sample(o) for _ in range(G)]        # G 个候选 chunk
    w     = softmax(verifier.score(o, cands))        # 每候选一个权重
    A_exec = sum(w_i * c_i for w_i, c_i in zip(w, cands))
    return A_exec

# ---------- 蒸馏期：把成功的「聚合动作」变成监督 ----------
def distill(success_buffer, vla, lora, opt):
    for o, A_exec in success_buffer:                 # 只含成功 episode [论文 Abstract]
        pred = lora_forward(vla, o)                  # 原 VLA + LoRA
        loss = flow_matching_loss(pred, A_exec)      # 标准流匹配损失 [论文]
        opt.zero_grad(); loss.backward(); opt.step() # 只更新 LoRA

# 训练循环：每任务只采 10 个 episode 即可（54.1% → 70.6%）[论文]
```

**输入/输出**：执行输入=观测 + G 候选与 verifier 分数；执行输出=聚合动作。蒸馏输入=成功样本（观测 → 聚合动作）；输出=LoRA 权重。无需额外 RL、无需专用教师 rollout。

**模块拆解**

| 模块 | 输入 | 输出 | 职责 |
|---|---|---|---|
| LLM planner（带工具） | 任务描述、当前观测 | 子指令/工具调用 | 高层规划与纠错 [论文] |
| 冻结 VLA 执行器 | 观测 + 子指令 | 动作 | 底层执行 [论文] |
| 轨迹记录器 | 完整 episode | (观测, 动作, 到达目标?, 进度) | 保存会话 [合成接口] |
| 成功过滤器 | 会话列表 | 成功会话集 | 只保留到达目标的会话 [论文] |
| 重标注/掩码器 | 成功会话 | 训练样本（掩码 + 终点标签） | 远离目标步掩损失、近目标打终点标签 [论文] |

# ---------- 阶段 1：异构 agent 采集成功经验 ----------
def collect(tasks, planner, vla):
    sessions = []
    for task in tasks:
        traj = []

        sessions.append((task, traj, reached_goal(traj)))

# ---------- 阶段 2：VLA 单独训练 ----------
def train(success_sessions, vla, opt):

        for i, (obs, a, sub_goal) in enumerate(traj):
            label_mask = 1.0
            if moving_away_from_goal(traj, i):           # 远离目标的步不学 [论文]
                label_mask = 0.0
            if near_goal(traj, i):                       # 近目标处打 END 标签 [论文]
                label = END
            loss = vla_loss(vla(obs), a, end_label=label, mask=label_mask)

#### (6) EmbodyAgent：黑盒教师 → SFT → RL 三管线

**模块拆解**

| 模块 | 输入 | 输出 | 职责 |
|---|---|---|---|
| 黑盒教师客户端 | 任务描述 + 图像 | think-then-code 文本（解释+程序） | 强教师 API，只有 token 级输出 [论文] |
| 合成与过滤 | 教师轨迹 | (解释, 程序, 成功?) | 按任务成功过滤 [论文] |
| SFT 管线 | 过滤后数据 | 9B 开源 VLM 权重 | 蒸馏「解释+程序」目标，视觉+语言编码器都可训 [论文] |
| 执行工具 | 程序文本 | 7 维末端控制 + 原始视觉观测 | primitive-free Python 执行器，无动作解码器 [论文] |
| 在线 RL 管线 | 学生自产 episode | 组相对优势 + runtime-error 惩罚的奖励 | 优化学生自身轨迹 [论文] |

**伪代码**

```python
# ---------- ① 黑盒数据合成 ----------
def synth(teacher, tasks, k):
    data = []
    for task in tasks:
        for _ in range(k):
            reply = teacher.chat(task, contract="think-then-code")  # 强制先想后写代码 [论文]
            expl, code = parse(reply)
            ok = run_task(code)                                    # 真实执行判定
            data.append((task, expl, code, ok))
    return [(t, e, c) for t, e, c, ok in data if ok]               # 成功过滤 [论文]

# ---------- ② SFT 蒸馏进 9B 开源 VLM ----------
def sft(model, data, opt):
    for task, expl, code in data:
        loss = ce(model(task), expl + code)                        # 解释+程序一起学 [论文]
        opt.zero_grad(); loss.backward(); opt.step()               # 视觉/语言编码器可训 [论文]

# ---------- ③ 在线 RL（GRPO 式组相对优势 + runtime-error 惩罚）----------
def rl_step(model, tasks, G=8):
    for task in tasks:
        rollouts = [model.generate(task).execute() for _ in range(G)]
        r = [reward(rollout) - penalty(runtime_error(rollout)) for rollout in rollouts]
        A = (r - mean(r)) / (std(r) + eps)                         # 组内标准化 [论文]
        loss = -sum(A_i * logp(rollout_i) for i, rollout_i in enumerate(rollouts))
        loss.backward(); opt.step()
```

**输入/输出**：① 输入=任务集+教师 API；输出=过滤后的（解释, 程序）数据。② 输入=该数据；输出=9B SFT 模型。③ 输入=任务集；输出=RL 后模型。效果：held-out 0→14→84/100；rollout 成功率 8.4%→87.7%；每 episode 中位调用 36→11 次 [论文]。

#### (7) Fast Plans：Block-AR + NGM（层级 VLA 效率，非蒸馏）

**模块拆解**

| 模块 | 输入 | 输出 | 职责 |
|---|---|---|---|
| Token-AR 基线 | 观测 + 指令 | 逐 token waypoint 计划 | 需 57 次 VLM 前向 [论文] |
| Block-AR 解码器 | 观测 + 指令 | 块级 waypoint 计划 | waypoint 对齐的块并行解码，≤8 次前向（含 1 次 prefix prefill）[论文] |
| NGM 调制器 | waypoint 计划 + 相位 | 逐层目标路径条件 | layer-wise 目标调制 + 相位门控 [论文] |
| Anti-shortcut 训练 | 计划-动作对 | 调整后参数 | 防止执行器绕过计划 [论文] |

**伪代码**

```python
# ---------- 推理：Block-AR ----------
def plan_blocks(obs, instr, vlm, blk=8):
    prefix = vlm.prefill(obs, instr)                    # 1 次前向 [论文]
    blocks = []
    for b in range(n_blocks):
        # 一次前向并行出 blk 个 waypoint token（块内并行、块间因果）[论文]
        out = vlm.decode(prefix, blocks, block=blk)
        blocks.append(out)
    return flatten(blocks)                              # 最多 8 次前向，非 57 次 [论文]

# ---------- 训练：NGM + anti-shortcut ----------
def train_step(obs, instr, plan_gt, act_gt, vlm, ngm):
    plan = plan_blocks(obs, instr, vlm)
    cond = ngm(plan, phase=t)                           # 逐层调制目标路径，相位门控 [论文]
    act  = executor(obs, cond)
    loss = l1(act, act_gt) + lam * consistency(plan, plan_gt)  # 计划必须被使用 [合成接口]
    loss.backward()
```

**输入/输出**：推理输入=观测+指令；输出=waypoint 计划（≤8 次前向，规划延迟 −8.7×）。训练输入=计划与动作真值；输出=模型参数。消融发现：抹掉 waypoint 端点几乎不掉点 → 执行器绕过计划，是层级 VLA 的通用风险 [论文]。

### 9.3 对 robovan 的增量启示

1. **驾驶侧现在有两条「范式转换」蒸馏**：Orion-Lite（LLM→小 decoder，隐层蒸馏）与 WAM-Diff2（AR→离散扩散，三阶段层级蒸馏）。若你们 VLA 是自回归动作 token，WAM-Diff2 的 block-causal 课程 + on-policy 蒸馏可直接照抄；15.1× 的加速来自 FlashInfer+CUDA Graphs，属系统侧白捡。
2. **一步生成是三股势力在卷**：SnapFlow（捷径自蒸馏）、DriftingVLA（漂移目标原生一步）、FastOPD（在线蒸馏）——DriftingVLA 的公式最简单（stop-gradient 漂移目标，无教师网络），且 3.36× 提速不牺牲成功率；车载流匹配动作头值得评估这条线。
3. **计划-执行脱节是新雷区**：Fast Plans 的消融（erase waypoint 端点几乎不掉点）与 Language2Drive/ICR-Drive 的指令失效同源——**层级设计里「上层输出不被下层使用」必须用 anti-shortcut 类训练显式对抗**，你们做 VLA 高层决策 + two-stage 执行时同样适用。
4. **TTC 固化和遥操接管蒸馏是对口组合**：Verify-Act-Distill（verifier 增益→LoRA）与 H2E（人工/LLM 介入成功轨迹→VLA）可以叠加进现有 RFT 闭环：上线后远程接管员每救一次车，就把那次成功干预作为蒸馏数据回流。
