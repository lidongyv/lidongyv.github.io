CVPR 2026   Finalist

SAM 3D Body: Robust Full-Body Human Mesh Recovery

Xitong Yang ⋅ Devansh Kukreja ⋅ Don Pinkus ⋅ Taosha Fan ⋅ Jinhyung Park ⋅ Soyong Shin ⋅ Jinkun Cao ⋅ Jia-Wei Liu ⋅ Nicolás Ugrinovic ⋅ Anushka Sagar ⋅ Jitendra Malik ⋅ Matt Feiszli ⋅ Piotr Dollár ⋅ Kris Kitani
arXiv PDF ⬇arXiv 摘要Scholar

摘要 Abstract

We introduce SAM 3D Body (3DB), a promptable model for single-image full-body 3D human mesh recovery (HMR) that demonstrates state-of-the-art performance, with strong generalization and consistent accuracy in diverse in-the-wild conditions. 3DB estimates the human pose of the body, feet, and hands. It is the first model to use a new parametric mesh representation, Momentum Human Rig (MHR), which decouples skeletal pose and body shape. 3DB employs an encoder–decoder architecture and supports auxiliary prompts, including 2D keypoints and masks, enabling user-guided inference similar to the SAM family of models. We derive high-quality annotations from a multi-stage annotation pipeline that uses various combinations of manual keypoint annotation, differentiable optimization, multi-view geometry, and dense keypoint detection. Our data engine efficiently selects and processes data to ensure data diversity, collecting unusual poses and rare imaging conditions. We present a new evaluation dataset organized by pose and appearance categories, enabling nuanced analysis of model behavior. Our experiments demonstrate superior generalization and substantial improvements over prior methods in both qualitative user preference studies and traditional quantitative analysis. Both 3DB and MHR are open-source.

📝 精读笔记

灵魂一句
Meta 出品的「可提示」单图全身(身+手+脚)3D 人体 mesh 恢复(HMR)模型，对标 SAM 家族。三支柱：① SAM 式 promptable encoder-decoder(可选 2D keypoint / mask 引导)，共享 image encoder + 身/手两个独立 decoder 解决两者优化冲突；② 首个用新参数化 mesh MHR(Momentum Human Rig)——把「骨架 pose」与「体型 shape」解耦(vs SMPL 把二者纠缠)；③ VLM 驱动的 data engine 主动挖难样本 + 多阶段标注流水线 → 7M 高质量标注。SOTA + 强泛化 + 用户偏好 5:1。
问题 & 动机
原文：现有 HMR “exhibit unsatisfactory robustness when applied to in-the-wild images”，在 challenging pose / 严重遮挡 / 罕见视角上失败，且难在统一框架里同时估好 body 与 hands/feet。两根因：① 数据——大规模、多样、高质量 mesh 标注难且贵(实验室数据 low diversity、pseudo-label low quality)；② 模型——架构没解决 body 与 hand 的不同优化机制，也没处理单目的 uncertainty/ambiguity。
核心方法 + 关键结构
① promptable encoder-decoder：image encoder → 特征 F(可选 hand crop → Fhand)；2D keypoint prompt 编码成 token、mask 卷积后逐元素加到 image embedding。decoder query token = [Tpose(MHR+camera), Tprompt, Tkeypoint2D, Tkeypoint3D, Thand]；body decoder cross-attend(T,F)→O(Eq.10)，首 token 过 MLP 回归 θ={P,S,C,Sk}(pose/shape/camera/skeleton)。
② 两 decoder 解冲突：body 与 hand 在「输入分辨率、相机估计、监督目标」上不同，shared encoder + 分离 decoder 缓解。
③ MHR：解耦 skeleton 与 shape(SMPL 把骨架+软组织揉进 shape space，参数不直接对应骨长、可解释/可控性差)。
④ 训练：multi-task Ltrain=Σλ_i·L_i(2D/3D keypoint L1 + per-joint 可学 uncertainty、参数 L2 + 关节限位、hand box GIoU+L1)，3D keypoint 用 warm-up，模拟交互(多轮随机采 prompt)。
⑤ 推理 hand 融合：用 hand decoder 的 wrist + body decoder 的 elbow 反过来 prompt body decoder，避免直接把 hand 塞进 kinematic tree 导致 elbow 错。
关键结果
Table 2(5 标准集)：3DB-H 3DPW PA-MPJPE 33.2 / EMDB 38.5，超所有单图法、可比视频法，OOD 的 EMDB/RICH 泛化最好。Table 3(5 新集 leave-one-out)：EE4D-Phy PVE 49.7 vs CameraHMR 71.1、Harmony4D 63.5 vs 84.6——泛化碾压。Table 4(FreiHand 手)：3DB PA-MPJPE 5.5 ≈ SoTA 手专模型 WiLoR 5.5(还没训 FreiHand)。Table 6(3D 难 pose)：pose_3d:very_hard PVE 114.2 vs 213.66/186.35。用户研究(7800 人)：整体 5:1，vs 最强 baseline NLF 83.8% win。
亮点
① 把 SAM 的「promptable + 大数据引擎」范式搬到 HMR；② MHR 解耦骨架/体型带来可控可解释；③ data engine 用 VLM 按「失败分析」迭代更新挖掘规则、主动找 hard case(遮挡/倒立/劈叉/截断)——categorical 评测显示正是这些类别提升最大；④ mask conditioning 对多人近距离交互大涨(Hi4D PVE 91.4→58.3)；⑤ 偏好研究规模大(7800 人/20000+ 响应)。
疑问 / 边界
① 限制(原文)：逐人独立处理，不建模 multi-person / human-object 交互；② hand 精度仍不超专用手模型，body decoder 单独的 hand 估计 suboptimal；③ MHR/3DB 对各年龄段体型(尤其 children)建模不足；④ 大量工程/数据细节(7M 数据配比、各 loss 权重 λ)靠经验设定，复现门槛高(Meta 级资源)；⑤ MHR 本身是另一篇([Ferguson 2025]，ATLAS 的增强)——本文是「用+适配」，MHR 内部细节需查原文(外部)。

① 引言/摘要 — 逐句精讲（这是 Meta 技术报告，开篇即摘要）
一句话立意：Meta Superintelligence Labs 出的 SAM 3D Body（3DB）——单图全身（body+手+脚）三维网格重建（HMR）的 SOTA、可提示（promptable，像 SAM 一样可用 2D 关键点/mask 引导）、在野外（in-the-wild）极端姿态/视角下鲁棒，且开源。
逐句拆解（verbatim）：
1) "We introduce SAM 3D Body (3DB), a promptable model for single-image full-body 3D human mesh recovery (HMR) that demonstrates state-of-the-art performance, with strong generalization and consistent accuracy in diverse in-the-wild conditions."
2) "It is the first model to use a new parametric mesh representation, Momentum Human Rig (MHR), which decouples skeletal structure and surface shape." —— 首次用 MHR，把骨架结构与表面形状解耦。
3) "3DB employs an encoder–decoder architecture and supports auxiliary prompts, including 2D keypoints and masks, enabling user-guided inference similar to the SAM family of models."
4) "is preferred by users in a study of 7,800 participants, achieving a significant 5 : 1 win rate in visual quality." —— 7800 人用户研究、5:1 视觉胜率。
📚 背景知识①（外部）：HMR / SMPL / SMPL-X / MANO
HMR（Human Mesh Recovery）=从图像恢复人体 3D 网格（姿态+形状）。最常用人体模型 SMPL（Loper 2015）把人体参数化为 pose+shape；SMPL-X 进一步含手（MANO）和脸（FLAME）。原文点出 SMPL 的局限："SMPL models intertwine the skeletal structure and soft-tissue mass within the shape space, which can limit interpretability (e.g., the parameters do not always map directly to bone lengths) and controllability." —— 骨架与软组织混在一个 shape space 里，参数不直接对应骨长，可解释性/可控性差。这正是本文换用 MHR 的动机。
📚 背景知识②（外部）：MHR（Momentum Human Rig）核心
MHR（Ferguson 2025，ATLAS 的增强版）显式解耦骨架结构与体形：\(\theta=\{P,S,C,Sk\}\) 分别是 pose（姿态）、shape（形状）、camera（相机）、skeleton（骨架）。好处：① 参数直接映射骨长，可解释；② 骨架与形状独立 → 更丰富的控制（如保持骨架改胖瘦）；③ 对全身重建更友好。原文："Momentum Human Rig … explicitly decouples the skeletal structure and body shape, and we adopt it as our representation of the human body." 3DB 是首个用 MHR 的 HMR 模型，评测时把 MHR mesh 映射回 SMPL 格式以对齐既有 benchmark。
📚 背景知识③（外部）：promptable 推理 + 评测指标
Promptable inference（SAM 系 Kirillov 2023 / SAM2 Ravi 2024 推广）：让用户/系统给 prompt（2D 关键点、mask）引导预测。3DB 把 prompt token 直接塞进 transformer，实现交互式 mesh 恢复。指标：MPJPE（Mean Per-Joint Position Error，关节位置误差 mm，↓）、PA-MPJPE（Procrustes 对齐后，去掉全局旋转/平移/尺度，↓）、PVE（Per-Vertex Error，顶点误差 mm，↓）、PCK@0.05（Percentage of Correct Keypoints，关键点落在阈值内的比例，↑）。手部还用 PA-MPVPE 与 F@5/F@15（F-score，阈值 5mm/15mm 内的顶点比例）。这些指标里 PA-* 系列因做了 Procrustes 对齐，只评"姿态形状对不对"、不罚全局位姿，故常比未对齐的 MPJPE 小不少。
② Introduction — problem → solution → why（数据 + 模型双瓶颈）
problem：现有 HMR 在野外不鲁棒——"current models often fail on individuals presenting challenging poses, severe occlusion, or captured from uncommon viewpoints. They also struggle to reliably estimate both the overall body pose and the fine details of the hands and feet in a unified full-body framework." 作者把根因归为两面：① 数据——大规模高质量 mesh 标注难且贵，实验室数据多样性低、伪标注质量差；② 模型——现有架构没处理好 body 与 hand 各自不同的优化机制，也没好策略应对单目歧义。solution：3DB = 鲁棒全身 HMR 模型 + data engine 驱动的大规模高质量数据。三条模型贡献：(i) promptable encoder-decoder（可条件于 2D 关键点/mask/相机）；(ii) 共享 image encoder + body/hand 两路 decoder（缓解 body-hand 优化冲突）；(iii) 用 MHR 取代 SMPL。
Q&A · 为什么用 MHR，而不是大家都在用的 SMPL？
问：既然 SMPL/SMPL-X 生态成熟（benchmark、工具都基于它），为何冒险换 MHR？答：因为 SMPL 把"骨架"和"软组织形状"塞进同一个 shape 空间，导致两个工程痛点：参数不直接对应骨长（不可解释）、改 pose 会牵连 shape（不可控）。MHR 把 \(Sk\)（skeleton）和 \(S\)（shape）解耦成独立参数，于是：① 全身重建时骨架/胖瘦/姿态各管各，减少耦合误差；② 对 hand decoder 这种"自由手腕"设计更友好（手腕能相对身体自由转）。代价是要把 MHR 网格映射回 SMPL 才能跑老 benchmark，作者已处理。这是"先把表示选对，再谈架构与数据"的第一性思路。
③ 架构：Image Encoder（式1-2）
人裁剪图 \(I\) 归一化后过视觉 backbone 得稠密特征 \(F=\text{ImgEncoder}(I)\)（式1）；可选地给手裁剪图 \(I_{hand}\) 得手特征 \(F_{hand}=\text{ImgEncoder}(I_{hand})\)（式2）。两个变体：3DB-H 用 ViT-H（632M）backbone，3DB-DINOv3 用 DINOv3（840M）encoder。输入 resize 到 \(512\times512\)，并用现成 FOV 估计器（MoGe-2）提供相机内参。两类 prompt：2D 关键点（位置编码+学习嵌入，作为 pose decoder 的额外 token）与 mask（卷积嵌入后逐元素加到 image embedding，SAM 式做法）。
③ 架构：Decoder Tokens（式3-9）
pose decoder 吃一组 query token，四类：① MHR+Camera token：初始 MHR/相机估计嵌成可学 token \(T_{pose}=\text{RigEncoder}(E_{init})\in\mathbb{R}^{1\times D}\)（式3）；② 2D 关键点 prompt token：\(T_{prompt}=\text{PromptEncoder}(K)\in\mathbb{R}^{N\times D}\)（式5），每个关键点表示为 \((x,y,\text{label})\in\mathbb{R}^{N\times3}\)（式6）；③ Hand position token \(T_{hand}\in\mathbb{R}^{2\times D}\)（可选，定位图中手位置，没有它也能出全身 rig）；④ 辅助关键点 token \(T_{keypoint2D}\in\mathbb{R}^{J_{2D}\times D}\)、\(T_{keypoint3D}\in\mathbb{R}^{J_{3D}\times D}\)（式7-8，增强交互/容量）。全部拼接：\(T=[T_{pose},T_{prompt},T_{keypoint2D},T_{keypoint3D},T_{hand}]\)（式9）。
③ 架构：MHR Decoder + 输出（式10）
body decoder 用 cross-attention 同时关注 query token \(T\) 与全身图特征 \(F\)：\(O=\text{Decoder}(T,F)\in\mathbb{R}^{(3+N+J_{2D}+J_{3D})\times D}\)（式10），把 prompt 信息与视觉上下文融合 → 鲁棒且可编辑的 mesh 恢复。\(O\) 的首 token 过 MLP 回归最终参数 \(\theta=\text{MLP}(O_0)=\{P,S,C,Sk\}\)（pose/shape/camera/skeleton）。可选的 hand decoder 用同样 prompt 但关注手特征 \(F_{hand}\) 得 \(O_{hand}\)，再合并进 body 输出改善手姿。这种"统一框架里同时出 body 与 hand"正是它区别于"只做身体"或"只做手"的关键。为何这套设计能"可编辑"：因为 prompt token 与视觉特征在 cross-attention 里平等参与，用户/系统加一个 2D 关键点就等于给优化加一条强约束，模型会顺着它重算整套 \(\theta\)。这让 3DB 在歧义场景（遮挡、截断、罕见视角）下可由人轻量介入纠偏，而不必重训——这正是"像 SAM 一样可提示"对 HMR 的迁移价值：把不可控的单目歧义，变成可交互、可收敛的推理过程。
③ 为什么要 two-way decoder（body/hand 分离）？
原文："This two-way-decoder design effectively alleviates conflicts in optimizing body and hand pose estimation, which arise from differences in input resolution, camera estimation, and supervision objectives." —— body 与 hand 的输入分辨率、相机估计、监督目标都不同，硬塞进一个 decoder 会互相打架。共享 image encoder（省算力、共享语义）+ 两路独立 decoder（各自优化）是折中。推理时默认用 body 输出，检测到手就合并 hand decoder 输出；但直接把 hand 结果插进 MHR 运动学树中段会让相邻关节（尤其肘部）出错，于是用 hand decoder 的手腕位置 + body decoder 的肘部位置反过来prompt body decoder 做精修——把"可提示"这一设计用在了自我纠错上。
④ 训练：多任务损失 + 交互式 prompt 训练
总损失 \(L_{train}=\sum_i\lambda_i L_i\)，各 \(L_i\) 针对特定预测头/解剖结构。2D/3D 关键点损失：L1，带可学每关节不确定性调制（按置信度加权）；3D 关键点先用骨盆/手腕归一化。参数损失：MHR pose/shape 用 L2，加关节限位惩罚防解剖不可能姿态。手检测损失：GIoU+L1 监督手框回归，预测手框不确定性、推理时对手被遮挡样本关掉 hand decoder。训练还模拟交互（SAM 式）：每样本多轮随机采样 prompt，并对用户给的关键点上调权重以鼓励 prompt 一致性。部分损失（如 3D 关键点）用 warm-up 渐增权重以稳训。
⑤ Data Engine：VLM 挖掘困难样本
核心是 VLM 驱动的挖掘：不靠简单启发式/随机采样，而让 VLM 自动生成并迭代更新"挖掘规则"，从数千万图里筛高价值样本送标注。VLM 专挑六类困难场景：occlusion（遮挡）、unusual poses（杂技/舞蹈等罕见姿态）、interaction（人-物/人-人）、extreme scale（异常远近）、low visibility（弱光/运动模糊/部分可见）、hand-body coordination（手语/运动中手身紧耦合）。挖掘规则基于当前模型的失败分析迭代更新（半自动：跑 3DB→看关键点误差最大的图→人工几词描述→喂 VLM 生成文本 prompt→VLM 选新图→人工标注），形成"模型越弱处越被挖"的闭环。
⑤ 多阶段标注：单图/多视图 mesh fitting + 595 dense keypoints
单图 fitting：先用当前 3DB 出初始 MHR + 高容量检测器出的 595 个 dense 2D 关键点（原文称这是"the minimal manifold of a human body mesh"——捕捉体形与手姿的最小流形），再梯度精修最小化复合损失 \(L_{fit}=\sum_j\lambda_j L_j\)（2D 关键点重投影 L2 + 初始锚定正则防漂移 + 学习的高斯混合 pose/shape 先验）。多视图 fitting：同步多相机 2D 关键点三角化得稀疏 3D，再二阶优化联合拟合所有帧/视角，加 3D 关键点损失与时序平滑，交替更新 camera/shape/skeleton/pose 并用 RANSAC/鲁棒损失滤噪。dense keypoint 检测器还用稀疏关键点引导+迭代自训练（投影 mesh→再训）两轮。
⑥ 训练数据 7M（Table 1）
混合单视图野外 + 多视图一致 + 高保真合成，共约 7 百万高质量标注图。单视图野外：MPII(5K)、COCO(24K)、3DPW(17K)、AIChallenger(172K)、SA-1B 子集(1.65M)。多视图：Ego-Exo4D(1.08M/4+视角)、Harmony4D(250K/20视角)、EgoHumans(272K/15视角)、InterHand2.6M(1.09M/66视角)、Re:Interhand(1.50M/170视角)、DexYCB、Goliath(966K/500+视角)。合成：Goliath 的照相级合成扩展(1.63M，带 GT MHR)。原文点出合成的价值："Synthetic data ensures accurate supervision … complementing real-world datasets that prioritize diversity over quality." ⋆标的数据集额外训手 decoder。
④ 实验：5 个标准 benchmark（Table 2，真数字）
3DPW（PA-MPJPE/MPJPE/PVE）：3DB-H 33.2/54.8/64.1、3DB-DINOv3 33.8/54.8/63.6，优于最强单图基线 NLF（33.6/54.9/63.7）、CameraHMR（35.1/56.0/65.9）、PromptHMR（36.1/58.7/69.4），甚至胜过视频法 GENMO（34.6/53.9/65.8）。EMDB（域外）：3DB-H 38.5/62.9/74.3、DINOv3 38.2/61.7/72.5，大幅优于 NLF（40.9/68.4/80.6）、PromptHMR（41.0/71.7/84.5）——泛化更好。RICH（域外）：3DB-DINOv3 30.9/53.7/60.3（NLF 28.7/51.0/58.2 但 NLF 训练用了 RICH、3DB 没用）。2D PCK@0.05：COCO 3DB-H 86.8、LSPET 68.9（vs PromptHMR 79.2/55.6），均 SOTA。
④ 实验：5 个新数据集泛化（Table 3，leave-one-out 真数字）
为公平测泛化，3DB 用留一法（训练不含被测数据集），与同样没见过这些数据的基线比。结果（PVE/MPJPE，越低越好）：Synthetic CameraHMR 102.8/87.2、PromptHMR 92.7/80.7 → 3DB-H 留一 85.6/75.5、全量 55.2/47.2；Harmony4D CameraHMR 84.6/70.8 → 3DB-H 留一 63.5/54.0、全量 41.0/33.9；SA1B-Hard（Avg-PCK↑）：CameraHMR 63.0、PromptHMR 59.0 → 3DB-H 留一 73.1、全量 76.6。原文："prior work still struggle with these five domains, incurring a significant drop in performance. In contrast, our leave-one-out model shows strong generalization." 还观察到基线"constantly trade places for second"——各自过拟合一小片分布。
④ 手部（Table 4）+ 2D/3D 类别分析（Table 5/6，真数字）
手部 FreiHand（Table 4，PA-MPVPE/PA-MPJPE/F@5）：3DB-H 6.3/5.5/0.735、DINOv3 6.2/5.5/0.737——没在 FreiHand 上训练却已逼近专门手模型（WiLoR 5.1/5.5/0.825、MaskHand 5.4/5.5/0.801）；这是"全身模型也能打手专用模型"的罕见结果。2D 类别（Table 5，SA1B-Hard，aPCK body）：3DB 在全部 24 类全胜，差距最大的是难场景：Camera-bottom-up 69.62 vs 55.18/46.56、Pose-Inverted body 78.18 vs 46.12/39.83、Pose-Leg/arm splits 83.69 vs 57.51/54.76。3D 类别（Table 6，PVE）：pose_3d:very_hard 3DB 114.20 vs CameraHMR 213.66 / PromptHMR 186.35；truncation:severe 126.53 vs 230.51/186.57——硬姿态/截断上优势巨大，作者归因于 data engine 挖来的难样本分布。
④ 用户研究（7800 人，Fig 8 真数字）
6 组成对比较（vs HMR2.0b/CameraHMR/NLF/PromptHMR/SMPLer-X/SMPLest-X），7,800 名独立参与者（每组 1,300）、20,000+ 票，问"哪个 3D 模型更匹配原图"。3DB 胜率（Fig 8，wins/80）：vs HMR2.0b 96.2%、vs CameraHMR 95.0%、vs NLF（最强基线）83.8%、vs PromptHMR 97.5%、vs SMPLer-X 98.8%、vs SMPLest-X 100.0%。原文："Focusing on the strongest baseline, NLF, 3DB achieves a win rate of 83.8%." 摘要里的"5:1 win rate"即此感知质量优势的概括——证明指标提升与人类感知一致。值得注意的是连最强基线 NLF 都被压到 83.8%，而对 SMPLest-X 是 80/80 全胜，说明 3DB 的优势不是"小数点后的指标内卷"，而是普通用户一眼就能看出的重建质量差距。
Q&A · data engine 的"失败驱动闭环"凭什么有效？
问：为什么不直接收集更多数据，而要搞 VLM 挖掘 + 失败分析迭代？答：因为视频/批量数据虽多但冗余——原文："the poses, appearance, imaging conditions, and background might be very similar." 多样性而非数量才是泛化瓶颈。data engine 的妙处是把标注预算花在模型当前最弱处："Mining rules are automatically updated iteratively based on failure analysis of the current model, allowing the engine to adaptively focus on the most challenging or informative samples." 流程闭环——跑 3DB → 找关键点误差最大的图 → 人工几词标注 → 喂 VLM 造 prompt → VLM 从数千万图选同类难例 → 人工精标 → 重训。这等于让"模型的弱点"自动定义"下一批该标什么"，比固定启发式或随机采样高效得多，也直接解释了为何 3DB 在 inverted body / truncation:severe 这些罕见类上碾压基线（这些正是被反复挖出来训的）。
Q&A · 为何强调"留一法"和"细粒度类别评测"？
留一法（leave-one-out）：因为不同方法训练数据不可比（CameraHMR/PromptHMR/NLF 分别训于 6/9/48 个数据集，且 licenses/代码不全），直接比不公平。3DB 用留一（训练剔除被测集）与"同样没见过该集"的基线比，专测真泛化，并另给"全量训练"作上界。原文："This ensures a fair comparison with prior work which have also not seen these datasets." 细粒度类别：传统 benchmark 的单一均值掩盖了"模型在哪类图上崩"。3DB 建 24 个 2D + 28 个 3D 类别（occlusion/truncation/viewpoint/pose 难度/shape/interaction 等），让分析"可解释、可扩展、客观"，从而能指着 truncation:severe、pose_3d:very_hard 说"这里我强 1.6-1.8×"。这种评测方法学本身就是贡献。
🌟 亮点（为何是一篇有分量的系统/数据工作）
① 统一框架同时打 body 与 hand——首个让全身模型的手部逼近手专用 SoTA（FreiHand 未训练仍 5.5 PA-MPJPE）；② 用 MHR 解耦骨架/形状，可解释、可控、利于全身重建；③ VLM 数据引擎 + 多阶段标注（595 dense keypoints + 多视图三角化 + 合成）造 7M 高质量数据，把"难样本"主动挖出来训——这是泛化碾压的根因；④ promptable 设计不仅交互，还用于自我纠错（手腕+肘部互 prompt 修精）；⑤ 评测方法学贡献：建 24 个 2D + 28 个 3D 细粒度类别评测集，能定位模型在"倒立/截断/俯视"等场景的真实强弱，外加 7800 人感知研究。
❓ 疑问 / Limitations（诚实）
① 本质是工程+数据的胜利：模型架构是 SAM 式 promptable encoder-decoder 的成熟范式，真正的护城河是 7M 数据 + data engine + 标注管线，复现门槛高（多视图采集、合成资产、标注团队、VLM 闭环），学术界难照搬。② 依赖外部组件：相机内参靠 MoGe-2 FOV 估计器、初始化靠"当前版 3DB"自举、先验靠学习的 GMM——任一环节失准会传导。③ RICH 上未夺第一（NLF 28.7 vs 3DB 30.9），因 NLF 训练用了 RICH，说明"见过即占优"仍部分成立。④ 手部仍略逊专用模型（F@5 0.735 vs WiLoR 0.825），自由手腕与身体约束的张力未完全消除。⑤ [推测] 失败分析"semi-manually"半人工，规模化与客观性存疑；超参 \(\lambda_i\) 经验设定。⑥ 评测里的"伪 GT"困境：作者自己指出单视图数据集的 pseudo-GT 是"low-fidelity approximations"，所以才建多视图（100+ 相机）评测集——但这也意味着很多历史 benchmark 的绝对数值本身就有噪声，跨论文比较需谨慎。这篇的诚实之处在于：它没有回避"指标提升可能部分来自更干净的标注/评测"，反而用 7800 人感知研究做交叉验证，让"赢"落到人眼可感的程度上。
📌 全文一页总结（problem→method→experiment→takeaway）
problem：单图全身 HMR 在野外（极端姿态/遮挡/视角）不鲁棒，且 body 与 hand 难在统一框架里都做好；根因是数据（高质量 mesh 标注稀缺）+模型（body/hand 优化冲突、SMPL 表示耦合）双瓶颈。
method：3DB = ① 用 MHR（解耦骨架/形状）替代 SMPL；② SAM 式 promptable encoder-decoder，共享 image encoder + body/hand 两路 decoder（式1-10），prompt 还用于自我纠错；③ VLM data engine 主动挖 6 类困难样本 + 多阶段标注（595 dense keypoints/多视图三角化/合成）造 7M 高质量数据。
experiment：5 标准 benchmark SOTA（3DPW 33.2 PA-MPJPE、EMDB/RICH 域外领先），5 新数据集留一法泛化碾压（Synthetic PVE 102.8→85.6），手部逼近专用模型（FreiHand 未训练 5.5），2D/3D 24/28 类全胜（pose_3d:very_hard PVE 114 vs 213），7800 人用户研究 vs 最强 NLF 83.8% 胜率、vs SMPLest-X 100%。
takeaway：全身 HMR 的鲁棒性主要来自"把对的表示（MHR）+ 对的架构（two-way promptable）+ 对的数据（VLM 引擎 7M）"三件事一起做对；可提示设计既是交互入口也是纠错杠杆。代价是工程/数据门槛极高。
