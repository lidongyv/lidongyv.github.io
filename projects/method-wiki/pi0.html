2. 原文引用（5 句英 + 中译）

Q1 · π0 的抽象（一句话说清整篇）

原文： "We propose a novel flow matching architecture built on top of a pre-trained vision-language model (VLM) to inherit Internet-scale semantic knowledge."（Abstract）

中译：我们提出一种新的 flow matching 架构，构建在预训练的视觉-语言模型（VLM）之上，以继承互联网规模的语义知识。

Q2 · 为什么要动作块 + flow

原文： "we use an action chunking architecture with flow matching (a variant of diffusion) to represent complex continuous action distributions. This enables our model to control robots at frequencies of up to 50 Hz for dexterous tasks such as laundry folding"（Introduction）

中译：我们使用带 flow matching（扩散的一个变体）的动作块架构来表示复杂的连续动作分布。这使我们的模型能在叠衣服这类灵巧任务上以最高 50 Hz 的频率控制机器人。

Q3 · 关键部件

原文： "To combine flow matching with VLMs, we use a novel action expert that augments the standard VLM with flow-based outputs."（Introduction）

中译：为了把 flow matching 与 VLM 结合，我们用一个新颖的 action expert，为标准 VLM 增补了基于 flow 的输出。

Q4 · π0.5 的抽象

原文： "We describe π0.5, a new model based on π0 that uses co-training on heterogeneous tasks to enable broad generalization."（Abstract）

中译：我们描述 π0.5，一个基于 π0 的新模型，它通过对异构任务的协同训练来实现广泛泛化。

Q5 · π0.5 的分层推理

原文： "At runtime, during each step of inference, the model first predicts the semantic subtask, inferring the behavior that is appropriate to perform next based on the task structure and the semantics of the scene, and then predicts the low-level robot action chunk based on this subtask."（Introduction）

中译：运行时，在每一步推理中，模型先预测语义子任务——基于任务结构与场景语义推断下一步该做什么行为——然后基于这个子任务预测低层机器人动作块。

这 5 句给出整条演化链：VLM 继承语义 → 动作块 + flow 表示连续多模态动作 → action expert 把两者焊在一起 → π0.5 换成异构协同 → 推理改成「先想子任务再出动作」。

3. Problem

3.1 π0：三个瓶颈同时挡路

原文： "However, developing such generalist robot policies — i.e., robot foundation models — involves a number of major challenges. First, any such research must be done at a very large scale, because the full benefits of large-scale pre-training are often not present at smaller scales. Second, it requires developing the right model architectures that can effectively make use of diverse data sources, while at the same time being able to represent the intricate and subtle behaviors necessary to interact with complex physical scenes. Third, it requires the right training recipe."（Introduction）

中译：然而，开发这类通用机器人策略——即机器人基础模型——涉及若干主要挑战。第一，这类研究必须在非常大的规模上做，因为大规模预训练的好处往往在小规模上并不成立。第二，需要正确的模型架构，既能有效利用多样数据源，又能表示与复杂物理场景交互所需的精细微妙行为。第三，需要正确的训练配方。

原文： "Training only on high-quality data does not teach the model how to recover from mistakes, since mistakes are rarely seen in such data. Training on only lower-quality pre-training data does not teach the model to act efficiently and robustly."（Introduction）

中译：只用高质量数据训练，教不会模型如何从错误中恢复，因为这类数据里几乎看不到错误。只用较低质量的预训练数据训练，教不会模型高效、鲁棒地行动。

问题本质：机器人领域缺的不是「一个更好的策略网络」，而是三件套（规模 / 架构 / 配方）。π0 的赌注是：把 NLP 的「预训练 + 后训练」两段式搬到机器人上，用 VLM 补语义、用大规模多机器人数据补覆盖、用高质量小数据补「流畅与鲁棒」。

3.2 π0.5：从「实验室泛化」到「别人家的厨房」

原文： "Open-world generalization represents one of the biggest open problems in physical intelligence: embodied systems such as robotic arms, humanoids, and autonomous vehicles only truly become useful when they can leave the lab and handle the diverse situations and unexpected events that occur in the real world."（Introduction）

中译：开放世界泛化是物理智能最大的开放问题之一：机械臂、人形、自动驾驶等具身系统只有走出实验室、能处理真实世界里多样情境与意外事件时，才真正有用。

原文： "However, the diversity of situations that a robot might encounter in the real world requires more than just scale: we need to design training recipes that can provide the breadth of knowledge that will allow robots to generalize at many levels of abstraction."（同段）

中译：然而，机器人在真实世界可能遇到的情境多样性，要求的不只是规模：我们需要设计训练配方，提供足够广博的知识，使机器人能在多个抽象层级上泛化。

为什么「刷数据」在这里失效：擦一个陌生厨房涉及三类不同泛化——① 已充分覆盖的技能（抓盘子）；② 已有技能的新组合/新用法；③ 纯语义推断（哪个抽屉该开、台面上哪个东西最可能是沥水架）。第三类不可能靠在更多房子里采更多轨迹来覆盖，只能从非机器人数据里迁移。这就是 π0.5 的全部动机。

4. Core idea

4.1 π0：VLM 出语义，flow 出连续动作，中间用 action expert 隔开

原文： "π0 uses conditional flow matching to model the continuous distribution of actions. Flow matching provides our model with high precision and multimodal modeling capability, making it especially well suited to high-frequency dexterous tasks."（IV The π0 Model）

中译：π0 使用条件 flow matching 来建模动作的连续分布。Flow matching 为模型提供了高精度与多模态建模能力，使其特别适合高频灵巧任务。

原文： "π0 is implemented as a single transformer with two sets of weights (also known as experts), where each token is routed to one of the experts; the weights interact only through the transformer's self-attention layers."（Appendix A-B）

中译：π0 实现为单个 transformer 但带两套权重（也称专家），每个 token 被路由到其中一个专家；两套权重只通过 transformer 的自注意力层交互。

一句话核心：不是「VLM 输出动作」，而是「VLM 输出条件，另一个小专家在连续空间里用去噪的方式生成动作块」。这避免了把高维连续动作离散成 token 再自回归（OpenVLA 路线在高维人形上会遇到的扩展问题）。

4.2 π0.5：同一套权重，先写字再动手

原文： "The π0.5 architecture can flexibly represent both action chunk distributions and tokenized text outputs, with the latter used both for co-training tasks (e.g., question-answering) and for outputting high-level subtask predictions during hierarchical inference."（IV-A）

中译：π0.5 架构能灵活表示动作块分布与词元化的文本输出，后者既用于协同训练任务（如问答），也用于分层推理时输出高层子任务预测。

原文： "πθ(a(t:t+H), ℓ̂ | o_t, ℓ) = πθ(a(t:t+H) | o_t, ℓ̂) · πθ(ℓ̂ | o_t, ℓ)"（IV-A 式；论文原式为下标记法 a 下标 t 冒号 t+H，本页统一改成括号记法 a(…)，含义不变，避免花括号占位）

中译：给定观测 o_t 与总指令 ℓ，动作块与文本输出 ℓ̂ 的联合分布，可分解为「给定子任务出动作」×「给定总指令与观测出子任务」。

一行物理意义：把「做什么」和「怎么动」显式拆成两次前向，但共享同一套权重与同一段上下文——所以它既不是两个模型（如 SayCan 的 VLM 规划器 + 独立策略），也不是纯端到端（如图 π0 直接出动作）。论文强调 “the high-level inference process still runs at a lower frequency than low-level action inference”，即慢的那一层负责结构，快的那一层负责精度。

5. 架构细节

5.1 规模：3B VLM + 300M 专家 = 3.3B

原文： "we use PaliGemma as our base model. PaliGemma is an open-source 3 billion parameter VLM that offers a convenient tradeoff between size and performance. We add 300M parameters for the action expert (which is initialized from scratch) for a total of 3.3 billion parameters."（IV）

中译：我们以 PaliGemma 作为基座。PaliGemma 是一个开源、30 亿参数的 VLM，在规模与性能之间提供了便利的折中。我们为 action expert 增加 300M 参数（从零初始化），总计 33 亿参数。

原文： "PaliGemma is based on the Gemma 2B language model, which uses multi-query attention and a configuration of width=2048, depth=18, mlp_dim=16,384, num_heads=18, num_kv_heads=1, head_dim=256. … To speed up inference (which requires multiple forward passes of the action expert), we downsize the action expert to width=1024, mlp_dim=4096, resulting in a parameter count of ~300M."（Appendix A-B）

中译：PaliGemma 基于 Gemma 2B 语言模型，使用 multi-query attention，配置为 width=2048, depth=18, mlp_dim=16,384, num_heads=18, num_kv_heads=1, head_dim=256。……为加速推理（action expert 需要多次前向），我们把 action expert 缩小到 width=1024, mlp_dim=4096，参数量约 300M。

部件配置参数量为什么是这个尺寸
VLM 骨干width 2048 / depth 18 / mlp 16384 / 18 heads / 1 KV head / head_dim 2563B（PaliGemma 总参；语言骨干为 Gemma 2B）要装下互联网级语义；每次观测只跑 1 次，可以慢
action expertwidth 1024 / mlp 4096，其余同构~300M要在一次推理里跑 10 遍 → 必须小；论文明确写 “To speed up inference”
总参数两者只通过 self-attention 交互3.3Bwidth/mlp 不必对齐，因为专家之间不共享 FFN

5.2 序列与注意力：三个 block，动作 token 双向

原文： "π0 uses a blockwise causal attention mask with 3 blocks: … Within each block, there is full bidirectional attention, whereas the tokens in each block cannot attend to the tokens in future blocks."（Appendix A-B；原文三个 block 依次为「图像 + 语言提示」「本体状态」「噪声动作」，数组下标展开用省略号略去）

中译：π0 使用 3 个 block 的分块因果注意力掩码：图像与语言提示、状态、噪声动作。每个 block 内部是全双向注意力，而每个 block 的 token 不能注意未来 block 的 token。

原文： "The action expert uses a full bidirectional attention mask, so that all action tokens attend to each other."（IV）

中译：action expert 使用完全双向的注意力掩码，使所有动作 token 互相可见。

三个 block 各自的物理理由：① 图像/语言放第一个 block 且不看向后两个 → 保持与 PaliGemma 预训练时的分布一致，减少分布漂移；② 状态单独一个 block → 它在 10 次去噪迭代中不变，单独分块后其 K/V 可缓存；③ 噪声动作 block 可以看见前面全部 → 动作生成必须条件化在观测上，且 50 个动作 token 之间要互相协调（例如两手不能同时伸向同一处）。

5.3 动作块与积分步数

原文： "Formally, we want to model the data distribution p(A_t | o_t), where A_t … corresponds to an action chunk of future actions (we use H = 50 for our tasks), and o_t is an observation."（IV；省略号处原文为动作块数组 50 个元素的下标展开，本页略去以免下标记法写成花括号）

中译：形式上我们要建模 p(A_t | o_t)，其中 A_t 是未来动作的动作块（我们的任务取 H = 50），o_t 是观测。

原文： "At inference time, we generate actions by integrating the learned vector field from τ=0 to τ=1, starting with random noise … We use 10 integration steps (corresponding to δ=0.1) in our experiments."（IV）

中译：推理时，我们从随机噪声出发，把学到的速度场从 τ=0 积分到 τ=1 来生成动作……实验中我们用 10 个积分步（对应 δ=0.1）。

注意一个易错点：论文用 τ=0 是噪声、τ=1 是动作；而 openpi 代码的约定相反（t=1 是噪声、t=0 是目标，源码注释里作者自己写了 “yes, this is the opposite of the pi0 paper, and I'm sorry.”）。读公式与读代码时必须先确认约定，否则符号会全反。

5.4 时间步采样：偏「高噪声」而不是偏「中间」

原文： "we hypothesized that the task of action prediction is subtly different from high-resolution image synthesis — while it may be relatively easy to predict the mean image conditioned on a text label, predicting the mean action conditioned on a robot observation (i.e., learning E[A_t | o_t]) is a much harder problem; this is because the observation o_t is very informative in that it should constrain the distribution of possible actions much more than a text label constrains the distribution of possible images. As a result, we designed a timestep sampling distribution that emphasizes low timesteps (high noise levels) … The distribution is given by p(τ) = Beta((s−τ)/s; 1.5, 1) … We use s = 0.999 in our experiments, which allows for δ > 1/1000, or up to 1,000 integration steps."（Appendix A-B）

中译：我们假设动作预测任务与高分辨率图像合成有微妙差异——给定文本标签预测「平均图像」可能相对容易，而给定机器人观测预测「平均动作」（即学 E[A_t | o_t]）要难得多；因为观测 o_t 信息量很大，它对可能动作分布的约束远强于文本标签对图像分布的约束。因此我们设计了一个强调低时间步（高噪声）的采样分布……分布为 Beta((s−τ)/s; 1.5, 1)……实验取 s = 0.999，允许 δ > 1/1000，即最多 1,000 个积分步。

一句话物理意义：动作分布的「均值」本身就有意义（它是对观测最合理的动作），所以要在高噪声端多采样、把均值学好；而图像生成的均值常常是模糊的平均图，无意义，所以常见做法偏中间步。这是 π0 与图像扩散在训练分布上的关键差异。

5.5 π0.5 的三处改动

改动原文依据为什么
状态从连续输入变成离散文本 token“The robot proprioceptive state is discretized and input to the model as text tokens.”（IV-A）让状态进入 VLM 的语言通道，从而能在预训练阶段（纯自回归、无 action expert）也被用到
时间步用独立 MLP + adaRMSNorm 注入“Unlike π0 that fuses the flow-matching timestep τ with the noisy action before being fed into the transformer, π0.5 uses a separate MLP for projecting τ only and then applies adaptive RMSNorm to inject the timestep information to each layer of the action expert.”（Appendix A-E）τ 不再占动作 token 的通道，动作 token 只表示动作；调制改为逐层进行
动作有两种表示共存：FAST 离散 token + flow 连续“We use the attention matrix to ensure that the different action representations do not attend to each other.”（IV-B）预训练用离散（可自回归、训练快），推理用连续（非自回归、10 步出块）；两种表示互相遮蔽以防信息泄漏

π0.5 的动作块长度：正文 IV-E 与 Appendix A-E 写 “action horizon of 50, i.e. H = 49”。这是论文自身的表述矛盾（50 与 49 同时出现）；openpi 配置里 action_horizon=50。引用时建议写「H≈50，论文 A-E 处出现 50/49 两种写法」。

6. 训练

6.1 π0 的数据混合：9.1% 开源 + 903M 自有步

原文： "9.1% of the training mixture consists of open-source datasets, including OXE, Bridge v2, and DROID. The robots and tasks in these datasets typically have one or two cameras and use low-frequency control, between 2 and 10 Hz. However, these datasets cover a wide range of objects and environments. To learn dexterous and more complex tasks, we also use 903M timesteps of data from our own datasets, where 106M steps are from single-arm robots and 797M are from dual-arm robots. This data has 68 tasks"（V-A）

中译：训练混合中 9.1% 是开源数据集，包括 OXE、Bridge v2、DROID。这些数据集的机器人通常有 1–2 个相机、控制频率较低（2–10 Hz），但覆盖了大量物体与环境。为学习灵巧且更复杂的任务，我们还用了自有数据集的 903M 时间步，其中 106M 来自单臂机器人、797M 来自双臂机器人，共 68 个任务。

原文： "Since the datasets are somewhat imbalanced in size (e.g., the more difficult laundry folding tasks are overrepresented), we weight each task-robot combination by n^0.43, where n is the number of samples for that combination, such that over-represented combinations are down-weighted."（V-A）

中译：由于数据集在规模上有些不平衡（例如更难的叠衣任务被过度表示），我们按 n^0.43 对每个「任务-机器人」组合加权，n 是该组合的样本数，从而把过度表示的组合降权。

原文： "The configuration vector q_t and action vectors a_t always have the dimensionality of the largest robot in the dataset (18 in our case, to accommodate two 6-DoF arms, 2 grippers, a mobile base, and a vertically actuated torso). For robots with lower-dimensional configuration and action spaces, we zero-pad the configuration and action vectors."（V-A）

中译：配置向量 q_t 与动作向量 a_t 始终取数据集中最大机器人的维度（本文为 18：两条 6-DoF 臂 + 2 个夹爪 + 移动底座 + 竖直升降躯干）。对维度更低的机器人，用零填充配置与动作向量。

n^0.43 是什么意思：若某组合样本量是另一组合的 10 倍，其原始权重高 10 倍，加权后只高 10^0.43 ≈ 2.7 倍。这是一条「温和的平方根级」重加权——比取平方根（n^0.5）更弱，目的是不让最多数的数据支配梯度，同时不把稀缺的高质量任务压没。

6.2 语言标注的粒度：2 秒一段

原文： "The pre-training phase also uses diverse language labels, combining task names and segment annotations (fine-grained labels for sub-trajectories, typically about 2 seconds in length)."（III Overview）

中译：预训练阶段还使用多样的语言标签，结合了任务名与分段标注（对子轨迹的细粒度标签，通常约 2 秒长）。

为什么是 2 秒：50Hz 下 2 秒 = 100 个控制步 ≈ 2 个动作块（H=50）。也就是说语言标签的粒度与动作块的粒度同量级——这样一条指令对应一个可执行的「动作单元」，而不是一整段长任务。这是 π0 能做「语言跟随」实验（每条指令对应一个抓取/放置）的数据基础。

6.3 π0.5 的两段训练：280k 离散 + 80k 连续

原文： "After pre-training the model with discrete tokens for 280k gradient steps, we perform a second stage of training that we refer to as post-training."（IV-D）

中译：在用离散 token 预训练 280k 个梯度步之后，我们进行第二段训练，称之为后训练。

原文： "We optimize the objective in Equation (1), with α = 10.0 for 80k additional steps."（IV-D）

中译：我们优化式 (1) 的目标，取 α = 10.0，再训练 80k 步。

原文： "This scheme enables us to first pre-train our model as a standard VLM transformer model by mapping actions to text tokens (α = 0), and then add additional action expert weights predicting continuous action tokens in a non-autoregressive fashion for fast inference in a post-training stage."（IV-B）

7. 部署与推理

7.1 π0：开环执行动作块，故意不做时间集成

原文： "Since the model generates an entire H-step action chunk at once, we can execute up to H actions before we need to run inference again. However, we may run inference more often than that… We tried temporal ensembling early on and found that it hurt policy performance, so we opted not to aggregate actions and instead execute action chunks open-loop. For the 20Hz UR5e and Franka robots, we run inference every 0.8 seconds (after executing 16 actions), and for all other robots, which run at 50Hz, we run inference every 0.5 seconds (after executing 25 actions)."（Appendix A-D）

中译：由于模型一次性生成整个 H 步动作块，我们在需要再次推理前最多可执行 H 个动作。但我们可能比这更频繁地推理……我们早期尝试过时间集成（temporal ensembling），发现它损害策略性能，因此选择不聚合动作，而是开环执行动作块。对 20Hz 的 UR5e 与 Franka，我们每 0.8 秒推理一次（执行 16 个动作后）；对其他 50Hz 机器人，每 0.5 秒推理一次（执行 25 个动作后）。

一行物理意义：H=50 给出 1 秒的动作（50Hz 下），但只执行 25 步（0.5 秒）就重规划——用一半的块长换取对外界变化的响应；剩下的半块是「保险」，不是浪费，因为重规划会覆盖它。

7.3 π0.5：4 相机分层 + 极简控制栈

原文： "The control system is very simple: the π0.5 model directly commands target poses for the arms, gripper, and torso lift, and the target base velocities at 50 Hz (with action chunking). 中译：控制系统非常简单：π0.5 模型直接指令手臂、夹爪、躯干升降的目标位姿，以及 50 Hz 的底座目标速度（带动作块）。这些目标由简单的 PD 控制器跟踪，没有任何额外的轨迹规划或碰撞检测。所有操作与导航控制完全端到端。

原文： "We use all four cameras for high-level inference, and the wrist and forward cameras for the low-level inference process. The total dimensionality of the state and action spaces is 18 or 19, depending on the platform."（IV-E）

中译：高层推理使用全部四个相机（前、后、双腕），低层推理只用腕部与前向相机。状态与动作空间总维度为 18 或 19，取决于平台。

为什么两层用不同相机：高层要「看全局」（后方相机决定往哪走、哪个抽屉在哪），低层要「看手」（腕相机给接触几何、前向相机给接近方向）。这是把算力花在刀刃上：4 相机 token 数更多，只跑低频；2 相机只跑高频。

9. 公式 + 物理意义 + 映射到代码

式 1 · 条件 flow matching 训练目标（π0 IV 逐字）

L^τ(θ) = E over p(A_t|o_t)、q(A_t^τ|A_t)：‖ v_θ(A_t^τ, o_t) − u(A_t^τ | A_t) ‖²，u = A_t − ε，A_t^τ = τ·A_t + (1−τ)·ε，ε ~ N(0, I)

一行物理意义：网络要学的不是「动作本身」，而是「把噪声推回示教动作块的速度方向」——同一个网络对所有噪声等级都给出指向动作的速度，因此天然能表示多模态（多个合理抓法各自成流）。

路径：q(A_t^τ | A_t) = N(τ·A_t, (1−τ)·I)（线性高斯 / 最优传输路径，π0 IV 逐字给出）。

式 2 · 推理：前向 Euler 积分（π0 IV 逐字）

A_t^(τ+δ) = A_t^τ + δ·v_θ(A_t^τ, o_t)，A_t^0 ~ N(0, I)，δ = 0.1，共 10 步

一行物理意义：从纯噪声出发沿学到的速度场走 10 小步，落到一个「既符合观测、又像示教」的动作块上；10 步是精度与延迟的折中点（Table I 实测 27 ms）。

式 3 · π0.5 联合目标（π0.5 式 1 逐字）

E over D、τ、ω：[ H(x(1:M), f^ℓ_θ(o_t, ℓ)) + α‖ω − a(t:t+H) − f^a_θ(a(t:t+H)^(τ,ω), o_t, ℓ)‖² ]，α = 10.0

一行物理意义：同一个 transformer 同时被两件事监督——文本（含子任务与 FAST 动作 token）走交叉熵，连续动作走 flow 回归；α 是「动作精度」相对「语言能力」的权重（论文取 10.0，说明后训练阶段重心明显偏向动作）。

式 4 · 分层分解（π0.5 IV-A 逐字）

πθ(a(t:t+H), ℓ̂ | o_t, ℓ) = πθ(a(t:t+H) | o_t, ℓ̂) · πθ(ℓ̂ | o_t, ℓ)

一行物理意义：动作给定子任务后与总指令条件独立——所以「换说法但同一子任务」不会改变动作，这让语言条件的泛化与动作执行解耦。

10.4 结论

π0：证明的是「架构 + 配方」而非单点技巧——在 out-of-box 与微调两类设定上，同时赢过自回归 VLA（OpenVLA）与扩散基线（Octo），且用 1/4.4 的训练步数（160k vs 700k）仍领先。最有说服力的对照是 π0-small：同样的数据、更小的模型、无 VLM 初始化 → 全面更差，说明「VLM 预训练 + 大容量 + flow」三者缺一不可。

π0.5：证明的是「异构协同」——在 97.6% 训练样本都不来自目标机器人的前提下，仍能在全新家庭完成长程清洁；且 π0-FAST+Flow（已补齐 flow、只缺 HL/WD）仍不如它，把增益精确定位到数据构成而非动作表示。这比「我们更大更强」有信息量得多。

但要警惕：两篇论文的关键结果都在图里，没有表格；跨论文比较「谁成功率更高」缺乏共同的评测协议（任务不同、评分尺度不同、试次少）。正确的引用方式是引用它们各自的受控对照（表内相对差），而不是引用绝对成功率。

                                                        # p(τ)=Beta(·;1.5,1) 截断到 (0.001,1)：偏大噪声端采样

u_t = noise - actions                                   # 目标速度场：从动作指向噪声的反方向

prefix_tokens, prefix_mask, prefix_ar_mask = self.embed_prefix(observation)
                                                        # 图像 patch + 语言：走 3B VLM，每步观测只算一次
suffix_tokens, suffix_mask, ar_mask, adarms_cond = self.embed_suffix(observation, x_t, time)
                                                        # 状态 1 token + 动作 50 token，宽度 1024；τ 经 MLP 注入

x_0, _ = jax.lax.while_loop(lambda c: c[1] >= -dt / 2, step, (noise, 1.0))
                                                        # 循环到 t≈0：10 步后得到动作块

为什么 kv_cache 是性能关键：prefix 3B 前向 32 ms 只做一次，10 步循环里只跑 300M 专家（合计 27 ms）。若不做缓存，10 步 × 32 ms = 320 ms，50Hz 部署直接不可行——这就是论文说「inference can be implemented efficiently by caching the attention keys and values for the prefix」的实际含义。

12.1 论文自述局限（逐字）

π0 原文： "our experiments do not yet provide a comprehensive understanding of how the pre-training datasets should be composed: we combined all data available to us, but understanding what type of data is more helpful to add and how it should be weighted remains an open problem. Not all tasks in our evaluation work reliably, and it remains unclear how to predict how much and what kind of data is needed to attain near-perfect performance."（VII）

中译：我们的实验还没有给出「预训练数据该如何构成」的完整理解：我们把手上所有数据都合在一起了，但弄清「哪类数据更有帮助、该如何加权」仍是开放问题。我们评估中的任务并非都可靠可复现，也仍不清楚如何预测「要达到近完美性能需要多少、何种数据」。

π0.5 原文： "While our VLA exhibits broad generalization, it still makes mistakes. Some environments present persistent challenges (e.g., unfamiliar handles on drawers, or cabinets that are physically hard for the robot to open), some behaviors present challenges with partial observability (e.g., the robot arm occluding a spill that should be wiped), and in some cases the high-level sub-task inference is easily distracted (e.g., closing and opening a drawer multiple times while putting away items)."（VI）

中译：虽然我们的 VLA 展现了广泛泛化，它仍会犯错。有些环境带来持续挑战（如不熟悉的抽屉把手、机器人物理上难以打开的柜门）；有些行为存在部分可观测问题（如机械臂挡住了本该擦掉的污渍）；还有些情况下高层子任务推断容易被干扰（如收纳物品时反复开合同一个抽屉）。

π0.5 原文： "The model also uses a relatively modest context, and incorporating richer context and memory could make the model significantly more capable in settings with more partial observability, such as tasks that require navigating between different rooms or remembering where objects are stored."（VI）

中译：该模型的上下文也相对有限；引入更丰富的上下文与记忆，可以显著提升模型在部分可观测更强的场景中的能力，例如需要在不同房间之间移动、或需要记住物体存放位置的任务。

13. Q&A（追问 why，带数值或反例）

Q1：为什么不用自回归离散动作（OpenVLA 路线），非要 flow？

数值：H=50 的动作块若离散化，需要串行解码 50 步；flow 只需 10 步并行（实测这 10 步共 27 ms）。串行长度差 5 倍，且每步都要跑一次网络前向——50Hz 下 20 ms 的动作预算会被直接吃穿。论文的实测对照：OpenVLA 在同一预训练混合上“struggles on these tasks because its autoregressive discretization architecture does not support action chunks”（VI-A），即便是只训 160k 步的 π0 也全面赢它。反例边界：若动作维度很低（比如只有 1 个二值夹爪），离散化完全够用，flow 的收益就不明显——这正是论文说 prior VLA 在低维控制（如二值平行夹爪）上有一些成功的原因。

Q2：为什么 action expert 只有 300M，而不是也给 3B？

数值：一次推理里 prefix 跑 1 次（32 ms），专家跑 10 次（27 ms）。若专家也是 3B（≈10 倍），这 10 步会膨胀到约 270 ms 量级（按参数量线性外推，量级估算），加上 prefix 32 ms + 编码 14 ms，单次推理超过 300 ms；50Hz 下 0.5 秒的执行窗口只剩不到 40% 余量，20Hz 的 UR5e（0.8 秒窗口）也接近极限。why：专家的计算被「放在最内层循环」——它的成本要乘以积分步数，所以必须小；而 VLM 的计算在循环外，可以大。这条「非对称分工」是整个设计的经济学基础。

Q3：时间步为什么偏「高噪声」采样，而不是像图像扩散那样偏中间？

why：高噪声端（τ 小）对应「几乎纯噪声 → 动作均值」的映射。图像生成里这个均值是模糊的平均图，没意义；但动作里 E[A_t | o_t] 是「给定观测下最合理的动作」，本身就很有用。所以要多采样。反例：若按 logit-normal 偏中间采样（图像扩散常用），τ 小的一端样本稀疏，模型学不好「从纯噪声一步跳到合理动作」，10 步积分的前 2–3 步就会生成明显偏离的动作块——而 π0 只有 10 步可用，没有纠错余地。论文用一个具体参数把这件事钉死：s = 0.999（保证 δ 可小到 1/1000，即最多 1000 步，但实际只用 10 步）。

Q4：π0.5 为什么非要「先离散预训练、再连续后训练」两条腿？直接全程 flow 不行吗？

why：两个效率约束方向相反。训练端：FAST 把动作块压成离散 token 后，训练是标准 next-token 预测，可复用 VLM 的成熟配方，稳定且快（论文：α=0 阶段 280k 步）。推理端：离散表示要自回归解码 50 步，太慢；连续 flow 非自回归，10 步出块。所以「训练用离散、推理用连续」。反例（论文自己做的）：π0-FAST+Flow 就是这个混合配方、但只用动作数据训练 → 仍然不如 π0.5，说明「混合表示」本身不是增益来源，HL + WD 数据才是。同时论文还给出更强的一条：把 π0 训到 300k 步仍不如 π0.5 —— 排除了「只是训练更久」的解释。

Q5：为什么 π0.5 的高层预测能超过人类 oracle？

论文事实：“the full π0.5 model performs the best, and outperforms even the human HL 'oracle' baseline”（V-E）。本页推断（非原文）：人类 oracle 给的是「人认为对的子任务」，但不保证低层策略执行得了——比如人看到污渍会说「擦掉它」，而低层策略可能从未学过擦拭动作；模型预测的子任务则是在同一批机器人数据上训练出来的，天然落在「低层已具备的能力集合」内。换言之，高层与低层共享权重与数据分布，等于自带「可执行性约束」；人类 oracle 没有这个约束。佐证：论文同时报告 implicit HL（不做高层推理、但训练里含子任务数据）是第二好（V-E），说明收益一部分来自「子任务标注提供的结构信息」，而不只是运行时的显式规划。这也解释了为什么 no VI 只去掉 11% 的数据却显著变差——语言示范教会了模型「怎么把技能拆成可执行步骤」。

14. 全文总结（problem → method → experiment → takeaway）

环节π0π0.5
Problem机器人基础模型同时缺规模、缺架构、缺配方；纯高质量数据学不会纠错，纯预训练数据学不会流畅开放世界泛化：真实家庭的语义长尾无法靠「在更多房子里采更多轨迹」覆盖
MethodPaliGemma 3B + 300M action expert（单 transformer 双专家）+ 动作块 H=50 + 条件 flow matching + 10 步 Euler；两段式预训练/后训练同架构，但预训练用 FAST 离散 token 自回归（280k 步），后训练加 flow 专家（80k 步，α=10）；数据换成 MM/ME/CE/HL/WD 异构协同 + VI 语言示范；推理分「先出子任务、再出动作块」

Takeaway「VLM 出条件、flow 出连续动作块」是高频灵巧操作的可用形态；关键是让两个专家只通过 self-attention 交互，且把贵的前向放进循环外泛化的瓶颈不是机器人数据量，而是知识的异构性；在目标形态数据只占 2.4% 时，跨构型 + 网页 + 子任务标注 + 语言示范才是泛化的真正来源
