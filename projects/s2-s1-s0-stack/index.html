0. 先看总图：一条链路

读图顺序：从下往上看（S0 是地基），从上看下看（S2 是意图）。三层各自独立开发，用接口解耦。

1. 为什么必然分三层：三个物理约束

约束数字推论
大模型推理慢VLM 单次 50–200ms（云更慢）；VLA 输出 1–5Hz不能直接闭环控制；只能出「意图/子目标」
控制需要快平衡/接触需 50–200Hz；力矩环 1kHzS1 必须机载、低延迟；S0 在驱动器内闭环
物理安全力矩/速度/姿态超限需 ms 级切断安全层必须在 S0 独立实现，不能依赖 S1/S2
一句话：S2 决定「做什么」，S1 决定「怎么做」，S0 保证「做得动、不出事」。

2.4 S0（物理层）

选项实现优点缺点
推荐 关节 PD + 限幅Kp/Kd + 力矩/速度/位置限幅简单可靠、所有机器人标配接触柔顺一般
阻抗控制M(q)q̈ + C + G + K(q−q*) + Dq̇ = τ接触友好、可调柔顺需动力学模型
串联弹性/被动顺应弹性关节、足底橡胶、柔性件抗冲击、省控制带宽低、设计复杂
纯力矩控制力矩环最柔顺需高精度力矩传感

4. S0 实现：物理层的代码与物理意义

4.1 关节 PD（最常用）

# 每个关节、每 1ms 执行一次（驱动器内）
# q: 当前位置(rad)  qd: 当前速度(rad/s)  q_des: S1 给的目标位置
tau = Kp * (q_des - q) - Kd * qd + tau_ff      # 单位 N·m
tau = clamp(tau, tau_min, tau_max)             # 保护减速器
motor.set_torque(tau)
# 物理意义：
#   Kp: 刚度——越大跟得越紧，但太大激起结构共振/振荡（典型 20–200 Nm/rad，按关节调）
#   Kd: 阻尼——抑制超调；太小欠阻尼抖动，太大迟滞（典型 0.5–5 Nms/rad）
#   tau_ff: 重力/摩擦前馈——减小稳态误差，让 PD 不必靠大 Kp 硬顶
#   限幅：保护齿轮箱；遇到撞击时靠饱和+柔顺吸收能量

4.2 阻抗控制（需要接触时）

# 笛卡尔/关节空间阻抗：M q̈ + C(q,q̇) + G(q) + K(q−q*) + D q̇ = τ_ext + τ
tau = M @ qdd_des + C @ qd + G + K @ (q_des - q) + D @ (qd_des - qd)
# 物理意义：M/C/G 补偿机器人自身动力学；K/D 设定「弹簧-阻尼」手感
#   K 小 → 柔顺（易被推、适合接触）；K 大 → 刚性（精确但危险）

4.3 安全层（必须独立）

# 与 S1 不同进程/不同看门狗；1kHz 检查
if abs(tau) > tau_limit or abs(qd) > vel_limit or imu.tilt > tilt_limit:
    motor.disable()                 # 硬件级切断，不等上层
if now - last_cmd_ts > 200ms:       # 上层失联
    enter_damping_mode()             # 只保留阻尼，缓慢停下

4.4 S0 的「选型」怎么定

  • 有足底接触/人形：关节 PD + 足底橡胶（被动顺应）+ 力矩限幅；必要时加阻抗。
  • 臂/手做精细接触：阻抗或力控；末端六维力传感器。
  • 高动态（跑跳）：低延迟力矩环 + 轻量腿（降低惯量）；PD 增益随相位调度。
  • 低成本：纯位置 PD + 机械限位 + 电流限幅，不追求力控。

5. S1 实现：快控制层

5.1 推理循环（50Hz）

# 50Hz = 20ms 周期；jitter 要 < 2ms，否则策略抖动
while True:
    t0 = now()
    obs = read_proprio()                 # q, qd, imu(roll/pitch/yaw, gyro), last_action
    tok = token_buf.consume_fresh(now()) # 或 ref = planner.latest()
    q_des = policy(obs, tok)             # [n_joints]，网络输出
    q_des = rate_limit(q_des, q_des_prev, max_dq)   # 限速，防突变
    publish(q_des, ts=now())
    sleep_until(t0 + 20ms)

5.2 RL 跟踪训练（SONIC 式）

# 仿真：IsaacLab，4096 并行环境，PPO
for it in range(100_000):
    for t in range(32):
        enc = sample_encoder()           # robot / smpl / teleop
        tok = FSQ(Encoder[enc](obs_tokenizer))
        a   = Decoder_dyn(tok, proprio)  # 关节目标
        obs, r, done = env.step(a)       # PD 在仿真里同样存在
    # 奖励：跟踪根/连杆位姿+速度 − 动作突变/足部加速度惩罚
    # 域随机化：摩擦/恢复系数/质心/推搡/指令扰动

5.3 选型建议

  • 要通用、可跨任务：RL 跟踪器（SONIC），一次训练多任务复用。
  • 要极致低延迟：小 visuomotor（Helix S1 80M，200Hz）+ latent 接口。
  • 要单模型端到端：VLA 动作头（DiT flow matching），频率降到 10–50Hz，配动作 chunk。
  • 约束硬/可解释：MPC/WBC，但接触任务弱。

6. 接口实现：时间戳与延迟补偿（最容易翻车的地方）

# S2 出 token，带时间戳；S1 只取「未过期」的最新一个
class TokenBuffer:
    def push(self, tok, ts): self.buf.append((tok, ts))
    def consume_fresh(self, now, max_age_ms=400):
        tok, ts = self.buf[-1]
        if now - ts > max_age_ms:
            return None          # 过期：上层保持/停止，别用旧意图
        return tok
# 物理意义：S2 周期 400ms；max_age 取 1–2 个周期。用旧 token = 执行「过去的意图」，会滞后甚至撞。

# 位姿接口（3 点 VR 格式）：头/双腕位姿 + 腰高 + 导航速度
cmd = {"head": SE3, "lwrist": SE3, "rwrist": SE3,
       "waist_h": 0.45, "v": 0.6, "w": 0.2}
# 下半身由运动规划器补全：autoregressive，0.8–2.4s 段，100ms 重规划

延迟补偿三件套

  1. 训练镜像部署：训练时给 S1 输入加时间偏移 = 部署推理延迟（Helix 做法）。
  2. 时间戳对齐：所有信号统一时钟；token 按采集时刻而不是到达时刻打戳。
  3. 插值/外推：S0 按当前时刻在相邻目标间插值，避免阶跃。

7.3 选型建议

  • 任务固定、要稳：VLA 微调（GR00T N1.7 / π0.5）。
  • 指令开放、任务多变：VLM 规划器 + 子任务接口。
  • 需要想象/验证：WAM（GR00T 2 式）+ agent。
  • 要最低成本：VLM 只出「目标点/抓取点」，S1 用现成 RL 控制器执行。

8. 备选方案：五种常见组合

组合结构优点缺点适合
A 端到端双系统（Helix）S2 VLM 7–9Hz → latent 向量 → S1 80M 200Hz延迟小、一致性好需大量遥操作；S1 难复用产品化人形
B 分层+潜动作（SONIC/GR00T）推荐S2 出 64 维 token → S1 预训练全身控制器S1 通用可复用、跨本体S1 训练贵；token 语义受限大多数场景
C 语言子任务（π0.5）S2 出子任务文本 → S1 VLA可解释、调试易带宽低、细节丢长程、多阶段
D 纯 RL 专家单任务 RL 控制器性能高、简单不通用、重训单一任务量产
E 云-端（Gemini Robotics）云端 S2 → 端侧 S1算力大、迭代快网络依赖联网/服务机器人

9. 延迟预算与常见坑

环节典型延迟预算建议
S2 推理100–400ms（云 300–800ms）≥2.5Hz；输出带时间戳
接口/规划5–12ms（Jetson Orin）< S1 周期
S1 推理1–20ms50Hz 留 50% 余量
S0 力矩环1ms独立看门狗
五个最常见的坑：① S2 出 token 太慢、S1 用旧 token（滞后/撞）；② 训练不含推理延迟（部署振荡）；③ 接口版本漂移（训练 3 点、部署 token）；④ PD 增益没调好（S1 再强也抖）；⑤ 安全层依赖上层（危险）。

10. ASTRA（GPT-6 Astra）：最新外部基线，不是机器人策略

它是什么：GPT-6 Astra 是通用大模型。2026 年 9–10 月有两篇系统评测把它接到机器人上（2609.38537 六域评测；2610.26846 视触觉），测「通用模型能否直接当策略」。

10.1 两种用法

模式Astra 做什么底层控制
Direct直接生成数值动作：末端/关节目标、夹爪、底盘指令、导航原语（前进步/转向/停止）IK / 关节或操作空间控制 / 离散导航原语
Hybrid审阅、修改或替换学习策略的提案；或给冻结全身控制器提供密集运动参考、速度指令、稀疏身体目标学习任务策略 / 冻结 WBC（如 ScaleTrack）

10.2 六域结果（原论文数字）

域结果解读
夹爪操作（RoboDojo 子集）与 π0.5 混合控制 48%能纠正目标、准备接触，但不替代策略
灵巧操作（DexJoCo 10 次）混合 50%；直接手内控制难协调手指接触接触密集仍是专用策略强项
移动操作（RoboCasa365）混合 38.7%底盘+手臂协调有增益但不稳
导航RxR 92%；HM3D 物体搜索 82%局部领先，但绕路多、搜索低效
运动（locomotion）单障碍赛道 5 次连续尝试 0 次到达密集运动参考不可靠

10.3 成本（最值得记住的数据）

  • 50 个 RoboDojo 实例/条件：策略辅助 6.248 亿 token；直接控制 11.32 亿 token。
  • 30 秒运动跑：250 次模型调用，平均每次 39.86 秒，推理期间物理暂停。
  • 导航接口：适配器把输出转成 0.25m 前进/30° 转向，预算 500 个原语，无路径规划。

10.4 视触觉版本（2610.26846）

把视触觉 RGB 当普通图像输入 Astra 的视觉接口：19 个 UniVTAC / OpenViTAC 任务、每设定 210 个种子，视觉+触觉 93.8% / 81.8%（比最强专用基线 +22.9 / +13.1 个百分点）；纯视觉 76.3% / 80.6%。

对搭建者的意义：ASTRA 证明「S2 用通用模型」可行，但延迟与成本决定它只能做慢决策；实时控制仍要靠 S1/S0。

11.2 网络（`all_mlp_v1.yaml` 逐项）

# 编码器：MLP [2048,1024,512,512] + SiLU，输入 10 帧未来，输出 2 个 token
enc_g1    : command_multi_future(10 帧) + motion_anchor_ori + command_z
enc_teleop: lower_body_future + vr_3point_pos + vr_3point_ori + anchor_ori + command_z
enc_smpl  : smpl_joints_future(10 帧) + smpl_root_ori + wrist_pos

# FSQ：num_fsq_levels=32，fsq_level_list=32 → 每 token 32 维、每维 32 级
# max_num_tokens=2 → 总 token = 2×32 = 64 维（正好对应 VLA 的 64 维接口）

# 解码器 g1_dyn：MLP [2048,2048,1024,1024,512,512] + SiLU
g1_dyn: inputs = token_flattened + proprioception → outputs = action（关节目标）

11.3 数据与规模

  • 自建动捕：700 小时、1 亿+帧@50Hz、170 人（145–199cm，均值 174.3）；GMR 重定向。
  • 公开：BONES-SEED 142K+ 动作（约 288 小时，含 G1 MuJoCo 轨迹）。
  • 模型 1.2M→16M→42M；算力 16/32/128 GPU ≈ 2k/9k/21k GPU 小时（128 卡 × 7 天，5 万迭代）。
  • 消融：42M 在 test-content 99.6% / MPJPE-L 23.8mm；1.2M 为 98.0% / 27.7mm。

11.4 部署与 VLA 接口

# 部署栈：C++ 推理 + TensorRT + ZMQ；机器人 G1
# 可加 latent residual（post/pre quantization）做下游修正

11.5 结果

test-content 98.5% / test-repetition 99.2% / PHUMA 97.2%；真机 124 条动作 99.2%（仿真 100%），MPJPE-L 25.7mm（仿真 22.3mm，脚部 53.7 vs 29.0mm）；对比 BeyondMimic 82.0/85.4/73.8%、Any2Track 61.6/69.4/78.5%；vs 专用 OpenHomie 存活率 98.5% vs 43.0%。

12.2 N1.5（官方页 L1）

  • VLM 换成 Eagle 2.5（2.1B）并在预训练+微调全程冻结；连接视觉→LLM 的 adapter 简化并加 LayerNorm。
  • 新增 FLARE：对齐目标未来嵌入（loss 0.2），不做生成式未来。
  • 训练：250K 步、1K×H100、全局 batch 16384、AdamW+cosine、warmup 0.05。
  • 结果：语言跟随 46.6→93.3%；真机总成功 43.3→83.0%；G1 1K demos 44.0→98.8%；RoboCasa 30 demos 17.4→47.5。

12.3 N1.7（官方文档 L1）

3B 版本（`nvidia/GR00T-N1.7-3B`），官方微调命令：20k steps、bs 32、4 GPU、LeRobot 数据；embodiment tag `UNITREE_G1_SONIC`；配合 SONIC 50Hz 执行。

12.4 GR00T 2（官方页 L1）

  • 范式：WAM——一个 DiT 联合去噪未来视频+动作；外部推理 agent 当 System 2。

14. PD 控制：S0 的实现与调参

14.1 代码（带物理意义）

# 1kHz 力矩环；q=位置 rad，qd=速度 rad/s
tau = Kp*(q_des - q) - Kd*qd + tau_ff
tau = clamp(tau, tau_min, tau_max)
# Kp 刚度：跟踪紧但易振荡（典型 20–200 Nm/rad，按关节）
# Kd 阻尼：抑制超调（典型 0.5–5 Nms/rad）
# tau_ff：重力/摩擦前馈，减小稳态误差
# 限幅：保护减速器；撞击时饱和+柔顺吸能

14.2 参数按物理算

  • 闭环带宽 f_n、关节惯量 J：Kp = J·(2πf_n)²，Kd = 2ζJ·(2πf_n)（ζ=1 临界阻尼）。
  • 例：J=0.1 kg·m²、f_n=2Hz → Kp≈15.8、Kd≈2.5；先半增益起调。
  • 流程：低 Kp → 加 Kd → 提到刚振荡 → 回退 30–50%；带负载/线缆复测；记录阶跃响应。
  • 重力补偿 tau_ff=G(q)（模型）或慢积分；摩擦补偿 Coulomb+粘滞。

14.3 安全（独立于上层）

if abs(tau) > tau_limit or abs(qd) > vel_limit or imu.tilt > tilt_limit:
    motor.disable()          # 硬件级切断

    enter_damping_mode()     # 上层失联→只留阻尼

术语小抄（给非具身读者）

术语一句话
PD 控制用「位置误差×刚度 − 速度×阻尼」算力矩：Kp 越大越硬，Kd 越大越稳
proprio（本体感知）机器人自己的关节角、速度、IMU 姿态——不用摄像头也知道自己在哪
token（潜动作）一串数字代表「未来一小段运动」，S1 能解码成关节动作；比关节角更抽象、跨本体
chunk（动作块）一次预测多步动作（如 16/32/40 步），减少推理次数
sim2real仿真训练的控制器搬到实机；靠域随机化+延迟标定缩小差距
阻抗控制让机器人末端表现成「弹簧+阻尼」，碰到东西会退让而不是硬顶
