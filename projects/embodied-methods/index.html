0. 方法地图：它们各自是什么角色

方法角色一句话证据级别
ASTRA（GPT-6 Astra）外部通用策略（S2/S2.5）用通用大模型直接生成数值动作或审阅策略提案，不是专门训练的机器人模型L3（两篇评测论文）
SONICS1 全身控制器用运动跟踪做预训练任务的 RL 策略，50Hz 输出关节目标，64 维潜动作 token 接 VLAL3（论文+官方文档）
GR00T N1/N1.5/N1.7S2（VLA）视觉语言动作模型：VLM 出语义 + DiT 出动作块；N1.5 冻结 VLM、N1.7 3BL3（N1 论文）/ L1（N1.5/N1.7 官方页）
GR00T 2S2（WAM）世界-动作模型：一个 DiT 联合去噪未来视频+动作；外部 agent 当 S2L1（官方页）
HelixS1+S2 一体（双系统 VLA）7B VLM（7–9Hz）+ 80M visuomotor（200Hz），单 latent 向量接口，端到端训练L1（厂商博客，信息很全）
PD 控制S0用刚度/阻尼把目标位置变成力矩，所有机器人最终都落到这一层工程常识 + 代码
读法：ASTRA 是「外部大脑」的极限测试；SONIC/GR00T/Helix 是「机器人自己怎么训」；PD 是「最后怎么动」。

1. ASTRA：GPT-6 Astra 当具身策略（最新外部基线）

它是什么：GPT-6 Astra 是通用大模型，本身不是机器人策略。两篇 2026 年 9–10 月的系统评测把它接到机器人上，测「通用模型能不能直接当策略」。

1.1 两种用法（论文 2609.38537 原文框架）

模式做什么底层控制
DirectAstra 直接生成数值动作（末端/关节目标、夹爪、底盘指令、导航原语）IK / 关节或操作空间控制 / 离散导航原语
HybridAstra 审阅/修改/替换学习策略的提案，或给冻结全身控制器提供密集运动参考、速度指令、稀疏身体目标学习任务策略 / 冻结 WBC（如 ScaleTrack）

1.2 关键结果（原论文数字）

域结果解读
夹爪操作（RoboDojo 子集）与 π0.5 混合控制 48% 成功Astra 能纠正目标、准备接触条件，但不替代策略
灵巧操作（DexJoCo 10 次）混合控制 50%；直接手内控制难协调手指接触接触密集任务仍是专用策略强项

1.3 成本（论文里最有价值的数据）

  • 50 个 RoboDojo 实例/条件：策略辅助消耗 6.248 亿 token；直接控制 11.32 亿 token。
  • 30 秒运动跑：250 次模型调用，平均每次 39.86 秒，推理期间物理暂停。
  • 结论：通用模型做 S2 可行，但延迟/成本离实时控制很远；适合「慢决策 + 快控制器」的分层。

1.4 触觉版本（论文 2610.26846，2026-10-19）

把视触觉（Tactile RGB）当普通图像输入 Astra 的视觉接口，在 19 个 UniVTAC / OpenViTAC 任务、每设定 210 个种子：视觉+触觉 93.8% / 81.8%（比最强专用基线 +22.9 / +13.1 个百分点）；纯视觉也有 76.3% / 80.6%。行为分析看到主动探测、谨慎抓取、接触对齐与恢复，但切向加载与纠错执行仍弱。

对上手者的意义：ASTRA 不是可直接部署的方案，而是告诉你「S2 用通用模型时，接口（Direct/Hybrid）和延迟决定成败」。

2. SONIC：人形全身控制器（S1）的实现

2.1 定位与总体

把「动作跟踪」当预训练任务：给定参考运动，输出关节目标，用 PD 跟踪。一个策略覆盖走、跑、跳、爬、拳击等；部署在 Unitree G1。

2.2 网络结构（官方文档）

# UniversalTokenModule（SONIC 的动作变换模块 ATM）
G1 obs    ──► G1 Encoder (MLP) ─┐
Teleop    ──► Teleop Encoder   ─┼──► FSQ 量化 ──► G1 Dynamic Decoder ──► 关节目标（部署只用这个）
SMPL      ──► SMPL Encoder    ─┘        │
                                        └──► G1 Kinematic Decoder ──► 重建未来帧（仅训练辅助损失）
  • 三个编码器：机器人关节位/速（F_r 帧）、人体 3D 关节（F_h 帧，SMPL）、混合（上体关键点+下体机器人动作，F_m 帧）——多帧输入让策略能「预判」。
  • FSQ 量化：每个 latent 维独立量化到离散级；论文默认配置记为 FSQ-32-32（精确 level 列表以仓库 config 为准）。
  • 双解码器：`g1_dyn` 出关节动作（部署唯一使用）；`g1_kin` 重建未来运动帧（训练辅助损失，起隐式重定向作用）。
  • latent residual：下游策略可在量化前/后注入修正（`post_quantization` / `pre_quantization` / `pre_quantization_replace`）。

3.2 N1 的实现细节（可抄）

  • VLM 用第 12 层（不是最后一层）：更快且下游成功率更高；图像 224×224 + pixel shuffle → 64 token/帧。
  • 动作头：DiT（交叉+自注意力交替），embodiment-specific MLP 编码 state/action；H=16；flow matching 损失，τ~Beta((s−τ)/s;1.5,1)，s=0.999；推理 Euler K=4 步。
  • 潜动作：VQ-VAE 学帧间潜动作（encoder 当 IDM），把无动作视频当作 "LAPA" embodiment。
  • 后训练：真机:神经轨迹 = 1:1；IDM 只在低数据场景训练。

4. Helix：双系统一体 VLA 的实现

项细节
数据约 500 小时高质量多机器人、多操作员遥操作数据（不到同类 VLA 数据集的 5%）；用自动标注 VLM做 hindsight 指令（"如果想让机器人做出视频里的动作，你会给什么指令？"）；训练物品全部排除出评测。
S27B 开源开放权重 VLM；输入单目图像 + 机器人状态（腕位姿+手指位置）+ 语言；输出单个连续 latent 向量；7–9Hz。
S180M 交叉注意力 encoder-decoder transformer；卷积多尺度视觉骨干（仿真预训练）；把 latent 投影进 token 空间与视觉特征拼接；200Hz；35-DoF 上半身（腕位姿、手指屈伸/外展、躯干/头朝向）+ 一个「任务完成百分比」动作（自预测终止）。
训练单阶段端到端，像素+文本 → 连续动作，标准回归损失；梯度经 latent 从 S1 回传 S2；训练时给 S1/S2 输入加时间偏移，校准到部署推理延迟差；无任务头、无 per-task 微调。
部署每台机器人双低功耗板载 GPU：S2 异步后台进程持续更新共享内存 latent；S1 独立实时进程跑 200Hz 环；训练-部署时间偏移一致。
结果单套权重（7B+80M）覆盖抓放/抽屉/冰箱/双机协作/数千新物体；两机器人同权重协作搬运未见过的杂货。
# Helix 推理（双 GPU 异步）
# GPU0：S2 后台
while True:
    z = s2(image, state, instruction)     # latent [d]
    shared_latent.write(z)                # 7–9Hz
# GPU1：S1 实时
while True:
    x = vision_s1(image) + project(shared_latent.read())
    a = s1(x)                             # 35-DoF + 完成度
    robot.set_targets(a); sleep(5ms)      # 200Hz
关键工程点：Helix 不需要动作 token 化；S2/S1 分离带来「各自最优频率」；时间偏移是训练-部署一致性的核心。

5. PD 控制：S0 的实现与调参

5.1 代码（带物理意义）

# 1kHz 力矩环（驱动器内）；q=位置 rad，qd=速度 rad/s
tau = Kp*(q_des - q) - Kd*qd + tau_ff
tau = clamp(tau, tau_min, tau_max)
# Kp 刚度：越大跟踪越紧、越易振荡（典型 20–200 Nm/rad，按关节）
# Kd 阻尼：抑制超调；太小欠阻尼抖动，太大迟滞（典型 0.5–5 Nms/rad）
# tau_ff：重力/摩擦前馈，减小稳态误差（可由模型 G(q) 或积分项给）
# 限幅：保护减速器；撞击时饱和+柔顺吸能

5.2 参数怎么定（按物理算）

  • 目标闭环带宽 f_n（如 2–5Hz）与关节惯量 J：Kp = J·(2πf_n)²，Kd = 2ζJ·(2πf_n)，ζ=1 临界阻尼。
  • 例：J=0.1 kg·m²、f_n=2Hz → Kp≈15.8、Kd≈2.5；先从一半增益起，逐步加。
  • 流程：低 Kp → 加 Kd → 提到刚出现振荡 → 回退 30–50%；带负载/带线缆复测；记录阶跃响应。
  • 重力补偿：tau_ff = G(q)（模型）或慢积分；摩擦补偿：Coulomb + 粘滞项。

5.3 安全（必须独立于上层）

if abs(tau) > tau_limit or abs(qd) > vel_limit or imu.tilt > tilt_limit:
    motor.disable()            # 硬件级切断
